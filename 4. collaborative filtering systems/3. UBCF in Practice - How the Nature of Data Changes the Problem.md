In the previous lesson, we introduced **User-Based Collaborative Filtering (UBCF)** and saw that its core idea is to identify users who are _similar_ to a target user and recommend items that those similar users have liked. We also examined **Item-Based Collaborative Filtering (IBCF)** and discussed the key differences between the two approaches from both technical and application perspectives. We will now focus more closely on _UBCF_ and examine one of the most important factors affecting how the algorithm operates: **the type of data available to us**.

As discussed in previous lessons, user–item interaction data can be broadly divided into two main categories: **explicit data** and **implicit data**. Each type provides different information about user preferences. Consequently, the problem that _UBCF_ attempts to solve, as well as the type of output it produces, changes substantially depending on the data type. In this lesson, we will see how this fundamental distinction leads to two fundamentally different problems within _UBCF_.

**The central idea of UBCF:** If Ali and Mary have exhibited similar preferences in the past—for example, they have liked the same movies or assigned similar ratings to them—then items that Ali is likely to enjoy in the future, but with which Mary has not yet interacted, are also likely to be attractive to Mary, and vice versa.

To implement this idea, we need data representing users' interactions with or preferences for items. This data determines whether the _UBCF_ problem is one of predicting an **exact rating** or predicting the **probability of interest or interaction**.

### Explicit Data

Explicit data directly and deliberately expresses a user's opinion or preference. The user **explicitly** communicates how they feel about an item.

**Examples:**

- Star ratings, such as assigning 1 to 5 stars to a movie or product
    
- Like/dislike ratings (👍 / 👎)
    
- Written reviews or comments containing explicit positive or negative sentiment
    
- Responses to surveys, such as "How satisfied were you with this product?"
    

**Key characteristic:** Explicit data contains a _value_ representing the intensity of the user's preference, ranging from strong dislike to strong liking. In this case, the user–item matrix is referred to as a **ratings matrix**.

### Implicit Data

Implicit data does not directly express the user's opinion. Instead, it is inferred from the user's behavior. Such behaviors provide signals of interest—or lack of interest—but not with the same explicitness or precision as explicit data.

**Examples:**

- Purchasing a product
    
- Watching a movie or listening to a song, particularly when the content is consumed to completion
    
- Clicking on a link or news article
    
- Visiting a product or item page
    
- Adding an item to a shopping cart or wish list
    
- The amount of time a user spends interacting with an item
    

**Key characteristic:** Implicit data is often **binary**—interaction occurred or did not occur—or may represent quantities such as the number of interactions or the duration of an interaction. It does not directly specify the precise intensity of preference. In this case, the user–item matrix is referred to as an **interaction matrix**. Such a matrix typically contains values such as 1/0 (interaction occurred/did not occur), interaction counts, or durations.

Given these distinctions, it is natural that different types of data lead to different problem formulations. This lesson examines these differences in detail.

### User-Based Collaborative Filtering with Explicit Data: The Rating Prediction Problem

When our data is explicit, the primary objective of _UBCF_ is to predict what **rating** a target user would assign to items with which they have not yet interacted.

Suppose we are working with a movie-streaming service in which users rate movies from 1 to 5 stars. Our user–item matrix contains these ratings, with empty cells representing movies that a user has not yet rated.

**Problem:** Suppose user "Amir" has not yet watched the movie _Forrest Gump_. _UBCF_ must predict what rating Amir would likely assign to the movie if he watched it—for example, perhaps **4.5 out of 5**.

Consider a restaurant-review platform where you have rated several restaurants. _UBCF_ identifies users who have rated those same restaurants with approximately similar scores. The system observes that these similar users have given high ratings to a new restaurant. The problem for _UBCF_ is therefore:

> Given how much people with preferences similar to yours liked this restaurant—that is, the ratings they assigned—what rating would you probably give it?

The ultimate goal is to recommend restaurants with the highest **predicted ratings**.

#### Challenges with Explicit Data

From a problem-formulation perspective, explicit data introduces several important challenges:

- **Data sparsity:** Users typically rate only a small number of items. Consequently, the ratings matrix is highly sparse, making it difficult to identify neighboring users with a sufficient number of commonly rated items.
    
- **Rating bias:** Some users are naturally strict raters, whereas others tend to give generous ratings. This makes normalization necessary in many cases, as reflected in approaches such as Pearson correlation.
    
- **Does not rating an item mean disliking it?** No. The fact that a user has not rated an item does not necessarily indicate a lack of interest. The user may not have seen the item or may simply have chosen not to provide a rating.
    

### User-Based Collaborative Filtering with Implicit Data: The Interaction Probability Prediction Problem

When our data is implicit—for example, purchases, clicks, or page views—we can no longer directly predict what _rating_ a user would assign to an item, because there may be no explicit rating system at all, or the actual objective may be different.

In this setting, the _UBCF_ problem shifts toward predicting the **probability** or **propensity** of a user to have a **positive interaction** with an item.

Suppose we are working with an online store and have access only to customers' purchase data. Our user–item matrix indicates which products each user has purchased, perhaps using a binary value such as 1 or using the number of purchases.

**Problem:** Suppose user "Fatemeh" has not yet purchased a Bluetooth headset. _UBCF_ must predict the probability that Fatemeh will purchase it. In other words, is the product sufficiently attractive to Fatemeh that she is likely to take the action of purchasing it?

As another example, suppose we operate a music-streaming service. Our data contains the songs that users have listened to. For simplicity, assume that each successful listening event represents a positive interaction. You have listened to several songs. _UBCF_ identifies users who have listened to songs similar to those you have listened to. The system then observes that these similar users have listened to new songs that you have not yet heard.

The problem for _UBCF_ is therefore:

> Given that people with preferences similar to yours have listened to these songs, how likely are you to listen to and enjoy them if you encounter them?

The ultimate goal is to recommend a list of songs with the highest **probability of successful listening**. We do not know how much you will "like" a song in terms of an explicit rating. Instead, we predict how likely you are to engage with it.

#### Challenges with Implicit Data

From a problem-formulation perspective, implicit data introduces several important challenges:

- **Ambiguity of non-interaction:** An empty cell in an implicit interaction matrix may indicate either lack of interest or lack of awareness. These **missing negatives** are a major challenge because we do not know which items the user actually dislikes.
    
- **Ambiguity of positive interactions:** A purchase or click does not necessarily indicate complete satisfaction. The user may have regretted the purchase or may simply have interacted with the item once. Implicit data does not directly reveal the intensity of preference.
    
- **Noise in the data:** Random or accidental user behaviors can enter implicit datasets and produce misleading signals.
    
- **Ranking rather than exact-value prediction:** We need algorithms and evaluation methods designed for ranking problems—for example, measuring the quality of the top-$N$ recommended items—rather than relying solely on rating-prediction metrics such as **RMSE** or **MAE**.
    

### Explicit vs. Implicit UBCF

|**Feature**|**UBCF with Explicit Data**|**UBCF with Implicit Data**|
|---|---|---|
|**Input data type**|Ratings, likes/dislikes, reviews; explicit preference values|Purchases, clicks, views, duration; implicit signals, typically 0/1 or counts|
|**Information conveyed**|Preference intensity: how much the user likes or dislikes an item|Occurrence of an interaction: whether an interaction occurred|
|**User–item matrix**|Ratings matrix, typically containing continuous or discrete values; empty cells indicate no rating|Interaction matrix, typically containing 0/1 values, counts, or durations; empty cells indicate no observed interaction|
|**Meaning of an empty cell**|The user has not rated the item; they may not have seen it or may have no expressed opinion|The user has not interacted with the item; this may indicate either lack of interest or lack of awareness|
|**Primary prediction objective**|Predict the user's numerical rating for items they have not yet rated|Predict interaction or interaction propensity for items with which the user has not yet interacted|
|**Algorithm output**|Predicted rating, such as 4.1 out of 5|Interaction score or ranking used to order candidate items|
|**Common similarity measures**|Pearson correlation, cosine similarity applied to ratings|Cosine similarity, Jaccard similarity applied to interaction presence or counts|
|**Common evaluation metrics**|RMSE, MAE for rating-prediction accuracy|Precision@K, Recall@K, NDCG for ranking and retrieval quality|
|**Primary challenge**|Explicit-data sparsity and rating bias|Ambiguous non-interaction and ambiguous interpretation of interaction signals|

When we have explicit data, the _UBCF_ problem resembles a **regression** or **classification** problem, depending on whether ratings are treated as continuous or discrete values. The objective is to accurately estimate the **magnitude of preference**.

When we have implicit data, the problem is more naturally formulated as a **ranking** or **propensity-prediction** problem. We cannot reliably determine how much a user will like an item. Instead, we estimate **how likely the user is to interact with it**, or determine which item the user is **more likely to prefer** relative to another item. The objective is therefore to produce an ordered list of items with the highest estimated likelihood of interest.

This change in problem definition affects every subsequent stage of the system, including how similarity is computed, which similarity measures are appropriate, how the prediction step is formulated, and—most importantly—how system performance is evaluated. The central question changes from _"Is the predicted rating close to the user's actual rating?"_ to _"Have the appropriate items been placed near the top of the recommendation list?"_

#### Real-World Systems and Problems

- **Netflix (combined data):** Netflix has access to both explicit signals, such as user ratings, and implicit signals, such as watch duration, repeated viewing, and adding content to a list. In this setting, _UBCF_ can operate both on similarity in explicit ratings—predicting ratings for unseen movies—and on similarity in implicit viewing patterns—predicting a user's propensity to watch particular movies. Combining these two signals can lead to stronger results. If Netflix had only explicit ratings, recommending content to new users or newly released movies that had not yet received ratings would be considerably more difficult. If it had only implicit data, it could not accurately determine _how much_ a user liked a movie; it would only know that the user _watched it_.
    
- **Spotify (primarily implicit data):** Spotify relies primarily on implicit signals, such as listening to songs, adding songs to playlists, skipping songs, and repeated listening. Explicit ratings are less common. _UBCF_ in Spotify therefore relies more heavily on similarity in listening patterns, with the objective of predicting the probability that a user will listen to a new song or add it to a playlist. The problem here is predicting **listening propensity**, rather than an exact rating.
    

In **User-Based Collaborative Filtering**, the type of data available is a fundamental determinant of the problem we are attempting to solve.

- With **explicit data**, such as ratings, the _UBCF_ problem becomes **exact rating prediction** for items the user has not yet rated. We attempt to estimate _how much_ the user will like an item.
    
- With **implicit data**, such as purchases or clicks, the _UBCF_ problem becomes **positive-interaction propensity prediction** or **item ranking** based on the user's behavioral preference. We attempt to estimate _how likely_ the user is to interact with an item in a manner that indicates interest.
    

Understanding this fundamental difference in problem formulation is essential not only for understanding how _UBCF_ algorithms work, but also for selecting appropriate evaluation metrics, interpreting results, and ultimately designing more effective recommender systems. Although pure _UBCF_ faces scalability challenges in very large systems, its core principle—finding neighbors based on behavioral similarity—continues to appear in various forms in more advanced collaborative-filtering techniques, such as **Matrix Factorization**, which we will examine in future lessons and which can handle both explicit and implicit data.
