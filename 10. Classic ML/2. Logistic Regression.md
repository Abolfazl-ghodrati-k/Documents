
In the previous section, we studied **Linear Regression** and learned how it can be used to predict continuous numerical values, such as the rating a user might assign to an item. In machine learning and statistics, problems involving the prediction of continuous numerical variables are called **regression problems**.

We now turn to another fundamental category of machine learning problems: **Classification**.

In classification, the objective is to determine which category, or *class*, an observation belongs to. Many classification algorithms also estimate the probability that an observation belongs to a particular class.

When the target variable has exactly two possible classes, the problem is called **Binary Classification**.

In recommender systems, many important prediction tasks can be formulated as binary classification problems. For example:

- Will a user click on a recommended item?
- Will a user purchase a particular product?
- Will a user watch a recommended video?

Each question has two possible outcomes, commonly represented by the labels $0$ and $1$.

For example, in click prediction:

- $y=1$ indicates that the user clicked on the item.
- $y=0$ indicates that the user did not click on the item.

**Logistic Regression** is one of the simplest and most widely used algorithms for binary classification.

Rather than directly predicting a class label, logistic regression estimates the probability that an observation belongs to the positive class.

This probability lies between 0 and 1 and can be used to rank candidate items according to their predicted likelihood of receiving a positive interaction.

For example, if a recommendation model estimates that a user has a 90% probability of clicking on one product and a 40% probability of clicking on another, the first product would generally receive a higher ranking when the objective is to maximize predicted click probability.

Although the algorithm contains the word *regression* in its name, logistic regression is primarily a classification algorithm. The terminology reflects its use of a regression-like linear predictor to model the logarithm of the odds of a positive outcome.

## The Logistic Regression Model

Logistic regression begins with a linear combination of the input features, similar to the model used in linear regression.

The linear component is defined as:

$$
z=\beta_{0}+\beta_{1}x_{1}+\beta_{2}x_{2}+\cdots+\beta_{p}x_{p}
$$

Using vector notation:

$$
z=\beta_{0}+\mathbf{x}\cdot\boldsymbol{\beta}
$$

Where:

- $\mathbf{x}$ is the input feature vector.
- $\boldsymbol{\beta}$ is the coefficient vector.
- $\beta_{0}$ is the intercept.
- $z$ is the linear predictor, also called the **logit** or **log-odds**.

The main difference between linear regression and logistic regression lies in how this linear predictor is transformed into the model's final output.

In linear regression, the linear combination itself represents the predicted numerical value:

$$
\hat{y}=z
$$

Because $z$ can take any real value, ordinary linear regression predictions are not inherently restricted to a particular interval.

In logistic regression, however, the objective is to predict a probability.

A valid probability must lie between 0 and 1.

Therefore, logistic regression applies a nonlinear function called the **Sigmoid Function**, also known as the **Logistic Function**, to transform the linear predictor into a probability.

### The Sigmoid Function

The sigmoid function is defined as:

$$
\sigma(z)=\frac{1}{1+e^{-z}}
$$

Where $e$ is Euler's number, the base of the natural logarithm.

The sigmoid function has an S-shaped curve and maps every real number to a value strictly between 0 and 1.

The behavior of the sigmoid function can be summarized as follows:

- When $z$ is a large positive number, $\sigma(z)$ approaches 1.
- When $z$ is a large negative number, $\sigma(z)$ approaches 0.
- When $z=0$, the sigmoid function returns exactly 0.5.

For example:

$$
\sigma(0)=\frac{1}{1+e^{0}}=\frac{1}{2}=0.5
$$

The sigmoid function never returns exactly 0 or 1 for finite input values.

This property makes it suitable for modeling probabilities.

### Predicting Class Probabilities

By combining the linear predictor with the sigmoid function, we obtain the logistic regression prediction equation:

$$
\hat{p}=P(y=1\mid\mathbf{x})=\sigma(\beta_{0}+\mathbf{x}\cdot\boldsymbol{\beta})
$$

Equivalently:

$$
\hat{p}=\frac{1}{1+e^{-(\beta_{0}+\mathbf{x}\cdot\boldsymbol{\beta})}}
$$

Where:

- $\hat{p}$ is the predicted probability of the positive class.
- $P(y=1\mid\mathbf{x})$ is the conditional probability that the target variable equals 1 given the input features.
- $\mathbf{x}$ is the feature vector.
- $\boldsymbol{\beta}$ is the learned coefficient vector.

In a recommendation application, this probability may represent the likelihood that a user will click on a particular item.

### Converting Probabilities into Class Predictions

Logistic regression produces probabilities, but classification tasks often require discrete class labels.

A **decision threshold** is used to convert the predicted probability into a class.

A common default threshold is 0.5.

The decision rule is:

$$
\hat{y}=\begin{cases}1 & \text{if }\hat{p}\ge0.5\\0 & \text{if }\hat{p}<0.5\end{cases}
$$

For example:

- If the predicted click probability is 0.85, the model predicts class 1.
- If the predicted click probability is 0.20, the model predicts class 0.

The threshold does not necessarily have to be 0.5.

In practical recommendation applications, it may be adjusted according to the relative costs of false positives and false negatives, the class distribution, and the business objective.

Furthermore, when the objective is to rank items rather than make binary decisions, the predicted probabilities can be used directly without applying a classification threshold.

## Logistic Regression in Recommender Systems

To use logistic regression in a recommender system, we formulate recommendation as the prediction of whether a particular interaction will occur between a user and an item.

Examples include:

- Predicting whether a user will click on a product.
- Predicting whether a user will purchase an item.
- Predicting whether a user will watch a video.

Each training observation corresponds to a user–item pair:

$$
(u,i)
$$

The target variable indicates whether the interaction occurred.

The logistic regression model estimates:

$$
\hat{p}_{u,i}=P(y=1\mid(u,i))
$$

Using engineered features, this becomes:

$$
\hat{p}_{u,i}=\sigma\left(\beta_{0}+\sum_{j=1}^{m}\beta_{j}x_{u,i,j}\right)
$$

Where:

- $u$ represents the user.
- $i$ represents the item.
- $y=1$ indicates that the target interaction occurred.
- $m$ is the number of input features.
- $x_{u,i,j}$ is the value of feature $j$ for the user–item pair.
- $\beta_{j}$ is the learned coefficient for feature $j$.
- $\sigma$ is the sigmoid function.

The resulting probability can be used as a recommendation score.

For example, a recommendation system may rank candidate products according to their predicted purchase probabilities and display those with the highest scores.

## Preparing Training Data for Logistic Regression

Training a binary classification model requires observations belonging to both classes:

- **Positive samples:** Observations labeled 1.
- **Negative samples:** Observations labeled 0.

In recommender systems, constructing these classes requires particular care.

### Positive and Negative Interactions

Recommendation datasets often contain only observed interactions, such as clicks, purchases, or ratings.

For an implicit-feedback task, observed positive interactions can be labeled 1.

However, the absence of an interaction does not necessarily indicate a negative preference.

For example, a user may not have clicked on a product because:

- The product was never displayed.
- The user did not notice it.
- The user had no opportunity to interact with it.
- The product was irrelevant to the user's interests.

These situations have different interpretations.

Consequently, an unobserved user–item pair should not automatically be treated as a confirmed negative interaction.

For explicit rating datasets, observed ratings also require an appropriate labeling strategy. A low rating may represent negative preference, while a high rating may represent positive preference. Merely observing a rating does not establish that the user liked the item.

### Negative Sampling

Because interaction matrices are generally highly sparse, the number of unobserved user–item pairs is usually much larger than the number of observed interactions.

A common approach is **Negative Sampling**, in which a subset of unobserved user–item pairs is selected and assigned negative labels for model training.

For example, the number of sampled negative observations may be between 1 and 10 times the number of positive observations.

The appropriate ratio depends on the dataset, training objective, and evaluation methodology.

Negative sampling introduces several important considerations.

**Sampling Strategy**

Negative samples may be selected uniformly at random or according to a more sophisticated sampling distribution.

**Class Balance**

The ratio of positive to negative samples influences the training distribution.

**False Negatives**

Some sampled non-interactions may correspond to items that users would actually find relevant.

**Probability Calibration**

When negative sampling changes the natural class distribution, predicted probabilities may not directly represent real-world interaction probabilities.

Therefore, the sampling strategy must be considered when interpreting or calibrating model outputs.

### Feature Engineering

As with linear regression, logistic regression depends heavily on the quality of its input features.

The same feature categories introduced previously can be used:

- Statistical features derived from interactions.
- User side features.
- Item side features.
- Contextual features.
- Engineered interaction features.

For example, a click prediction model may use the user's historical interaction frequency, the item's popularity, and the item's category.

These features form the input vector for each user–item pair.

## Training the Logistic Regression Model

The objective of training logistic regression is to estimate the coefficients:

$$
\beta_{0},\beta_{1},\ldots,\beta_{p}
$$

that make the observed class labels as probable as possible under the model.

This approach is based on **Maximum Likelihood Estimation (MLE)**.

### Maximum Likelihood Estimation

Suppose we have $N$ training observations.

Each observation has:

- A feature vector $\mathbf{x}_{n}$.
- A binary target label $y_{n}$.
- A predicted positive-class probability $\hat{p}_{n}$.

The target label satisfies:

$$
y_{n}\in\{0,1\}
$$

The predicted probability is:

$$
\hat{p}_{n}=\sigma(\beta_{0}+\mathbf{x}_{n}\cdot\boldsymbol{\beta})
$$

For a single observation, the probability assigned to its observed label can be written as:

$$
P(y_{n}\mid\mathbf{x}_{n})=\hat{p}_{n}^{y_{n}}(1-\hat{p}_{n})^{1-y_{n}}
$$

This expression handles both possible labels.

When $y_{n}=1$, it becomes:

$$
P(y_{n}=1\mid\mathbf{x}_{n})=\hat{p}_{n}
$$

When $y_{n}=0$, it becomes:

$$
P(y_{n}=0\mid\mathbf{x}_{n})=1-\hat{p}_{n}
$$

Assuming the training observations are conditionally independent under the model, the likelihood of the complete dataset is:

$$
L(\boldsymbol{\beta})=\prod_{n=1}^{N}\hat{p}_{n}^{y_{n}}(1-\hat{p}_{n})^{1-y_{n}}
$$

Maximum likelihood estimation seeks the coefficient values that maximize this likelihood.

### Binary Cross-Entropy and Log Loss

Instead of maximizing the likelihood directly, logistic regression commonly minimizes its negative logarithm.

This produces the **Binary Cross-Entropy Loss**, also called **Log Loss**.

The objective is:

$$
\min_{\beta_{0},\boldsymbol{\beta}}-\sum_{n=1}^{N}\left[y_{n}\log(\hat{p}_{n})+(1-y_{n})\log(1-\hat{p}_{n})\right]
$$

Where:

- $N$ is the number of training observations.
- $y_{n}$ is the actual binary label.
- $\hat{p}_{n}$ is the predicted probability of the positive class.

The loss penalizes predictions that assign low probability to the observed class.

### Understanding the Loss for Positive Samples

Suppose:

$$
y_{n}=1
$$

Substituting this value into the loss for a single observation gives:

$$
\ell_{n}=-\log(\hat{p}_{n})
$$

If the model predicts a probability close to 1, the loss is small.

If it predicts a probability close to 0, the loss becomes large.

Therefore, the model is penalized heavily when it confidently predicts that a positive interaction is unlikely.

### Understanding the Loss for Negative Samples

Now suppose:

$$
y_{n}=0
$$

The loss becomes:

$$
\ell_{n}=-\log(1-\hat{p}_{n})
$$

If the model predicts a probability close to 0, the loss is small.

If it predicts a probability close to 1, the loss becomes large.

Thus, the model is penalized when it confidently predicts a positive interaction for an observation labeled negative.

### Optimizing the Loss Function

Unlike ordinary least squares linear regression, logistic regression does not generally have a direct closed-form solution for its optimal coefficients.

The model is therefore trained using iterative numerical optimization methods.

Examples include:

- Gradient Descent.
- Stochastic Gradient Descent.
- Limited-memory BFGS.
- Newton-based optimization methods.
- Coordinate descent and related methods.

These algorithms iteratively adjust the coefficients to reduce the objective function.

Practical implementations often include regularization to reduce overfitting and improve generalization.

### 3. Splitting the Dataset

We divide the dataset into training and test subsets using `train_test_split`.

Because the target classes are imbalanced, we use the `stratify` argument.

**Stratified sampling** attempts to preserve the original class proportions in both subsets.

Without stratification, a small or imbalanced dataset may produce a training or test subset containing very few observations from one class.

In extreme cases, a subset may contain only one class.

For example, if all training observations belong to class 1, the model cannot learn to distinguish positive interactions from negative interactions.

Stratification reduces the likelihood of this problem.

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42, stratify=y)
```

### 4. Creating the Logistic Regression Model

We now create an instance of Scikit-learn's `LogisticRegression` class.

The `solver` argument determines which numerical optimization algorithm is used to estimate the model coefficients.

```python
from sklearn.linear_model import LogisticRegression

model = LogisticRegression(solver='liblinear', random_state=42)
```

Here, we select the `liblinear` solver, which is suitable for small datasets and binary classification problems.

The `random_state` argument helps make the results reproducible when randomness is involved in the optimization procedure.

### The `solver` Argument

Scikit-learn supports several optimization algorithms for logistic regression.

The choice of solver depends on factors such as:

- Dataset size.
- Number of features.
- Number of classes.
- Regularization method.
- Memory availability.
- Computational requirements.

Three important solver categories are described below.

#### `liblinear`

The `liblinear` solver is particularly suitable for relatively small datasets.

It supports binary logistic regression and can be used with L1 or L2 regularization.

For multiclass problems, it can be incorporated into a One-vs-Rest strategy rather than directly optimizing a multinomial objective.

#### `sag` and `saga`

The `sag` and `saga` solvers are designed for efficient optimization on large datasets.

They use stochastic optimization techniques and can converge quickly when the dataset contains many observations.

Feature scaling is particularly important for their convergence behavior.

The `saga` solver also supports regularization configurations such as L1 and Elastic-Net.

#### `newton-cholesky`

The `newton-cholesky` solver is useful in certain settings where the number of observations is substantially larger than the number of model parameters.

A typical favorable condition is:

$$
N\gg p\cdot C
$$

Where:

- $N$ is the number of training observations.
- $p$ is the number of features.
- $C$ is the number of classes.

This solver can be useful for some datasets containing one-hot encoded categorical features.

However, it explicitly works with second-order information and can require substantial memory because the Hessian matrix grows quadratically with the number of parameters.

Therefore, it may become impractical when the number of encoded features is very large.

## 9. Evaluating the Logistic Regression Model

For binary classification, commonly used evaluation metrics include:

- Accuracy.
- Precision.
- Recall.
- F1-Score.
- Area Under the ROC Curve (ROC-AUC).

Scikit-learn provides implementations of these metrics in the `metrics` module.

### Accuracy

**Accuracy** measures the proportion of correctly classified observations.

$$
Accuracy=\frac{TP+TN}{TP+TN+FP+FN}
$$

Where:

- $TP$ is the number of true positives.
- $TN$ is the number of true negatives.
- $FP$ is the number of false positives.
- $FN$ is the number of false negatives.

Accuracy is intuitive, but it can be misleading when the class distribution is highly imbalanced.

### Precision

**Precision** measures the proportion of predicted positive observations that are actually positive.

$$
Precision=\frac{TP}{TP+FP}
$$

In recommendation applications, precision helps measure how frequently predicted positive interactions correspond to observed positive outcomes.

### Recall

**Recall** measures the proportion of actual positive observations that the model successfully identifies.

$$
Recall=\frac{TP}{TP+FN}
$$

High recall indicates that the model detects a large proportion of the positive interactions in the evaluation dataset.

### F1-Score

**F1-Score** combines precision and recall using their harmonic mean.

$$
F1=\frac{2\cdot Precision\cdot Recall}{Precision+Recall}
$$

This metric is useful when both false positives and false negatives are important.

A high F1-Score generally requires both precision and recall to be reasonably high.

### ROC-AUC

**ROC-AUC** measures how effectively a classifier distinguishes positive observations from negative observations across different classification thresholds.

The ROC curve plots:

- True Positive Rate.
- False Positive Rate.

The false positive rate is:

$$
FPR=\frac{FP}{FP+TN}
$$

The true positive rate is equivalent to recall:

$$
TPR=\frac{TP}{TP+FN}
$$

The Area Under the ROC Curve summarizes the model's ability to rank positive observations above negative observations.

An AUC of 0.5 corresponds to chance-level discrimination under standard assumptions.

An AUC of 1 indicates perfect ranking of positive observations above negative observations.

Unlike accuracy, precision, recall, and F1-Score calculated from predicted classes, ROC-AUC is generally calculated using continuous prediction scores or probabilities.

### Calculating the Evaluation Metrics

We can calculate all five metrics using Scikit-learn.

```python
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score, roc_auc_score

accuracy = accuracy_score(y_test, predicted_classes)
precision = precision_score(y_test, predicted_classes, pos_label=1)
recall = recall_score(y_test, predicted_classes, pos_label=1)
f1 = f1_score(y_test, predicted_classes, pos_label=1)
auc = roc_auc_score(y_test, predicted_probabilities[:, 1])


print(f"\nEvaluation on Test Set:")
print(f"Accuracy: {accuracy:.4f}")
print(f"Precision: {precision:.4f}")
print(f"Recall: {recall:.4f}")
print(f"F1-score: {f1:.4f}")
print(f"AUC: {auc:.4f}")
```

## Advantages and Disadvantages of Logistic Regression

Like linear regression, logistic regression is a relatively simple model with several useful characteristics.

### Advantages

**1. Simplicity and Computational Efficiency**

Logistic regression is comparatively straightforward to implement and train.

For many structured datasets, it provides an efficient baseline for binary classification.

Its relatively small number of parameters can also make inference computationally inexpensive.

**2. Relatively Fast Convergence**

With an appropriate optimization algorithm and suitable feature scaling, logistic regression can converge efficiently.

This makes it useful for experimentation and baseline development.

**3. Probabilistic Predictions**

One of its most important advantages is the ability to produce positive-class probabilities.

These probabilities can be used to rank candidate items according to their predicted likelihood of interaction.

For example, an e-commerce recommender may rank products according to predicted purchase probability.

**4. Support for Diverse Features**

Logistic regression can incorporate numerical representations of:

- User attributes.
- Item characteristics.
- Historical interaction statistics.
- Contextual variables.
- Engineered interaction features.

This flexibility makes it suitable for feature-based recommendation tasks.

**5. Mitigating Cold-Start Limitations**

When useful user or item side information is available, logistic regression can generate predictions even when interaction histories are limited.

For example, a new product may have no historical purchases but still contain useful attributes such as category, price, and textual metadata.

These features can support an initial prediction.

However, successful cold-start prediction depends on whether the available features contain sufficient information to generalize to new users or items.

**6. Interpretability**

The learned coefficients provide information about how features affect the log-odds of a positive interaction.

This makes logistic regression more interpretable than many complex nonlinear models.

Nevertheless, interpreting coefficients requires attention to feature scaling, correlations, and the distinction between association and causation.

### Disadvantages

**1. Limited Ability to Model Nonlinear Relationships**

Basic logistic regression uses a linear combination of input features.

Although the sigmoid function transforms this linear predictor nonlinearly into a probability, the model still assumes that the log-odds are linear in the supplied features.

Therefore, it may struggle to represent complex relationships between users and items.

For example, a user's preference for a movie genre may depend on interactions among several demographic, behavioral, and contextual characteristics.

Such relationships may require explicit interaction features or more flexible models.

**2. Strong Dependence on Feature Engineering**

The quality of the model depends heavily on the information contained in the input features.

If the selected features fail to capture important preference patterns, the model may produce inaccurate predictions.

Consequently, feature selection, encoding, transformation, and preprocessing are essential parts of developing logistic regression-based recommender systems.

**3. Sensitivity to Data Representation**

Features with substantially different numerical scales can affect optimization and regularization.

Categorical variables also require suitable encoding.

High-cardinality categorical attributes may produce very large feature matrices when one-hot encoding is used.

Sparse matrix representations and appropriate regularization can help address these challenges, but careful preprocessing remains necessary.

**4. Limitations of Negative Sampling**

In implicit-feedback recommendation, negative samples are often constructed from unobserved interactions.

Because unobserved interactions are not necessarily true negatives, the training labels may contain uncertainty.

The sampling strategy can also affect predicted probabilities and evaluation results.

These limitations must be considered when deploying logistic regression for click or purchase prediction.

## Logistic Regression at a Glance

Logistic regression is a fundamental baseline for binary classification tasks in recommender systems, particularly when the objective is to predict whether a user will click on, purchase, or otherwise interact with an item.

It combines a linear predictor with the sigmoid function to estimate the probability of a positive interaction.

The model is typically trained using maximum likelihood estimation, which corresponds to minimizing binary cross-entropy loss, potentially with regularization.

Its principal strengths are computational simplicity, interpretability, support for diverse features, and probabilistic outputs suitable for recommendation ranking.

Its main limitation is that the log-odds of the positive class are modeled as a linear function of the supplied features.

In addition, preparing suitable training data, especially through careful negative sampling, is an important practical challenge.

These characteristics make logistic regression a useful foundation for understanding more advanced classification and ranking models that can capture nonlinear patterns in recommendation data.

## Important Parameters of Scikit-learn's `LogisticRegression`

The `LogisticRegression` class provides several parameters that control the model's regularization, optimization, and training behavior.

The following table summarizes the most important parameters.

| Parameter | Description | Default Value | Practical Considerations |
|---|---|---|---|
| `penalty` | Specifies the regularization method applied to the model. | `'l2'` | Common choices include L2, L1, Elastic-Net, and no regularization. L2 shrinks coefficients, L1 can produce sparse coefficients, and Elastic-Net combines both approaches. Solver compatibility must be considered. |
| `C` | Controls the inverse strength of regularization. | `1.0` | Smaller values produce stronger regularization, potentially increasing underfitting. Larger values weaken regularization and may increase overfitting. Must be positive. |
| `fit_intercept` | Determines whether the model learns an intercept term. | `True` | When enabled, the model estimates $\beta_{0}$. When disabled, the intercept is fixed at zero, so the linear decision boundary passes through the origin in feature space. |
| `solver` | Selects the numerical optimization algorithm. | `'lbfgs'` | Available choices include `liblinear`, `lbfgs`, `newton-cg`, `newton-cholesky`, `sag`, and `saga`. The appropriate choice depends on dataset size, regularization, and computational resources. |
| `max_iter` | Specifies the maximum number of optimization iterations. | `100` | If the solver fails to converge within this limit, Scikit-learn may issue a convergence warning. Increasing the value or improving feature scaling may help. |
| `multi_class` | Controls how multiclass classification is handled in older Scikit-learn versions. | `'auto'` in older versions | Historically supported `auto`, `ovr`, and `multinomial`. This parameter has been deprecated and removed from newer versions; multinomial optimization is used for supported multiclass solvers, while explicit One-vs-Rest classification can be implemented separately. |
| `l1_ratio` | Controls the mixture of L1 and L2 regularization in Elastic-Net. | `None` in older versions | A value of 0 corresponds to L2, while 1 corresponds to L1. Intermediate values combine both penalties. Its availability and interaction with `penalty` depend on the Scikit-learn version. |
| `random_state` | Controls randomness in supported optimization procedures. | `None` | Setting a fixed integer helps reproducibility when the selected solver uses randomness. |
| `n_jobs` | Controls parallel execution in versions and configurations that support it. | `None` in older versions | Its effect depends on the solver and Scikit-learn version. It is not a general mechanism for accelerating every logistic regression fit and has been deprecated in newer releases. |

### Regularization and the `C` Parameter

Regularization is especially important when a recommendation model contains many features.

For example, one-hot encoding user IDs, item IDs, or high-cardinality categorical variables can produce a large number of coefficients.

Without sufficient regularization, the model may fit training observations closely but generalize poorly to unseen data.

The `C` parameter controls the strength of regularization inversely.

A smaller value of `C` imposes stronger regularization, encouraging smaller coefficients.

A larger value allows the model to fit the training data more freely.

Therefore, selecting `C` involves balancing underfitting and overfitting.

### Selecting a Suitable Solver

The choice of solver should reflect the characteristics of the dataset.

For example:

- `liblinear` is often suitable for small binary classification datasets.
- `lbfgs` is a general-purpose choice for many classification problems.
- `sag` and `saga` can be efficient for large datasets when features are appropriately scaled.
- `saga` supports L1 and Elastic-Net regularization.
- `newton-cholesky` can be effective when the number of observations is much larger than the number of model parameters, provided sufficient memory is available.

For practical recommendation applications, solver selection should be based on convergence behavior, training time, memory requirements, and compatibility with the chosen regularization method.
