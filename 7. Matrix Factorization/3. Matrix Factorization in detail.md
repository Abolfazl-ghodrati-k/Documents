In previous sections, we studied two major approaches to **collaborative filtering**: **user-based collaborative filtering**, which identifies similar users and recommends items preferred by those users, and **item-based collaborative filtering**, which identifies similar items and recommends items similar to those a user has already liked or interacted with.

These methods operate primarily by computing similarities directly between the rows or columns of the user–item interaction matrix.

However, in practice, particularly when working with large and sparse datasets, these approaches encounter important challenges such as **scalability** and **sparsity**, both of which were discussed in detail in previous sections.

## Matrix Factorization

**Matrix factorization** was developed as a powerful approach for addressing many of the limitations associated with traditional collaborative-filtering methods. Its central idea is to discover the **latent structure** underlying user–item interaction data.

Instead of working directly with the large and sparse user–item interaction matrix, denoted by $R$, matrix factorization attempts to approximate it as the product of two smaller matrices:

$$  
R \approx P Q  
$$

If $n$ denotes the number of users, $m$ denotes the number of items, and $k$ denotes the number of latent features, then the matrices have the following meanings:

- **Matrix $R$:** The original **user–item interaction matrix** with dimensions $(n,m)$. This matrix is typically very large and sparse.
    
- **Matrix $P$:** The **user–latent-feature matrix** with dimensions $(n,k)$. Each row is a vector representing the profile or preferences of one user in the latent-feature space.
    
- **Matrix $Q$:** The **latent-feature–item matrix** with dimensions $(k,m)$. Each column is a vector representing the characteristics of one item in the same latent-feature space.
    

The number of latent features, $k$, is a model parameter selected during model design and is generally much smaller than both the number of users and the number of items:

$$  
k \ll n  
$$

and

$$  
k \ll m  
$$

This dimensionality reduction is one of the primary reasons matrix-factorization methods can be considerably more scalable and computationally efficient than approaches that operate directly on the full interaction matrix.

> **Latent Features**
> 
> In matrix-factorization models for recommender systems, **latent features** are abstract characteristics or dimensions that are not directly observable in the raw user–item interaction data. Instead, they are **learned automatically** by the algorithm from patterns in the observed interactions.
> 
> These features can be interpreted as underlying concepts or factors that simultaneously describe user preferences and item characteristics. For example, a latent feature might approximately represent a user's **preference for science-fiction movies** or, in a food recommendation system, the **degree of spiciness of a dish**, even though such concepts were never explicitly supplied to the model as labeled attributes.
> 
> Each user is represented by a vector in the latent-feature space. The values in this vector indicate the degree to which the user's preferences align with the learned latent factors. Similarly, each item is represented by a vector in the same latent space, describing the extent to which that item is associated with each latent factor.
> 
> The predicted preference of a user for an item is commonly obtained by combining these two vectors, typically using their **dot product**. The resulting value reflects how closely the user's latent preference profile matches the item's latent characteristics.

## Predicting Ratings Using Latent Features

Once the matrices $P$ and $Q$ have been learned, the predicted rating of user $u$ for item $i$ can be computed directly.

The prediction is the **dot product** of the latent-feature vector for user $u$, corresponding to row $u$ of $P$, and the latent-feature vector for item $i$, corresponding to column $i$ of $Q$:

$$  
\hat{R}_{u,i} = P[u,:] \cdot Q[:,i]  
$$

Equivalently,

$$  
\hat{R}_{u,i} = \sum_{f=1}^{k} P_{u,f} Q_{f,i}  
$$

where $f$ indexes the latent features.

This dot product is exactly the element located at row $u$ and column $i$ of the matrix product $PQ$.

Therefore, computing

$$  
\hat{R} = P Q  
$$

produces a new matrix with dimensions $(n,m)$ containing the **predicted ratings for every user–item pair**, including pairs for which no interaction was previously observed.

Consider the following example. Suppose that a hypothetical user–item interaction matrix has already been factorized into a user–latent-feature matrix and a latent-feature–item matrix. Multiplying these two matrices reconstructs an approximation of the original interaction matrix and therefore produces predicted preferences for the users.

```
import numpy as np

P = np.array([
    [0.8, -0.2], # User 0 features
    [0.1, 0.9],  # User 1 features
    [0.5, 0.5]   # User 2 features
])


Q = np.array([
    [0.7, 0.3, 0.9, 0.1], 
    [-0.1, 0.6, 0.2, 0.8]
])

predicted_ratings_matrix = P @ Q 
print("\nPredicted Ratings Matrix (P @ Q, 3x4):\n", predicted_ratings_matrix)
```

Output:

```
Predicted Ratings Matrix (P @ Q, 3x4):
[[ 0.58  0.12  0.68 -0.08]
 [-0.02  0.57  0.27  0.73]
 [ 0.3   0.45  0.55  0.45]]
```

Here,

$$  
P =  
\begin{bmatrix}  
0.8 & -0.2 \  
0.1 & 0.9 \  
0.5 & 0.5  
\end{bmatrix}  
$$

has dimensions $3 \times 2$, meaning that there are three users and two latent features.

Similarly,

$$  
Q =  
\begin{bmatrix}  
0.7 & 0.3 & 0.9 & 0.1 \  
-0.1 & 0.6 & 0.2 & 0.8  
\end{bmatrix}  
$$

has dimensions $2 \times 4$, meaning that there are four items represented using the same two latent features.

Their product therefore has dimensions:

$$  
(3 \times 2)(2 \times 4) = 3 \times 4  
$$

and represents predicted values for all three users and all four items.

In matrix $Q$, column $j$ stores the latent-feature vector of item $j$. Therefore, to predict the rating that user $i$ would assign to item $j$, we compute the dot product between row $i$ of $P$ and column $j$ of $Q$.

Suppose we want to predict the rating that user `1` would assign to item `2`. Instead of computing the entire user–item prediction matrix, we can compute only the required entry:

```
predicted_rating_user0_item0 = np.dot(P[1, :], Q[:, 2])
print("\nPredicted rating for User 0 and Item 0 (dot product):", predicted_rating_user0_item0)
```

Output:

```
Predicted rating for User 0 and Item 0 (dot product): 0.27
```

The numerical calculation is:

$$  
P[1,:] =  
\begin{bmatrix}  
0.1 & 0.9  
\end{bmatrix}  
$$

and

$$  
Q[:,2] =  
\begin{bmatrix}  
0.9 \  
0.2  
\end{bmatrix}  
$$

Therefore,

$$  
\hat{R}_{1,2} = (0.1)(0.9) + (0.9)(0.2) = 0.09 + 0.18 = 0.27  
$$

The same value appears at row `1`, column `2` of the complete predicted-rating matrix.

Thus, multiplying $P$ and $Q$ produces a complete matrix of predicted ratings. Unlike the original interaction matrix, which is usually sparse, this reconstructed prediction matrix is generally **dense**, because the model can estimate a value even for user–item pairs for which no interaction was originally observed.

These predictions can then be used to recommend the items with the highest predicted scores to each user.

## Sparse Matrices and Linear Algebra

The original matrix $R$ that we wish to factorize is typically sparse.

Matrix-factorization algorithms used in recommender systems are therefore generally designed so that model learning is based only on the **observed interactions**, corresponding to the relevant stored entries of $R$, rather than treating every missing entry as an explicitly observed rating of zero.

If $\Omega$ denotes the set of observed user–item interactions, then:

$$  
\Omega = {(u,i) \mid R_{u,i} \text{ is observed}}  
$$

The factorization algorithm learns $P$ and $Q$ primarily from the entries indexed by $\Omega$.

This is precisely where the sparse-matrix structures provided by `scipy.sparse`, introduced in the previous section, become important. Rather than storing and repeatedly processing every element of a potentially enormous dense interaction matrix, sparse representations allow the algorithm to work efficiently with the interactions that are actually available.

The primary computations involved in matrix-factorization methods include operations such as:

- computing dot products between user and item latent vectors;
    
- computing prediction errors for observed interactions;
    
- updating the latent-factor matrices;
    
- performing matrix–vector or matrix–matrix operations where appropriate.
    

These operations can be implemented efficiently using optimized functionality provided by NumPy and `scipy.sparse`.
