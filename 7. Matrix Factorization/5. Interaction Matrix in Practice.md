
In the previous section, we became familiar with interaction matrices and formally defined them. We learned that, for matrix-factorization algorithms, the primary input is the **user–item interaction matrix $R$**, which typically contains only information such as `user_id`, `item_id`, and `rating`, or another type of interaction, and is usually represented as a **sparse matrix**.

In this section, we will examine the complete process of constructing an interaction matrix from raw data. For this purpose, we use the _MovieLens 100K_ dataset, which was introduced and used previously in the section _Preprocessing in Practice_.

## Getting Started

In _Preprocessing in Practice_, we observed that this dataset is already clean and does not require additional data-cleaning operations.

Nevertheless, when constructing an interaction matrix in a real-world workflow, it is important to remember that the data must first be cleaned and validated before the interaction matrix is created. Therefore, **data cleaning is the first step** in constructing an interaction matrix.

In this section, we assume that the required preprocessing and cleaning steps have already been completed and continue from that point.

### Loading the Dataset

We begin by loading the cleaned dataset. This can be done directly using Pandas.

```python
import pandas as pdimport numpy as np
ratings_df = pd.read_csv('ml100k.csv')
```

### Selecting the Interaction Columns

For constructing the interaction matrix, we only require the `user_id`, `item_id`, and `rating` columns.

```python
interaction_data = ratings_df[['user_id', 'item_id', 'rating']]
```

### Mapping Original Identifiers to 0-Based Indices

This is a critical step.

The `user_id` and `item_id` values in the original DataFrame may be **large**, **noncontiguous**, or even represented as **strings**. Libraries such as `scipy.sparse`, as well as many matrix-factorization implementations, require matrix row and column positions to be represented by consecutive numerical indices starting from `0`.

We therefore map the original user and item identifiers to consecutive 0-based indices:

```python
mapped_user_ids_full, unique_user_ids = pd.factorize(interaction_data['user_id'])
mapped_item_ids_full, unique_item_ids = pd.factorize(interaction_data['item_id'])

print("Original unique user_ids count:", len(unique_user_ids))
print("Original unique item_ids count:", len(unique_item_ids))
```

Output:

```
Original unique user_ids count: 943
Original unique item_ids count: 1682
```

### Important Note

The identifier mapping must be created using **all unique users and items in the complete dataset before splitting the data into training and test sets**.

This ensures that the training and test interaction matrices have identical dimensions and use exactly the same row and column indexing scheme.

For example, suppose a particular item appears only in the test set. If identifier mapping were performed independently after the train–test split, that item might receive an index that does not exist in the training matrix, or the meaning of a particular column index could differ between the two matrices.

By defining the mapping once over the complete dataset, every original user and item identifier receives a single, stable matrix index that is used consistently in both the training and test sets.

### Determining the Matrix Dimensions

Let $n$ denote the number of unique users and $m$ denote the number of unique items. The final interaction matrix therefore has dimensions:

\(n \times m\)

We can determine these dimensions directly from the arrays of unique identifiers:

```python
num_users = len(unique_user_ids)
num_items = len(unique_item_ids)
matrix_shape = (num_users, num_items)

print(f"\nDetermined matrix shape (num_unique_users, num_unique_items): {matrix_shape}")
```

Output:

```
Determined matrix shape (num_unique_users, num_unique_items): (943, 1682)
```

Thus, the complete interaction matrix has:

$$(943 \times 1682)$$

entries.

The total number of possible user–item pairs is therefore:

$$(943 \times 1682 = 1{,}586{,}126)$$

Only a relatively small fraction of these possible pairs correspond to observed ratings, which is why a sparse representation is appropriate.

### Splitting the Data into Training and Test Sets

To evaluate the performance of recommendation models, we need separate training and test data.

The split should be performed on the interaction records before constructing the final training and test interaction matrices. Each observed interaction is assigned either to the training set or to the test set, while the previously created user and item mappings remain unchanged.

```python
from sklearn.model_selection import train_test_split

test_set_size = 0.2
random_state = 42 

train_user_ids, test_user_ids, \
train_item_ids, test_item_ids, \
train_ratings, test_ratings = train_test_split(
    mapped_user_ids_full,
    mapped_item_ids_full,
    interaction_data['rating'].values,
    test_size=test_set_size,
    random_state=random_state
)

print(f"\nNumber of interactions in training set: {len(train_user_ids)}")
print(f"Number of interactions in test set: {len(test_user_ids)}")
```

Output:

```
Number of interactions in training set: 80000
Number of interactions in test set: 20000
```

The original MovieLens 100K dataset contains $100{,}000$ observed ratings. With a test-set size of 20%, the interaction records are divided into:

$$(80{,}000)$$

training interactions and

$$(20{,}000)$$

test interactions.

It is important to distinguish between the **number of interactions** and the **dimensions of the interaction matrix**.

Both the training and test matrices will have the same shape:

$$(943 \times 1682)$$

However, only $80{,}000$ positions in the training matrix and $20{,}000$ positions in the test matrix correspond to observed ratings.

### Constructing Sparse Matrices in COO Format

Using the mapped user identifiers, mapped item identifiers, and corresponding rating values, we can construct separate sparse matrices for the training and test sets using `coo_matrix`.

```python
from scipy.sparse import coo_matrix

train_matrix_coo = coo_matrix((train_ratings, (train_user_ids, train_item_ids)),
                              shape=matrix_shape)

test_matrix_coo = coo_matrix((test_ratings, (test_user_ids, test_item_ids)),
                             shape=matrix_shape)

print("\nTrain Interaction Matrix (COO format):")
print(train_matrix_coo)
```

### Converting to CSR Format for Computation

Although COO format is convenient for constructing sparse matrices from lists of coordinates and values, **CSR (Compressed Sparse Row)** format is generally more suitable for repeated row access and many linear-algebra operations used in matrix-factorization workflows.

We therefore convert both COO matrices to CSR format:

```python
from scipy.sparse import csr_matrix

train_matrix_csr = train_matrix_coo.tocsr()
test_matrix_csr = test_matrix_coo.tocsr()


print("\nTrain Interaction Matrix (CSR format) - Ready for training:")
print(train_matrix_csr)
```
