
In the previous section, we introduced the concept of **sparse matrices** and observed that user–item interaction matrices in recommender systems are typically highly sparse because of the nature of interaction data. We also saw that storing and processing such large matrices in dense form using ordinary NumPy arrays is highly inefficient in terms of both memory consumption and computational performance.

To address this problem, we need tools specifically designed for sparse matrices. The `scipy.sparse` module in Python's scientific computing ecosystem provides a standard and powerful solution for this purpose. It offers efficient representations that store only nonzero elements, together with optimized methods for performing linear algebra operations on sparse matrices.

## Sparse Matrix Formats in `scipy.sparse`

The `scipy.sparse` module provides several formats for storing sparse matrices. Each format organizes and stores nonzero elements differently and is optimized for particular classes of operations.

The formats most commonly encountered in recommender-system applications include:

|Format|Description|Best Use Case|Notes / Limitations|
|---|---|---|---|
|**COO (Coordinate)**|Stores each nonzero element as a triplet `(row, column, value)`.|Initial matrix construction from raw records such as `user_id`, `item_id`, and `rating`.|Not particularly efficient for repeated computational operations such as matrix multiplication and is usually converted to another format afterward.|
|**CSR (Compressed Sparse Row)**|Stores data in compressed form by row.|Row-oriented operations, efficient access to user interactions, matrix–vector multiplication, and matrix multiplication.|Structural modifications can be relatively expensive, and column-oriented operations are less efficient than in CSC format.|
|**CSC (Compressed Sparse Column)**|Stores data in compressed form by column.|Column-oriented operations, multiplication involving a transposed matrix, and matrix multiplication.|Accessing individual rows may be slower than in CSR format.|

Other sparse formats, including `BSR`, `LIL`, and `DIA`, are also available. However, **COO**, **CSR**, and **CSC** are sufficient for getting started and for many common recommender-system applications.

# Constructing Sparse Matrices

In practice, user–item interaction data is often stored in a Pandas `DataFrame` with columns such as `user_id`, `item_id`, and `rating`, or analogous interaction-related fields.

The user and item identifiers in such datasets are often large, noncontiguous, nonzero integers. They may even be strings.

However, when constructing sparse matrices, the row and column positions must be represented using numerical, zero-based indices. Therefore, an essential preprocessing step is to **map the original identifiers to consecutive integer indices**, starting from `0` and ending at the number of unique identifiers minus one.

Consider the following example:

```python
import numpy as np
import pandas as pd

data = {
    'user_id': [101, 101, 255, 255, 300, 300, 300, 101, 255],
    'item_id': [1001, 1002, 1001, 1003, 1002, 1003, 1004, 1005, 1005],
    'rating': [5, 4, 4, 5, 3, 4, 5, 3, 4]
}

ratings_df = pd.DataFrame(data)

mapped_user_ids, unique_user_ids = pd.factorize(ratings_df['user_id'])
mapped_item_ids, unique_item_ids = pd.factorize(ratings_df['item_id'])

print("\nMapped user_ids (0-based indices):", mapped_user_ids)
print("Original unique user_ids:", unique_user_ids.tolist())

print("\nMapped item_ids (0-based indices):", mapped_item_ids)
print("Original unique item_ids:", unique_item_ids.tolist())
```

Output:

```
Mapped user_ids (0-based indices): [0 0 1 1 2 2 2 0 1]
Original unique user_ids: [101, 255, 300]

Mapped item_ids (0-based indices): [0 1 0 2 1 2 3 4 4]
Original unique item_ids: [1001, 1002, 1003, 1004, 1005]
```

## What Does Zero-Based Indexing Mean?

As shown above, `pd.factorize()` maps the original identifiers

```
[101, 255, 300]
```

to the zero-based indices

```
[0, 1, 2]
```

Similarly, the original item identifiers

```
[1001, 1002, 1003, 1004, 1005]
```

are mapped to

```
[0, 1, 2, 3, 4]
```

The resulting interaction matrix therefore uses:

- rows `0`, `1`, and `2` for the three users;
- columns `0` through `4` for the five items.

Conceptually, the mapping is:

|Original User ID|Matrix Row|
|---|---|
|101|0|
|255|1|
|300|2|

and:

|Original Item ID|Matrix Column|
|---|---|
|1001|0|
|1002|1|
|1003|2|
|1004|3|
|1005|4|

This mapping is important because matrix dimensions should depend on the **number of unique users and items**, not on the numerical magnitude of their identifiers.

For example, if we directly used user ID `300` as a row index, we would need at least `301` rows even though the dataset contains only three users. Such a representation would waste memory and would not reflect the actual structure of the data.

After mapping the identifiers, we can determine the correct dimensions of the interaction matrix.

```python
num_users = len(unique_user_ids)
num_items = len(unique_item_ids)
matrix_shape = (num_users, num_items)

print(f"\nMatrix shape (num_unique_users, num_unique_items): {matrix_shape}")
```

Output:

```
Matrix shape (num_unique_users, num_unique_items): (3, 5)
```

The interaction matrix therefore has the shape:

$$[ 3 \times 5 ]$$

because the dataset contains three unique users and five unique items.

# Constructing a COO Sparse Matrix

We can now construct the interaction matrix in **COO format**.

This can be done using the `coo_matrix` class from `scipy.sparse`.

The constructor receives two essential pieces of information:

1. the values to be stored in the matrix;
2. the row and column coordinates associated with those values.

It also receives the overall shape of the matrix.

In our example:

- `ratings_df['rating']` contains the interaction values;
- `mapped_user_ids` contains the row indices;
- `mapped_item_ids` contains the column indices;
- `matrix_shape` specifies the matrix dimensions.

```python
from scipy.sparse import coo_matrix

sparse_matrix_from_df = coo_matrix((ratings_df['rating'], 
                       (mapped_user_ids, mapped_item_ids)), 
                                   shape=matrix_shape)

print(sparse_matrix_from_df)
print("Shape:", sparse_matrix_from_df.shape)
print("Data type:", sparse_matrix_from_df.dtype)
print("Number of non-zero elements (nnz):", sparse_matrix_from_df.nnz)
```

Output:

```
<COOrdinate sparse matrix of dtype 'int64'
	with 9 stored elements and shape (3, 5)>
  Coords	Values
  (0, 0)	5
  (0, 1)	4
  (1, 0)	4
  (1, 2)	5
  (2, 1)	3
  (2, 2)	4
  (2, 3)	5
  (0, 4)	3
  (1, 4)	4
Shape: (3, 5)
Data type: int64
Number of non-zero elements (nnz): 9
```

As shown above, the sparse matrix stores only the coordinates and values of its stored entries.

For example,

```
(0, 0)    5
```

means that the value at row `0`, column `0` is `5`.

Similarly,

```
(2, 3)    5
```

means that the value at row `2`, column `3` is `5`.

The notation `nnz` refers to the **number of stored nonzero elements**. In this example:

\[ nnz = 9 \]

## An Important Interpretation

The sparse matrix can be understood directly from the mapped interaction records.

Conceptually, `scipy.sparse` receives data equivalent to:

```
   rating  mapped_user_id  mapped_item_id
0       5               0               0
1       4               0               1
2       4               1               0
3       5               1               2
4       3               2               1
5       4               2               2
6       5               2               3
7       3               0               4
8       4               1               4
```

Each row specifies one stored matrix entry.

For example:

```
rating = 5
mapped_user_id = 0
mapped_item_id = 0
```

corresponds to:

\[ R_{0,0} = 5 \]

Likewise:

```
rating = 4
mapped_user_id = 1
mapped_item_id = 2
```

corresponds to:

$$[ R_{1,2} = 4 ]$$

The complete dense representation of this interaction matrix would therefore be:

$$ R = \begin{bmatrix} 5 & 4 & 0 & 0 & 3 \\ 4 & 0 & 5 & 0 & 4 \\ 0 & 3 & 4 & 5 & 0 \end{bmatrix} $$

However, the sparse representation does not explicitly store all of these zeros.

# Constructing a Sparse Matrix from a Dense NumPy Array

A sparse matrix can also be constructed from an existing dense NumPy array.

For example:

```python
dense_array = np.array([
    [1, 0, 0],
    [0, 0, 2],
    [0, 3, 0]
])

sparse_matrix_csr_from_dense = coo_matrix(dense_array)

print(sparse_matrix_csr_from_dense)
print("Shape:", sparse_matrix_csr_from_dense.shape)
print("Number of non-zero elements (nnz):", sparse_matrix_csr_from_dense.nnz)
```

Output:

```
<COOrdinate sparse matrix of dtype 'int64'
	with 3 stored elements and shape (3, 3)>
  Coords	Values
  (0, 0)	1
  (1, 2)	2
  (2, 1)	3
Shape: (3, 3)
Number of non-zero elements (nnz): 3
```

The original dense matrix is:

\[ \begin{bmatrix} 1 & 0 & 0 \\ 0 & 0 & 2 \\ 0 & 3 & 0 \end{bmatrix} \]

but the COO representation only needs to store the three nonzero entries:

\[ (0,0,1),\quad(1,2,2),\quad(2,1,3) \]

Although converting a dense array into a sparse matrix is possible, this approach is generally **not recommended for very large matrices when the purpose of using sparse structures is to conserve memory**.

If a very large dense matrix is constructed first, the memory cost has already been incurred before the conversion takes place. Therefore, whenever possible, large matrices should be constructed directly in sparse form from the underlying interaction records.

# Converting Between Sparse Formats

After initially constructing a matrix in COO format, it is common to convert it to **CSR** or **CSC**, because these representations are more efficient for many computational operations.

## COO to CSR

A COO matrix can be converted to CSR using `.tocsr()`:

```python
from scipy.sparse import csr_matrix

sparse_matrix_csr = sparse_matrix_from_df.tocsr()
print(sparse_matrix_csr)
```

Output:

```
<Compressed Sparse Row sparse matrix of dtype 'int64'
	with 9 stored elements and shape (3, 5)>
  Coords	Values
  (0, 0)	5
  (0, 1)	4
  (0, 4)	3
  (1, 0)	4
  (1, 2)	5
  (1, 4)	4
  (2, 1)	3
  (2, 2)	4
  (2, 3)	5
```

Notice that the entries are now organized row by row.

The first row contains:

```
(0, 0)    5
(0, 1)    4
(0, 4)    3
```

The second row contains:

```
(1, 0)    4
(1, 2)    5
(1, 4)    4
```

and the third row contains:

```
(2, 1)    3
(2, 2)    4
(2, 3)    5
```

This organization makes CSR particularly suitable for row-oriented operations, which are extremely common in recommender systems. For example, retrieving all interactions associated with a particular user corresponds directly to retrieving one row of the user–item matrix.

## CSR to CSC

The CSR matrix can be converted to CSC using `.tocsc()`:

```python
from scipy.sparse import csc_matrix

sparse_matrix_csc = sparse_matrix_csr.tocsc()
print(sparse_matrix_csc)
```

Output:

```
<Compressed Sparse Column sparse matrix of dtype 'int64'
	with 9 stored elements and shape (3, 5)>
  Coords	Values
  (0, 0)	5
  (1, 0)	4
  (0, 1)	4
  (2, 1)	3
  (1, 2)	5
  (2, 2)	4
  (2, 3)	5
  (0, 4)	3
  (1, 4)	4
```

As the name **Compressed Sparse Column** suggests, the entries are organized according to their columns.

For example, column `0` contains:

```
(0, 0)    5
(1, 0)    4
```

while column `1` contains:

```
(0, 1)    4
(2, 1)    3
```

This organization makes CSC particularly suitable for column-oriented operations. In a recommender system, a column often represents an item, so CSC can be useful when we need to efficiently retrieve all users who interacted with a particular item.

## Converting Back to COO

Sparse-format conversion is not restricted to converting COO matrices into CSR or CSC. A matrix represented in another sparse format can also be converted back to COO.

For example:

```python
sparse_matrix_coo_again = sparse_matrix_csr.tocoo()
print(sparse_matrix_coo_again)
```

Output:

```
<COOrdinate sparse matrix of dtype 'int64'
	with 9 stored elements and shape (3, 5)>
  Coords	Values
  (0, 0)	5
  (0, 1)	4
  (0, 4)	3
  (1, 0)	4
  (1, 2)	5
  (1, 4)	4
  (2, 1)	3
  (2, 2)	4
  (2, 3)	5
```
