In previous chapters, we introduced the user–item interaction matrix as a fundamental representation of user behavior in recommender systems. In this matrix, rows correspond to users, columns correspond to items, and individual entries represent the type or intensity of interactions, such as ratings, click counts, or viewing durations.

In real-world recommender systems, the numbers of users and items can be extremely large, potentially reaching millions of users and billions of items. However, an important characteristic of these systems is that each user interacts with only a very small fraction of the available items.

For example, an individual user may have watched only a limited number of movies, purchased a relatively small collection of products, or listened to a subset of the songs available on a streaming platform. Meanwhile, thousands or millions of other items remain unexplored.

Consequently, instead of containing observed interaction values in most positions, a user–item interaction matrix typically contains a large number of empty or zero-valued entries.

Matrices in which most elements are zero are called sparse matrices.

Understanding sparse matrices and the computational challenges associated with them is an essential first step toward understanding why techniques such as matrix factorization are particularly valuable in recommender systems.

## Dense Matrices vs. Sparse Matrices

To understand the significance of sparsity, we must first distinguish between two types of matrices: dense matrices and sparse matrices.

### Dense Matrices

A dense matrix is a matrix in which a substantial proportion of the elements are nonzero.

In numerical computing, dense matrix representations allocate storage for every element, regardless of its value.

For example, a conventional two-dimensional NumPy array uses a dense representation. NumPy allocates memory for every position in the array, including positions containing zero.

Consider the following example:

```python
import numpy as np
dense_matrix = np.array([    [1, 0, 3],    [0, 5, 0],    [4, 0, 6]])
print("Shape:", dense_matrix.shape)print(dense_matrix)
```

Output:

```
Shape: (3, 3)
[[1 0 3]
 [0 5 0]
 [4 0 6]]
```

Mathematically, the matrix is represented as:

$$A=\begin{bmatrix}1 & 0 & 3 \\ 0 & 5 & 0 \\ 4 & 0 & 6\end{bmatrix}$$

The matrix contains nine elements, five of which are nonzero.

Although some entries are zero, NumPy stores all nine elements explicitly.

This approach is appropriate when most elements contain meaningful values or when the matrix is sufficiently small that memory consumption is not a concern.

However, it becomes inefficient when the dimensions are extremely large and most entries are zero.

It is important to distinguish between the **mathematical properties of a matrix** and its **storage representation**. A NumPy array always uses a dense storage representation, even if most of its elements are zero.

### Sparse Matrices

A **sparse matrix** is a matrix in which most elements are zero.

In recommender systems, the user–item interaction matrix is typically sparse because each user interacts with only a small subset of the available items.

Consider a movie recommendation platform with:

- 1,000,000 users
- 10,000 movies
- an average of 100 rated movies per user

The total number of possible user–movie pairs is:

$$1000000 \times 10000 = 10000000000$$

However, assuming each user rates 100 distinct movies, the total number of observed interactions is:

$$1000000 \times 100 = 100000000$$

Therefore, the proportion of observed interactions is:

$$\frac{100000000}{10000000000}=0.01=1\%$$

This means that only **1%** of the matrix entries are nonzero, while **99%** of the entries are empty or zero. This is a clear example of a highly sparse matrix.
