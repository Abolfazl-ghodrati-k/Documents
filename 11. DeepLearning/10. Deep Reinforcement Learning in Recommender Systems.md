**Deep Reinforcement Learning (DRL)** combines the trial-and-error learning framework of reinforcement learning with the representation-learning capabilities of deep neural networks. This combination has significantly expanded the range of complex decision-making problems that artificial intelligence agents can solve.

The success of DRL in Atari games, the achievements of AlphaGo, and subsequent developments such as MuZero demonstrate the ability of reinforcement learning agents to discover sophisticated strategies through interaction with an environment.

Unlike conventional supervised learning, reinforcement learning does not necessarily require a dataset containing the correct action for every possible situation. Instead, an agent learns from the consequences of its decisions, using rewards and penalties to improve its behavior over time.

This capability is particularly relevant to recommender systems, where recommendations influence subsequent user behavior and where optimizing immediate engagement does not necessarily maximize long-term user satisfaction.

## 10.1. Overview of Deep Reinforcement Learning

Consider a child learning to ride a bicycle.

The child performs an action, such as pedaling or steering, and receives feedback from the environment.

Successful actions help the child maintain balance, while unsuccessful actions may cause a fall.

Through repeated trial and error, the child gradually discovers a strategy that makes riding the bicycle easier and more reliable.

Reinforcement learning follows a similar principle.

An intelligent agent interacts with an environment, observes the consequences of its actions, and learns a strategy that maximizes its cumulative reward.

**Deep Reinforcement Learning** extends this framework by using deep neural networks to represent complex states, approximate value functions, or learn decision-making policies.

### 10.1.1. Agent–Environment Interaction

A reinforcement learning system consists of two principal components:

- **Agent:** The decision-making entity that selects actions.
- **Environment:** The system with which the agent interacts and from which it receives observations and rewards.

At each time step $t$, the interaction proceeds through four stages.

**1. State Observation**

The agent observes the current state:

$$
s_{t}
$$

The state represents information relevant to the current decision.

In a recommender system, it may include:

- The user's browsing history.
- Previously viewed or purchased items.
- Items currently displayed on the page.
- The time of interaction.
- Other contextual information.

**2. Action Selection**

Based on the observed state, the agent selects an action:

$$
a_{t}
$$

In a recommender system, an action may correspond to recommending a particular item to the user.

**3. Reward Observation**

After the action is executed, the agent receives a scalar reward:

$$
r_{t}
$$

The reward evaluates the outcome of the action.

For example:

- A click or purchase may produce a positive reward.
- Explicit rejection may produce a negative reward.
- Ignoring a recommendation may also be treated as negative feedback, depending on the reward design.

**4. State Transition**

The environment transitions to a new state:

$$
s_{t+1}
$$

The new state reflects the consequences of the previous action and any changes in the environment.

The complete interaction can therefore be represented as:

$$
(s_{t},a_{t},r_{t},s_{t+1})
$$

These interaction experiences provide the information used to train the reinforcement learning agent.

The parameters of its neural networks are updated using optimization methods such as Stochastic Gradient Descent (SGD) or related gradient-based algorithms.

Over time, the agent learns to select actions that maximize expected future rewards.

### 10.1.2. Markov Decision Processes

Sequential decision-making problems in reinforcement learning are commonly modeled using a **Markov Decision Process (MDP)**.

An MDP provides a mathematical framework for representing an environment in which actions influence both immediate rewards and future states.

The framework is particularly useful for recommender systems because recommending an item may affect not only the user's immediate response but also their subsequent interactions.

For example, recommending a product may influence what the user views next, which in turn changes the information available for future recommendations.

The reinforcement learning agent therefore attempts to learn a decision-making strategy that accounts for these sequential effects.

### 10.1.3. Value Functions

One of the principal approaches in deep reinforcement learning is to approximate a **Value Function** using a neural network.

A value function estimates the expected cumulative reward associated with a state or a state–action pair.

An important example is the action-value function:

$$
Q(s,a)
$$

This function estimates the expected long-term reward obtained by selecting action $a$ in state $s$ and subsequently following a particular policy.

In a recommender system, $Q(s,a)$ can estimate the long-term value of recommending item $a$ when the user is in state $s$.

The estimated value is not limited to the immediate reward associated with the recommendation.

It also accounts for expected future rewards.

This distinction is important because an item that produces an immediate click may not necessarily lead to the greatest long-term engagement.

### 10.1.4. Deep Q-Networks

A **Deep Q-Network (DQN)** uses a deep neural network to approximate the action-value function.

Instead of maintaining a separate value for every possible state–action combination, the network learns a mapping from state–action information to estimated long-term rewards.

The model can then select actions according to their predicted values.

DQN became widely recognized through its success in learning to play Atari games from visual observations.

This demonstrated that deep neural networks could learn useful representations from high-dimensional inputs while simultaneously supporting sequential decision-making.

In recommendation applications, a DQN can estimate the long-term value of recommending different candidate items.

### 10.1.5. Policy-Based Algorithms

An alternative to directly learning action values is to learn a decision-making policy.

A policy specifies how an agent selects actions in different states.

A parameterized stochastic policy is represented as:

$$
\pi_{\theta}(a\mid s)
$$

Where:

- $\pi_{\theta}(a\mid s)$ is the probability of selecting action $a$ in state $s$.
- $\theta$ represents the learnable parameters of the policy.
- $s$ is the current state.
- $a$ is a candidate action.

In policy-based reinforcement learning, the agent directly optimizes the policy parameters.

The objective is to increase the probability of actions that contribute to greater expected cumulative rewards.

### 10.1.6. Expected Discounted Return

The principal objective of a reinforcement learning agent is to maximize its **Expected Discounted Return**.

This objective can be expressed as:

$$
J(\theta)=\mathbb{E}_{\pi_{\theta}}\left[\sum_{t=0}^{\infty}\gamma^{t}r_{t}\right]
$$

Where:

- $J(\theta)$ is the expected discounted return that the agent seeks to maximize.
- $\theta$ represents the parameters of the policy or decision-making model.
- $\mathbb{E}_{\pi_{\theta}}$ denotes the expectation over trajectories generated by the policy.
- $\sum_{t=0}^{\infty}$ represents the cumulative reward across time steps.
- $\gamma$ is the discount factor.
- $r_{t}$ is the reward received at time step $t$.

The discount factor typically satisfies:

$$
0\le\gamma<1
$$

Its purpose is to control the relative importance of immediate and future rewards.

**When the discount factor is close to zero:**

The agent places greater emphasis on immediate rewards.

**When the discount factor is close to one:**

Future rewards receive greater importance.

In a recommender system, the choice of discount factor influences whether the agent prioritizes immediate interactions or longer-term outcomes.

For example, a recommendation strategy optimized primarily for immediate clicks may differ from one designed to encourage sustained user engagement.

### 10.1.7. Actor–Critic Architectures

Modern deep reinforcement learning frequently uses **Actor–Critic Architectures** to improve training stability and learning efficiency.

An actor–critic system contains two components.

**Actor**

The actor is responsible for selecting actions.

It learns a policy:

$$
\pi_{\theta}(a\mid s)
$$

The actor determines which action should be taken in a particular state.

**Critic**

The critic evaluates the quality of states or actions.

It may estimate a state-value function:

$$
V(s)
$$

Or an action-value function:

$$
Q(s,a)
$$

The critic provides an evaluation signal that helps the actor improve its policy.

For example, the critic may determine whether recommending a particular item is expected to produce a favorable long-term outcome.

The actor can then adjust its policy to favor actions associated with higher expected rewards.

By combining action selection and value estimation, actor–critic methods can provide more effective learning than approaches that rely exclusively on one of these mechanisms.

### 10.1.8. Applications and Developments in Deep Reinforcement Learning

Deep reinforcement learning has demonstrated considerable potential across complex sequential decision-making problems.

Notable developments include:

- **DQN:** Demonstrated strong performance in Atari games.
- **AlphaGo:** Combined deep neural networks with search and reinforcement learning to achieve exceptional performance in Go.
- **MuZero:** Extended model-based reinforcement learning by learning representations useful for planning without requiring an explicitly specified environment dynamics model.

Applications of DRL include:

- Robotics.
- Autonomous driving.
- Game-playing agents.
- Treatment planning.
- Portfolio optimization.
- Recommender systems.

Current research continues to address important challenges, particularly:

**Sample Efficiency**

Reducing the amount of interaction data required to learn effective policies.

**Training Stability**

Improving the reliability of optimization and reducing instability during learning.

**Exploration**

Encouraging agents to discover useful actions rather than repeatedly selecting only familiar alternatives.

Several techniques contribute to these objectives.

**Prioritized Experience Replay**

Prioritizes more informative past experiences during training.

**Meta-Learning**

Investigates how agents can adapt more efficiently to new tasks or environments.

**Model-Based Methods**

Use learned or available models of the environment to support planning and decision-making.

Open-source libraries such as **Stable Baselines3** and **RLlib** provide implementations of reinforcement learning algorithms and tools for experimentation across different environments.

These developments have made DRL increasingly accessible for research and practical applications.

## 10.2. DEERS: Deep Reinforcement Learning for Recommendations with Negative Feedback

Consider an intelligent recommendation agent operating in an online store.

The agent must decide which products to recommend to a customer.

A conventional recommendation model may primarily focus on products the customer has previously clicked or purchased.

However, positive interactions represent only part of the available behavioral information.

The customer may also have rejected certain products or ignored previously displayed recommendations.

Such negative feedback can provide valuable information about the customer's preferences.

The **DEERS** approach, introduced in *Recommendations with Negative Feedback via Pairwise Deep Reinforcement Learning*, incorporates both positive and negative feedback into a deep reinforcement learning framework.

Its objective is to improve sequential recommendation by learning from multiple types of user responses while maximizing long-term rewards.

### 10.2.1. Recommendation as a Markov Decision Process

DEERS models recommendation as a Markov Decision Process.

The recommendation agent repeatedly interacts with users by selecting items and observing their responses.

Each recommendation affects the immediate reward and may also influence subsequent user behavior.

The agent therefore attempts to learn a recommendation policy that maximizes cumulative long-term reward rather than considering each recommendation independently.

The model distinguishes between two types of user feedback.

**Positive Feedback**

Positive feedback indicates favorable user behavior, such as:

- Clicking a recommended item.
- Purchasing a product.
- Selecting an item for further interaction.

**Negative Feedback**

Negative feedback indicates unfavorable or non-engaging behavior, such as:

- Rejecting a recommended item.
- Skipping an item.
- Ignoring a recommendation.

The model uses both types of feedback to construct a representation of the user's current preferences.

### 10.2.2. State Representation

At time step $t$, DEERS represents the user's state as a pair:

$$
s_{t}=(s_{t}^{+},s_{t}^{-})
$$

Where:

- $s_{t}^{+}$ represents the user's recent positive interaction history.
- $s_{t}^{-}$ represents the user's recent negative interaction history.

Each component contains information about the most recent $N$ interactions of the corresponding type.

**Positive State**

$$
s_{t}^{+}
$$

This component contains the most recent $N$ items with which the user interacted positively.

For example, it may include recently clicked or purchased products.

These items provide evidence about the user's interests.

**Negative State**

$$
s_{t}^{-}
$$

This component contains the most recent $N$ items associated with negative feedback.

For example, it may include rejected or skipped recommendations.

These items provide information about characteristics the user may prefer to avoid.

Separating positive and negative histories allows the model to represent both attraction to and rejection of different item characteristics.

### 10.2.3. Actions and Rewards

At each time step, the agent selects an action:

$$
a_{t}
$$

The action corresponds to choosing an item to recommend.

After the recommendation is presented, the user provides feedback.

The agent receives a scalar reward:

$$
r_{t}
$$

The reward reflects the observed response.

For example:

- Clicking or purchasing the recommended item may produce a positive reward.
- Rejecting the item may produce a negative reward.

The agent uses these rewards to evaluate the effectiveness of its recommendations.

Because the framework considers future rewards, it attempts to learn recommendations that contribute to favorable outcomes over multiple interactions.

### 10.2.4. Deep Q-Network Architecture

DEERS uses a Deep Q-Network to estimate the optimal action-value function:

$$
Q^{*}(s^{+},s^{-},a)
$$

Where:

- $s^{+}$ is the positive interaction state.
- $s^{-}$ is the negative interaction state.
- $a$ is the candidate recommendation action.
- $Q^{*}(s^{+},s^{-},a)$ is the optimal expected long-term value of selecting action $a$ in the given state.

The model employs a specialized **Two-Stream Architecture**.

The two streams process positive and negative feedback separately.

**Positive Feedback Stream**

The first stream processes:

$$
(s^{+},a)
$$

It learns relationships between the candidate item and the user's positive interaction history.

This allows the model to identify candidate items that are compatible with previously expressed interests.

**Negative Feedback Stream**

The second stream processes:

$$
(s^{-},a)
$$

It learns relationships between the candidate item and the user's negative interaction history.

This helps the model identify items resembling previously rejected or ignored recommendations.

The representations produced by the two streams are subsequently combined through shared hidden layers.

The resulting representation incorporates both positive and negative behavioral evidence.

### 10.2.5. Learning from Positive and Negative Preferences

The two-stream architecture enables DEERS to model user preferences more comprehensively.

For example, suppose a user has:

- Clicked several science-fiction movies.
- Repeatedly ignored romantic comedies.

The positive feedback stream can identify similarities between candidate movies and the user's preferred science-fiction content.

The negative feedback stream can identify similarities between candidate movies and the ignored romantic comedies.

By combining both sources of information, the model can estimate which recommendations are more likely to produce favorable outcomes.

The objective is not merely to recommend items similar to positive interactions.

It is also to reduce the likelihood of recommending items associated with previously observed negative feedback.

### 10.2.6. Item Embedding Representations

Before being processed by the Deep Q-Network, items in both positive and negative histories are mapped into dense embedding vectors.

Each item is represented numerically in a latent feature space.

This process is analogous to representing words in a sentence using word embeddings.

A sequence of user interactions can therefore be treated as a sequence of embedded item representations.

These embeddings provide the neural network with numerical information from which it can learn relationships among items.

The positive and negative interaction embeddings are passed to their corresponding network streams.

The network then learns representations that support action-value estimation.

### 10.2.7. Offline Training from Interaction Logs

DEERS is trained offline using previously collected user interaction logs.

These logs contain information about:

- Historical user states.
- Recommended items.
- Observed feedback.
- Resulting rewards.
- Subsequent states.

The model uses these experiences to learn the relationship between recommendation decisions and their consequences.

This allows the agent to improve its estimated action values without requiring every training update to involve a new live user interaction.

### 10.2.8. Temporal-Difference Learning

DEERS updates its Deep Q-Network using **Temporal-Difference (TD) Learning**.

Temporal-difference learning adjusts value estimates by comparing predicted action values with targets derived from observed rewards and estimated future values.

A standard one-step TD target is:

$$
y_{t}=r_{t}+\gamma\max_{a'}Q(s_{t+1},a')
$$

Where:

- $y_{t}$ is the temporal-difference target.
- $r_{t}$ is the observed immediate reward.
- $\gamma$ is the discount factor.
- $s_{t+1}$ is the next state.
- $a'$ represents a possible next action.
- $Q(s_{t+1},a')$ estimates the future value of selecting action $a'$ in the next state.

The corresponding squared TD error is:

$$
\mathcal{L}_{TD}=(y_{t}-Q(s_{t},a_{t}))^{2}
$$

The network parameters are updated to reduce the difference between the predicted action value and the TD target.

In the DEERS setting, the state includes both positive and negative feedback histories:

$$
s_{t}=(s_{t}^{+},s_{t}^{-})
$$

Consequently, the learned action-value function incorporates information from both types of user behavior.

Repeated TD updates allow the model to improve its estimates of long-term recommendation value.

### 10.2.9. Advantages of DEERS

DEERS provides several important capabilities for sequential recommendation.

**Integration of Positive and Negative Feedback**

The model incorporates both favorable and unfavorable user responses into its state representation.

**Dynamic Preference Modeling**

Recent interaction histories allow the model to adapt its recommendations as user behavior changes.

**Long-Term Reward Optimization**

The reinforcement learning framework considers future rewards rather than optimizing only immediate recommendation outcomes.

**Two-Stream Representation Learning**

Separate processing of positive and negative histories enables the model to learn distinct patterns associated with preferred and rejected items.

**Sequential Decision-Making**

The model treats recommendation as an ongoing interaction process in which earlier decisions can influence future states and rewards.

These properties make DEERS suitable for recommendation settings where user preferences evolve over time and where negative feedback provides meaningful information about future recommendation decisions.
