4. Autoencoder-Based Recommendation Methods

This section examines one of the most important and widely used architectures in deep learning: the **Autoencoder**. We first explore its general structure and operating principles, then examine its applications in recommender systems through **AutoRec** and the **Collaborative Denoising Auto-Encoder (CDAE)**.

## 4.1. Introduction to Autoencoders

Imagine an artist attempting to capture the essential characteristics of a large, complex painting in a small, simplified sketch. The sketch should preserve enough information for someone examining it to reconstruct the original painting as accurately as possible.

An autoencoder operates according to a similar principle.

![Illustration of representation compression and reconstruction](https://quera.org/qbox/download/ZZohUhWiwA/AD_4nXf47-1uX-a_5466a2f5.png)

An **Autoencoder** is an artificial neural network designed to learn a compact representation of its input data, commonly called a *latent representation*. This representation captures important characteristics of the input, often within a lower-dimensional space.

The network is trained to reconstruct its original input from this learned representation.

An autoencoder consists of two principal components:

1. **Encoder**
2. **Decoder**

### 4.1.1. Encoder

The **Encoder** transforms the original input into a compact latent representation.

For example, the input may be a high-resolution image or a long vector containing information about user interactions.

The encoder maps this input into a latent representation, denoted by $\mathbf{z}$:

$$
\mathbf{z}=f_{\theta}(\mathbf{x})
$$

Where:

- $\mathbf{x}$ is the original input vector.
- $f_{\theta}$ is the encoder function, parameterized by $\theta$.
- $\mathbf{z}$ is the learned latent representation.

The encoder can be viewed as an intelligent compression mechanism that attempts to preserve essential information while discarding redundant or unnecessary details.

### 4.1.2. Decoder

The **Decoder** receives the latent representation and attempts to reconstruct the original input.

Its operation can be expressed as:

$$
\hat{\mathbf{x}}=g_{\phi}(\mathbf{z})
$$

Where:

- $\mathbf{z}$ is the latent representation.
- $g_{\phi}$ is the decoder function, parameterized by $\phi$.
- $\hat{\mathbf{x}}$ is the reconstructed input.

Combining both components gives:

$$
\hat{\mathbf{x}}=g_{\phi}(f_{\theta}(\mathbf{x}))
$$

The encoder learns how to represent the input compactly, while the decoder learns how to reconstruct the original information from that representation.

### 4.1.3. Reconstruction Loss

The primary objective of an autoencoder is to minimize its **Reconstruction Loss**, which measures the difference between the original input and its reconstruction.

For continuous numerical data, a common reconstruction loss is **Mean Squared Error (MSE)**:

$$
\mathcal{L}_{reconstruction}=\frac{1}{n}\sum_{j=1}^{n}(x_{j}-\hat{x}_{j})^{2}
$$

Where:

- $n$ is the number of input features.
- $x_{j}$ is the original value of feature $j$.
- $\hat{x}_{j}$ is its reconstructed value.

By minimizing reconstruction error under an appropriate architectural constraint, such as a lower-dimensional bottleneck, the network is encouraged to learn important underlying patterns rather than simply copying its inputs.

For example, an image autoencoder may learn representations corresponding to shapes, textures, and other visual characteristics.

Similarly, an autoencoder trained on user interaction data may discover patterns associated with user preferences and relationships among items.

However, a reconstruction objective alone does not guarantee meaningful feature learning. If the network has excessive capacity and insufficient regularization, it may simply learn to reproduce its inputs without discovering useful underlying structure.

### 4.1.4. Why Autoencoders Are Useful in Recommender Systems

Autoencoders are particularly relevant to recommendation problems because user–item interaction data is typically sparse.

Most users interact with only a small fraction of the available items.

Consequently, the user–item interaction matrix contains many unobserved entries.

Autoencoder-based recommendation models attempt to learn patterns from observed interactions and use those patterns to estimate missing preferences.

Their ability to learn informative latent representations provides a mechanism for discovering relationships among users and items without relying exclusively on traditional matrix factorization.

Several recommendation architectures have been developed around this principle.

One of the most influential examples is **AutoRec**.

## 4.2. AutoRec: Autoencoders for Collaborative Filtering

**AutoRec** is an autoencoder-based recommendation model that reformulates collaborative filtering as a reconstruction problem.

Rather than directly decomposing the user–item interaction matrix into latent-factor matrices, AutoRec learns to reconstruct user or item interaction vectors through a neural network.

The reconstructed values can then be used to estimate missing ratings or preferences.

### 4.2.1. Representing User–Item Interactions

Consider the user–item interaction matrix:

$$
\mathbf{R}\in\mathbb{R}^{m\times n}
$$

Where:

- $m$ is the number of users.
- $n$ is the number of items.
- $R_{ui}$ represents the observed rating or interaction between user $u$ and item $i$.

Each row of the matrix represents the interactions associated with a particular user.

Each column represents the interactions received by a particular item from different users.

![User–item interaction matrix](https://quera.org/qbox/download/QiegGGxATk/AD_4nXdFeSKmm1U_926722db.png)

For user $u$, the corresponding interaction vector is:

$$
\mathbf{r}_{u}=(R_{u1},R_{u2},\ldots,R_{un})
$$

For item $i$, the corresponding interaction vector is:

$$
\mathbf{c}_{i}=(R_{1i},R_{2i},\ldots,R_{mi})
$$

These vectors can serve as inputs to an autoencoder.

The model learns to reconstruct the observed interaction patterns and uses its output to estimate unobserved entries.

This leads to two variants of AutoRec:

- **Item-Based AutoRec (I-AutoRec)**
- **User-Based AutoRec (U-AutoRec)**

### 4.2.2. Item-Based AutoRec (I-AutoRec)

In **I-AutoRec**, the model receives item interaction vectors as inputs.

Each input vector contains the ratings that a particular item has received from different users.

For item $i$, the input is:

$$
\mathbf{c}_{i}=(R_{1i},R_{2i},\ldots,R_{mi})
$$

The autoencoder attempts to reconstruct this vector:

$$
\hat{\mathbf{c}}_{i}=g_{\phi}(f_{\theta}(\mathbf{c}_{i}))
$$

The reconstructed vector contains predicted ratings for the users represented in the input space.

Although each item provides a separate training example, the model generally uses a **shared autoencoder** across items rather than training an independent neural network for every item.

By learning patterns across item rating vectors, I-AutoRec can identify relationships among users' preferences and estimate missing ratings.

### 4.2.3. User-Based AutoRec (U-AutoRec)

In **U-AutoRec**, the model receives user interaction vectors as inputs.

Each vector contains the ratings or interactions of one user across the available items.

For user $u$:

$$
\mathbf{r}_{u}=(R_{u1},R_{u2},\ldots,R_{un})
$$

The model reconstructs this vector:

$$
\hat{\mathbf{r}}_{u}=g_{\phi}(f_{\theta}(\mathbf{r}_{u}))
$$

The reconstructed output contains estimated preferences for the items represented in the vector.

As with I-AutoRec, a shared autoencoder is trained across the corresponding interaction vectors.

The main difference between the two variants is the orientation of the interaction matrix used as input.

| Characteristic | I-AutoRec | U-AutoRec |
|---|---|---|
| Input | Item interaction vector | User interaction vector |
| Input dimensionality | Number of users | Number of items |
| Training examples | Items | Users |
| Reconstruction target | Ratings received by an item | Ratings assigned by a user |
| Main purpose | Estimate missing user ratings for items | Estimate missing item ratings for users |

Both approaches have demonstrated promising performance in collaborative filtering.

In the original AutoRec research, the item-based variant achieved particularly strong results and generally performed better than the user-based variant in the evaluated settings. However, the relative performance of the two variants depends on the dataset and experimental configuration.

### 4.2.4. Learning from Sparse Interaction Data

A major challenge in AutoRec is distinguishing between observed ratings and missing entries.

A missing interaction does not necessarily indicate that the user dislikes an item.

It may simply mean that the user has never encountered the item.

Therefore, the reconstruction objective should not automatically treat every missing rating as an observed rating of zero.

For explicit-rating prediction, a common approach is to calculate reconstruction loss only over observed entries.

Let:

$$
M_{ui}=\begin{cases}1 & \text{if }R_{ui}\text{ is observed}\\0 & \text{otherwise}\end{cases}
$$

The masked reconstruction loss can be written as:

$$
\mathcal{L}=\frac{\sum_{u=1}^{m}\sum_{i=1}^{n}M_{ui}(R_{ui}-\hat{R}_{ui})^{2}}{\sum_{u=1}^{m}\sum_{i=1}^{n}M_{ui}}
$$

This objective measures reconstruction errors only where ground-truth ratings are available.

The model can nevertheless produce predictions for missing entries, allowing those predictions to be used for recommendation.

### 4.2.5. Practical Example: Product Recommendation

Consider an online shopping platform such as Digikala.

A user's historical interactions may include:

- Products viewed.
- Products purchased.
- Products added to a shopping cart.
- Products explicitly rated.

These interactions can be represented as a vector and supplied to an autoencoder-based recommendation model.

The model attempts to reconstruct the interaction pattern.

During this process, it may also generate predictions for items with which the user has not previously interacted.

Suppose a user has purchased several smartphone accessories but has never viewed Bluetooth earphones.

By learning patterns from interactions across many users, AutoRec may discover that users with similar purchasing histories frequently show interest in particular Bluetooth earphones.

The model can consequently assign a relatively high predicted preference to such products.

These predictions can be used to rank candidate items and generate personalized recommendations.

## 4.3. Implementing AutoRec in Python

As discussed previously, AutoRec receives an incomplete user or item rating vector and attempts to reconstruct a complete vector containing predictions for missing ratings.

In the following example, we construct a simple AutoRec model with one hidden layer.

The input is a vector containing ratings for ten items. Some items have been rated, while others are represented by zero values.

The central idea is that the model learns from this incomplete vector while calculating reconstruction error **only for observed ratings**.

This is particularly important in recommender systems because an unobserved rating does not necessarily indicate a negative preference.

The model should therefore avoid treating missing entries as actual ratings of zero.

We will examine the model architecture, input preparation, initial predictions, reconstruction loss, and one training iteration.

Some of the PyTorch operations introduced here require familiarity with neural network training, automatic differentiation, and numerical optimization. Readers seeking a deeper understanding of these concepts are encouraged to consult specialized deep learning courses and textbooks.

### 4.3.1. Defining the AutoRec Architecture

We begin by defining an autoencoder containing an encoder and a decoder.

The input vector has ten dimensions, and the hidden representation has five dimensions.

The encoder compresses the input into the hidden representation, while the decoder reconstructs the original ten-dimensional vector.

```python
import torch
import torch.nn as nn
import torch.optim as optim
import torch.nn.functional as F

# تعریف ابعاد
num_items = 10
hidden_dim = 5

# مدل AutoRec
class AutoRec(nn.Module):
    def __init__(self, num_items, hidden_dim):
        super(AutoRec, self).__init__()
        # رمزگذار (Encoder): ورودی را به فضای فشرده نگاشت می‌کند
        self.encoder = nn.Linear(num_items, hidden_dim)
        # رمزگشا (Decoder): فضای فشرده را به ابعاد اصلی بازسازی می‌کند
        self.decoder = nn.Linear(hidden_dim, num_items)

    def forward(self, x):
        encoded = F.relu(self.encoder(x))
        decoded = self.decoder(encoded)
        return decoded
```

The architecture contains two fully connected layers:

| Component | Input Dimensions | Output Dimensions | Activation |
|---|---:|---:|---|
| Encoder | 10 | 5 | ReLU |
| Decoder | 5 | 10 | Linear |

The encoder first applies a linear transformation followed by the ReLU activation function.

The decoder then transforms the hidden representation back into the original input space.

Mathematically, the forward computation can be expressed as:

$$
\mathbf{z}=ReLU(\mathbf{W}_{e}\mathbf{x}+\mathbf{b}_{e})
$$

$$
\hat{\mathbf{x}}=\mathbf{W}_{d}\mathbf{z}+\mathbf{b}_{d}
$$

The decoder uses a linear output layer, allowing it to produce continuous numerical predictions.

### 4.3.2. Preparing the Input Data and Observation Mask

Next, we instantiate the AutoRec model and prepare an incomplete rating vector.

Suppose the user has rated only three items:

- Item 0: Rating 5
- Item 3: Rating 4
- Item 7: Rating 3

All remaining entries are zero, indicating that their ratings are missing.

We also construct an **observation mask** to distinguish observed ratings from missing entries.

The mask contains:

- `1` for observed ratings.
- `0` for missing ratings.

```python
# ایجاد یک نمونه مدل
model = AutoRec(num_items, hidden_dim)

# ورودی: بردار رتبه‌بندی یک کاربر (ناقص)
# فرض کنید کاربر به آیتم‌های با ایندکس 0، 3 و 7 امتیاز داده است.
# باقی آیتم‌ها (با مقدار 0) هنوز رتبه‌بندی نشده‌اند.
ratings = torch.tensor([5.0, 0.0, 0.0, 4.0, 0.0, 0.0, 0.0, 3.0, 0.0, 0.0])

# ساخت ماسک: این ماسک به ما می‌گوید کدام رتبه‌بندی‌ها مشاهده شده‌اند.
# 1 برای رتبه‌بندی‌های مشاهده‌شده، 0 برای رتبه‌بندی‌های گمشده
mask = (ratings > 0).float()

# ورودی به مدل یک Batch است (ابعاد [1, num_items])
input_data = ratings.unsqueeze(0)

# تعریف بهینه‌ساز
optimizer = optim.Adam(model.parameters(), lr=0.01)

print("--- شروع شبیه‌سازی یک گام آموزش ---")
print(f"ورودی خام مدل (رتبه‌بندی‌های ناقص): {input_data}")
print(f"ماسک رتبه‌بندی‌های مشاهده‌شده: {mask}")
```

**Output**

```text
--- شروع شبیه‌سازی یک گام آموزش ---
ورودی خام مدل (رتبه‌بندی‌های ناقص): tensor([[5., 0., 0., 4., 0., 0., 0., 3., 0., 0.]])
ماسک رتبه‌بندی‌های مشاهده‌شده: tensor([1., 0., 0., 1., 0., 0., 0., 1., 0., 0.])
```

The `ratings` tensor contains the user's incomplete rating history.

The `mask` tensor identifies the three observed ratings.

The `unsqueeze(0)` operation introduces a batch dimension, transforming the input shape from `[10]` to `[1, 10]`.

Finally, the Adam optimizer is initialized with a learning rate of `0.01`.

### 4.3.3. Calculating Initial Predictions and Reconstruction Loss

We now execute the model for the first time using the incomplete input vector.

Because the model parameters are initially randomized, its predictions have not yet been optimized.

The reconstruction loss is calculated using the observation mask so that only observed ratings contribute to the training objective.

```python
output_data = model(input_data)

# **نکته کلیدی:** تعریف تابع زیان که فقط روی رتبه‌بندی‌های مشاهده‌شده کار می‌کند.
# این همان چیزی است که AutoRec را برای داده‌های پراکنده کارآمد می‌کند.
loss = torch.sum(mask * (output_data - input_data)**2)

print("\n----------------------------------------------------")
print(f"خروجی خام مدل: {output_data.squeeze().detach()}")
print(f"زیان (فقط روی مقادیر مشاهده شده): {loss.item()}")
```

**Output**

```text
----------------------------------------------------
خروجی خام مدل: tensor([-0.1489,  0.4845, -0.3579,  0.3003,  0.5497,  0.8927, -0.5082,  0.8633,
         0.5370, -0.6524])
زیان (فقط روی مقادیر مشاهده شده): 44.7645378112793
```

The model produces a prediction for every item, including items whose ratings were missing from the input.

However, only the observed entries contribute to the reconstruction loss.

The loss function implemented in the code is:

$$
\mathcal{L}=\sum_{i=1}^{n}m_{i}(r_{i}-\hat{r}_{i})^{2}
$$

Where:

- $r_{i}$ is the observed or input rating for item $i$.
- $\hat{r}_{i}$ is the predicted rating.
- $m_{i}$ is the observation mask.
- $n$ is the total number of items.

When $m_{i}=0$, the corresponding squared error contributes nothing to the loss.

When $m_{i}=1$, the reconstruction error is included.

For the example, only the predictions for items 0, 3, and 7 contribute to the objective.

This masked reconstruction loss is essential for learning from sparse interaction matrices.

**Note:** The implementation uses the sum of squared errors over observed entries rather than their mean. The output values depend on the model's random initialization and may differ between executions.

### 4.3.4. Backpropagation and Parameter Updates

The next step is to update the model parameters using the calculated reconstruction loss.

This involves three operations:

1. `optimizer.zero_grad()` clears previously accumulated gradients.
2. `loss.backward()` performs backpropagation and computes gradients.
3. `optimizer.step()` updates the model parameters using the Adam optimization algorithm.

After the update, the model is executed again using the same input vector.

```python
# Backpropagation و به‌روزرسانی وزن‌ها
optimizer.zero_grad()
loss.backward()
optimizer.step()

# ورودی و خروجی پس از آموزش (با وزن‌های جدید)
new_output = model(input_data)
print("\n--- پس از یک گام آموزش ---")
print(f"خروجی جدید مدل: {new_output.squeeze().detach()}")
print(f"رتبه پیش‌بینی‌شده برای آیتم‌های گمشده به روز شده است.")
```

**Output**

```text
--- پس از یک گام آموزش ---
خروجی جدید مدل: tensor([-0.0904,  0.5103, -0.3167,  0.3755,  0.5392,  0.9561, -0.5862,  0.9782,
         0.5043, -0.6744])
رتبه پیش‌بینی‌شده برای آیتم‌های گمشده به روز شده است.
```

The output vector changes because the optimizer has updated the encoder and decoder parameters.

The updated model now produces different predictions for both observed and missing ratings.

This demonstrates the fundamental training mechanism of AutoRec: the model learns from observed interactions while generating reconstructed values for all items.

In a practical recommendation system, training would continue over many iterations and across numerous users or items.

The model would gradually learn patterns shared across interaction histories, enabling it to produce more meaningful predictions for previously unobserved interactions.

A single training step on one user vector is sufficient to demonstrate the mechanism, but it is not sufficient to train a reliable recommendation model.

## 4.4. Collaborative Denoising Auto-Encoder (CDAE)

The **Collaborative Denoising Auto-Encoder (CDAE)** is an autoencoder-based recommendation model designed to learn robust user preference representations from incomplete and noisy interaction data.

Consider a recommendation system containing a large collection of user interaction histories.

These histories are often incomplete because users interact with only a small fraction of the available items. They may also contain noisy or incidental interactions that do not accurately reflect long-term preferences.

CDAE addresses these challenges by introducing deliberate corruption into the training data and learning to reconstruct the original interaction patterns.

### 4.4.1. Denoising Autoencoders

A **Denoising Autoencoder** differs from a conventional autoencoder in the way its inputs are prepared.

Instead of receiving the original input directly, the model receives an intentionally corrupted version.

The training objective is to reconstruct the original, uncorrupted input from this modified representation.

Conceptually, this is similar to reconstructing a complete image from a blurred image or recovering a missing portion of a puzzle.

The deliberate corruption encourages the model to learn meaningful patterns rather than rely exclusively on individual observed features.

Let $\mathbf{x}$ represent the original interaction vector.

A corruption function produces:

$$
\tilde{\mathbf{x}}=C(\mathbf{x})
$$

Where:

- $\mathbf{x}$ is the original input.
- $C$ is the corruption process.
- $\tilde{\mathbf{x}}$ is the corrupted input.

The model attempts to reconstruct the original vector:

$$
\hat{\mathbf{x}}=g_{\phi}(f_{\theta}(\tilde{\mathbf{x}}))
$$

The reconstruction loss compares $\hat{\mathbf{x}}$ with the original input $\mathbf{x}$, rather than with the corrupted input.

This distinction is essential because the model must learn to recover information removed during corruption.

### 4.4.2. Incorporating User Embeddings

One of the principal characteristics of CDAE is the incorporation of a **User Embedding** into the neural architecture.

A user embedding is a learned vector that represents characteristics associated with a particular user's preferences.

It acts as a personalized representation that allows the model to distinguish between users who may have similar interaction histories but different underlying preferences.

For example, two users may have watched several of the same movies while differing in their preferences for particular actors, genres, or themes.

By incorporating user embeddings, CDAE can learn both shared interaction patterns and user-specific characteristics.

A simplified representation of the CDAE encoder is:

$$
\mathbf{h}_{u}=\phi(\mathbf{W}\tilde{\mathbf{x}}_{u}+\mathbf{v}_{u}+\mathbf{b})
$$

Where:

- $\tilde{\mathbf{x}}_{u}$ is the corrupted interaction vector for user $u$.
- $\mathbf{W}$ is a learnable weight matrix.
- $\mathbf{v}_{u}$ is the learned embedding associated with user $u$.
- $\mathbf{b}$ is a bias vector.
- $\phi$ is an activation function.
- $\mathbf{h}_{u}$ is the resulting hidden representation.

The user embedding contributes personalized information to the hidden representation.

Consequently, recommendations are influenced not only by patterns recovered from the corrupted interaction history but also by the user's learned individual characteristics.

### 4.4.3. CDAE for Top-K Recommendation

Unlike recommendation approaches primarily designed to predict exact numerical ratings, such as ratings on a one-to-five-star scale, CDAE is commonly applied to **Top-K Recommendation** using implicit feedback.

In Top-K recommendation, the objective is to identify the $K$ most relevant items for each user.

The model produces preference scores for candidate items, and these scores are used to rank the candidates.

The highest-ranked items are then selected for recommendation.

For example, a model may produce scores for hundreds of movies and return the ten movies with the highest predicted relevance.

The objective is therefore to construct a useful recommendation list rather than merely predict an individual numerical rating.

Although CDAE uses a reconstruction-based learning objective, its outputs can be used directly to rank items for personalized recommendation.

### 4.4.4. Learning Through Corrupted Interaction Histories

The central training strategy of CDAE is to deliberately remove or corrupt some observed interactions and train the network to reconstruct the original history.

Consider a streaming platform such as Netflix.

Suppose the platform has recorded a user's movie-watching history.

During training, CDAE may randomly remove some movies from the observed interaction vector.

The model then receives this incomplete version of the user's history and attempts to reconstruct the original interaction pattern.

The procedure consists of several stages.

**Stage 1: Constructing the Interaction Vector**

The user's historical interactions are represented as a vector.

For implicit feedback, an entry may indicate whether the user has watched or interacted with a particular movie.

**Stage 2: Introducing Artificial Corruption**

Some observed interactions are randomly removed or masked.

This produces a corrupted version of the user's interaction history.

**Stage 3: Encoding the Corrupted History**

The corrupted interaction vector is passed through the neural encoder.

The user embedding is incorporated to provide personalized information.

**Stage 4: Reconstructing the Original History**

The decoder attempts to recover the original interaction vector.

The model is trained to predict interactions that were deliberately removed during the corruption process.

**Stage 5: Predicting Unobserved Preferences**

After training, the model can produce scores for items that were not present in the user's observed interaction history.

These scores can be used to generate personalized recommendations.

### 4.4.5. Learning Individual and Collective Preference Patterns

The deliberate corruption process encourages CDAE to discover underlying patterns in user behavior.

These patterns may reflect two complementary sources of information.

**Individual Preferences**

The model can learn characteristics specific to individual users.

For example, a user may consistently prefer movies featuring a particular actor or belonging to a particular genre.

The user embedding helps represent such preferences.

**Collective Preferences**

The model can also learn patterns shared across many users.

For example, certain movies may frequently be watched together, or particular products may commonly appear in similar purchasing histories.

These shared patterns provide collaborative information that can help predict preferences for previously unseen items.

By combining individual user representations with patterns learned from corrupted interaction histories, CDAE can generate personalized recommendations even when the available interaction data is incomplete.

### 4.4.6. Comparison with Traditional Matrix Factorization

Traditional Matrix Factorization represents users and items through latent vectors and typically calculates their interaction using a dot product.

CDAE instead uses a neural reconstruction architecture that learns from corrupted interaction histories.

This provides several potential advantages:

- **Robustness to Missing Information:** The model is explicitly trained to reconstruct interaction patterns from incomplete inputs.
- **Personalization:** User embeddings introduce user-specific information into the learned representations.
- **Nonlinear Modeling:** Neural transformations can capture complex relationships among interactions.
- **Top-K Recommendation:** Reconstructed preference scores can be used to rank candidate items.
- **Collaborative Pattern Learning:** Training across many users allows the model to discover shared behavioral patterns.

These properties can help CDAE produce accurate and personalized recommendations.

However, superior performance over traditional matrix factorization is not guaranteed in every setting. Results depend on the dataset, sparsity level, corruption strategy, model architecture, and training procedure.
