This section examines another important deep learning architecture: **Recurrent Neural Networks (RNNs)**. We first review their structure, operating principles, and major variants, then explore how recurrent architectures can improve recommender systems by modeling temporal dependencies and evolving user preferences.

## 6.1. Overview of Recurrent Neural Networks

When reading a sentence, understanding a particular word often requires considering the words that precede it. The meaning of the current word depends not only on its individual characteristics but also on the context established by earlier words.

**Recurrent Neural Networks (RNNs)** are designed to process information in a similar manner.

RNNs are neural network architectures developed for **sequential data**, where the order of observations carries important information.

Examples include:

- **Natural language:** Words or tokens arranged in sentences.
- **Music:** Notes and acoustic patterns occurring over time.
- **Time series:** Measurements recorded at successive time intervals.
- **User interactions:** Sequences of clicks, purchases, searches, or item views.

Unlike conventional feedforward neural networks, RNNs maintain an internal state that allows information from previous observations to influence the processing of subsequent inputs.

### 6.1.1. Hidden States and Sequential Processing

At each time step $t$, an RNN receives two principal inputs:

1. The current observation, $\mathbf{x}_{t}$.
2. The hidden state from the previous time step, $\mathbf{h}_{t-1}$.

The network combines these inputs to calculate a new hidden state:

$$
\mathbf{h}_{t}=\phi(\mathbf{W}_{xh}\mathbf{x}_{t}+\mathbf{W}_{hh}\mathbf{h}_{t-1}+\mathbf{b}_{h})
$$

Where:

- $\mathbf{x}_{t}$ is the input vector at time $t$.
- $\mathbf{h}_{t-1}$ is the hidden state from the preceding time step.
- $\mathbf{h}_{t}$ is the updated hidden state.
- $\mathbf{W}_{xh}$ maps the current input into the hidden-state space.
- $\mathbf{W}_{hh}$ models the influence of the previous hidden state.
- $\mathbf{b}_{h}$ is a bias vector.
- $\phi$ is a nonlinear activation function.

The updated hidden state summarizes information from the current input and the preceding sequence.

For example, when processing the third word of a sentence, the network combines information about that word with the hidden state representing the first two words.

The hidden state therefore acts as a form of internal memory.

An output may then be generated from the current hidden state:

$$
\mathbf{y}_{t}=g(\mathbf{W}_{hy}\mathbf{h}_{t}+\mathbf{b}_{y})
$$

Where:

- $\mathbf{y}_{t}$ is the output at time $t$.
- $\mathbf{W}_{hy}$ is the output transformation matrix.
- $\mathbf{b}_{y}$ is the output bias.
- $g$ is an appropriate output activation function.

Depending on the task, the output may represent the next word in a sentence, the next observation in a time series, or the next item a user is likely to interact with.

### 6.1.2. Backpropagation Through Time

RNNs are trained using **Backpropagation Through Time (BPTT)**.

BPTT extends the conventional backpropagation algorithm to sequential models.

Conceptually, the recurrent network is unfolded across the time steps of the input sequence.

Although the same parameters are reused at every time step, the unfolded representation makes the dependencies between successive hidden states explicit.

During training, the loss gradients are propagated backward through the sequence.

This allows the model to determine how earlier hidden states and inputs contributed to later prediction errors.

The gradients are then used to update the shared network parameters.

### 6.1.3. Vanishing and Exploding Gradients

Traditional RNNs encounter significant difficulties when learning dependencies across long sequences.

Two particularly important problems are:

- **Vanishing Gradients**
- **Exploding Gradients**

These problems arise because gradient propagation through many time steps involves repeated multiplication by recurrent weight matrices and activation derivatives.

**Vanishing Gradients**

When the magnitudes of the relevant derivatives are repeatedly small, gradients can decrease exponentially as they propagate backward through time.

Consequently, the influence of earlier observations becomes increasingly difficult to learn.

For example, information introduced at the beginning of a long sentence may have little effect on parameter updates associated with predictions near the end.

This limits the ability of conventional RNNs to learn long-term dependencies.

**Exploding Gradients**

When repeated gradient transformations amplify their magnitudes, gradients can grow excessively large.

This may produce unstable parameter updates and interfere with optimization.

Gradient clipping is commonly used to mitigate exploding gradients.

However, addressing vanishing gradients requires architectural mechanisms that preserve information more effectively over long sequences.

One influential solution is the **Long Short-Term Memory (LSTM)** network.

### 6.1.4. Long Short-Term Memory Networks

**Long Short-Term Memory (LSTM)** networks were introduced to improve the ability of recurrent models to learn long-term dependencies.

LSTMs extend conventional RNNs by introducing a dedicated memory cell and several gating mechanisms.

The three principal gates are:

1. **Input Gate:** Controls which new information is written into the memory cell.
2. **Forget Gate:** Determines which previously stored information should be retained or discarded.
3. **Output Gate:** Controls which information from the memory cell contributes to the current hidden state.

These gates regulate the flow of information through the network.

The memory cell provides a pathway through which information can persist across multiple time steps, reducing the difficulties associated with vanishing gradients.

As a result, LSTMs can learn dependencies extending across substantially longer sequences than conventional RNNs in many applications.

For example, an LSTM processing a user's interaction history may retain information about earlier preferences while incorporating more recent behavior.

This is particularly valuable when recommendations depend on both historical interests and current user activity.

### 6.1.5. Gated Recurrent Units

The **Gated Recurrent Unit (GRU)** is a simplified gated recurrent architecture.

GRUs were developed to preserve many of the benefits of LSTMs while reducing architectural complexity.

Instead of maintaining separate input, forget, and output gates, a GRU primarily uses:

- **Update Gate:** Controls how much information from the previous hidden state is retained.
- **Reset Gate:** Controls how strongly previous information contributes when constructing the candidate hidden state.

Unlike LSTMs, GRUs do not maintain a separate cell state.

Their simpler structure generally requires fewer parameters for comparable hidden-state dimensions.

This can reduce computational requirements and training time.

GRUs frequently achieve performance competitive with LSTMs, although the relative effectiveness of the two architectures depends on the application and dataset.

### 6.1.6. Bidirectional Recurrent Neural Networks

A conventional RNN processes a sequence in a single direction, typically from the first observation to the last.

However, some tasks benefit from information appearing both before and after a particular observation.

**Bidirectional Recurrent Neural Networks (BiRNNs)** address this requirement by processing the sequence in two directions:

- Forward, from beginning to end.
- Backward, from end to beginning.

The resulting hidden representations are commonly concatenated:

$$
\mathbf{h}_{t}=[\overrightarrow{\mathbf{h}}_{t};\overleftarrow{\mathbf{h}}_{t}]
$$

Where:

- $\overrightarrow{\mathbf{h}}_{t}$ is the forward hidden state.
- $\overleftarrow{\mathbf{h}}_{t}$ is the backward hidden state.
- The semicolon denotes vector concatenation.

This allows the representation at each position to incorporate information from both earlier and later observations.

Bidirectional recurrent networks have been useful in natural language processing tasks such as:

- Named Entity Recognition (NER).
- Text classification.
- Sequence labeling.
- Contextual representation learning.

For example, recognizing a person's name in a sentence may require considering words that appear both before and after the name.

Bidirectional architectures are especially appropriate when the entire input sequence is available during prediction.

For real-time next-item recommendation, however, future interactions are not yet known. A bidirectional model must therefore be designed carefully to avoid using information that would be unavailable at prediction time.

### 6.1.7. Sequence-to-Sequence Architectures

RNNs have also played an important role in **Sequence-to-Sequence (Seq2Seq)** architectures.

A sequence-to-sequence model transforms an input sequence into an output sequence.

Examples include:

- Machine translation.
- Conversational systems and chatbots.
- Text summarization.
- Other sequence generation tasks.

Traditional sequence-to-sequence systems often used an encoder RNN to process the input sequence and a decoder RNN to generate the output sequence.

These architectures provided an important foundation for subsequent developments in neural sequence modeling.

### 6.1.8. Limitations of RNNs

Despite their capabilities, recurrent architectures have several limitations.

**Limited Parallelization**

The hidden state at time $t$ depends on the hidden state at time $t-1$.

Consequently, sequential computations cannot be fully parallelized across time steps in a conventional RNN.

This can make training relatively slow for long sequences.

**Difficulty with Very Long Sequences**

Although LSTMs and GRUs improve the modeling of long-term dependencies, processing extremely long sequences can remain computationally expensive and challenging.

**Sequential Computational Dependencies**

To process a long document or interaction history, the model generally needs to compute successive hidden states in order.

These limitations contributed to the development of **Attention Mechanisms** and, subsequently, the **Transformer** architecture.

Nevertheless, recurrent networks remain useful in applications involving moderate sequence lengths, streaming data, or limited computational resources.

Examples include certain real-time recommendation systems and time-series analysis applications.

By providing a systematic framework for modeling temporal dependencies, RNNs established an important foundation for later advances in deep learning.

The following sections examine two recommendation approaches that incorporate recurrent architectures.

## 6.2. Recurrent Coevolutionary Latent Feature Processes

Traditional collaborative filtering methods frequently represent users and items using latent vectors that remain fixed during prediction.

However, user preferences and item characteristics may change over time.

Every click, page view, purchase, or search provides additional information about evolving interests.

For example, a user's preferences may shift from casual clothing to formal clothing, while the popularity or perceived characteristics of products may also change as new interactions occur.

The **Recurrent Coevolutionary Latent Feature Processes (RCLFP)** model addresses this challenge by representing users and items as dynamically evolving entities.

Rather than treating user and item representations as static, the model learns how they change over continuous time.

### 6.2.1. Coevolution of Users and Items

The central idea of RCLFP is that user and item representations evolve together.

A new interaction can influence:

- The latent representation of the user.
- The latent representation of the item.

These changes may subsequently affect future interactions.

The model therefore treats user and item evolution as two interconnected processes.

For example, when a user interacts with a particular product, the interaction may provide new evidence about the user's preferences.

At the same time, the interaction may provide information about the product's appeal to a particular type of user.

RCLFP uses recurrent neural network mechanisms to capture three related phenomena:

- **Temporal Drift:** Changes associated with the passage of time.
- **Self-Evolution:** Changes associated with an entity's previous latent state.
- **Coevolution:** Changes caused by interactions between users and items.

These mechanisms allow the model to represent dynamic relationships rather than fixed user–item compatibility.

### 6.2.2. Latent Feature Embedding Update Processes

At the center of RCLFP are two latent feature processes:

1. A user latent feature process.
2. An item latent feature process.

Each user $u$ is associated with a time-dependent latent vector:

$$
\mathbf{U}_{u}(t)
$$

Each item $i$ is associated with a time-dependent latent vector:

$$
\mathbf{I}_{i}(t)
$$

These vectors represent the evolving characteristics of users and items.

Their values are updated when relevant interaction events occur.

Between interaction events, the stored latent representations remain unchanged under the event-driven update mechanism, although the model's temporal intensity function can still vary with time.

### 6.2.3. User Latent Feature Updates

Suppose user $u$ interacts with item $i_{k}$ at time $t_{k}^{u}$.

The user's latent representation is updated according to:

$$
\mathbf{U}_{u}(t_{k}^{u})=\sigma(\mathbf{W}_{1}(t_{k}^{u}-t_{k-1}^{u})+\mathbf{W}_{2}\mathbf{U}_{u}(t_{k-1}^{u})+\mathbf{W}_{3}\mathbf{I}_{i_{k}}((t_{k}^{u})^{-})+\mathbf{W}_{4}\mathbf{q}_{k}^{u,i_{k}})
$$

This equation contains four components.

**1. Temporal Drift**

$$
\mathbf{W}_{1}(t_{k}^{u}-t_{k-1}^{u})
$$

This component captures the influence of elapsed time since the user's previous interaction.

Where:

- $\mathbf{W}_{1}$ is a learnable parameter matrix or compatible linear transformation.
- $t_{k}^{u}$ is the time of the current interaction.
- $t_{k-1}^{u}$ is the time of the user's preceding interaction.

The elapsed time is:

$$
\Delta t_{u}=t_{k}^{u}-t_{k-1}^{u}
$$

This term allows the model to account for changes associated with the passage of time.

**2. Self-Evolution**

$$
\mathbf{W}_{2}\mathbf{U}_{u}(t_{k-1}^{u})
$$

This component incorporates the user's previous latent representation.

It allows the updated representation to preserve information about the user's historical preferences.

**3. Coevolution Through Item Features**

$$
\mathbf{W}_{3}\mathbf{I}_{i_{k}}((t_{k}^{u})^{-})
$$

This component incorporates the latent representation of the item involved in the current interaction.

The notation $(t_{k}^{u})^{-}$ indicates the instant immediately before the interaction occurs.

This ensures that the update uses the item's state before the current event modifies it.

The term captures how the interacting item's characteristics influence the user's evolving representation.

**4. Interaction Feature Evolution**

$$
\mathbf{W}_{4}\mathbf{q}_{k}^{u,i_{k}}
$$

Where:

- $\mathbf{W}_{4}$ maps interaction features into the latent representation space.
- $\mathbf{q}_{k}^{u,i_{k}}$ represents features associated with the interaction between user $u$ and item $i_{k}$.

These features may describe the type or characteristics of the observed interaction.

The nonlinear activation function $\sigma$ combines the four components to produce the updated user representation.

### 6.2.4. Item Latent Feature Updates

The item representation evolves through a corresponding process.

Suppose item $i$ interacts with user $u_{k}$ at time $t_{k}^{i}$.

The item latent vector is updated as follows:

$$
\mathbf{I}_{i}(t_{k}^{i})=\sigma(\mathbf{V}_{1}(t_{k}^{i}-t_{k-1}^{i})+\mathbf{V}_{2}\mathbf{I}_{i}(t_{k-1}^{i})+\mathbf{V}_{3}\mathbf{U}_{u_{k}}((t_{k}^{i})^{-})+\mathbf{V}_{4}\mathbf{q}_{k}^{i,u_{k}})
$$

Where:

- $\mathbf{V}_{1}$ models the influence of temporal drift.
- $t_{k}^{i}-t_{k-1}^{i}$ is the elapsed time between consecutive interactions involving item $i$.
- $\mathbf{V}_{2}$ models self-evolution.
- $\mathbf{I}_{i}(t_{k-1}^{i})$ is the item's latent representation at its previous interaction.
- $\mathbf{V}_{3}$ models coevolution through the interacting user's features.
- $\mathbf{U}_{u_{k}}((t_{k}^{i})^{-})$ is the user's latent representation immediately before the interaction.
- $\mathbf{V}_{4}$ maps interaction features into the item's latent space.
- $\mathbf{q}_{k}^{i,u_{k}}$ is the feature vector describing the interaction.
- $\sigma$ is a nonlinear activation function.
- $\mathbf{I}_{i}(t_{k}^{i})$ is the updated item representation.

The update equation mirrors the user update process.

Both users and items retain information from their previous states while incorporating information from their latest interactions.

The nonlinear activation function may be implemented using functions such as ReLU or sigmoid, depending on the architecture.

The notation $t^{-}$ consistently denotes the instant immediately preceding an interaction event.

Together, these update processes allow user and item representations to coevolve over time.

### 6.2.5. Modeling Interactions as Temporal Point Processes

RCLFP does not merely model which interactions are likely to occur.

It also attempts to model **when** those interactions will occur.

For this purpose, the model uses a **Temporal Point Process**.

A temporal point process is a probabilistic framework for modeling events that occur at irregular times.

Examples include:

- User clicks.
- Product purchases.
- Website visits.
- Customer returns.
- Interactions with recommended items.

The central quantity in a temporal point process is the **Intensity Function**.

The intensity function describes the instantaneous rate at which an event is expected to occur, conditional on the observed history.

For user $u$ and item $i$, the model defines:

$$
\lambda_{u,i}(t)=\exp(\eta_{u,i}+\mathbf{U}_{u}(t)^{\top}\mathbf{I}_{i}(t)+\alpha_{u,i}(t-t_{k}^{u}))
$$

Where:

- $\lambda_{u,i}(t)$ is the interaction intensity between user $u$ and item $i$ at time $t$.
- $\eta_{u,i}$ is a baseline intensity parameter.
- $\mathbf{U}_{u}(t)$ is the user's latent representation at time $t$.
- $\mathbf{I}_{i}(t)$ is the item's latent representation at time $t$.
- $\alpha_{u,i}$ controls the effect of elapsed time.
- $t-t_{k}^{u}$ is the time elapsed since the user's most recent interaction.
- $\exp$ is the exponential function.

The intensity function combines several sources of information.

**1. Baseline Intensity**

$$
\eta_{u,i}
$$

This term represents a relatively stable component of the user's tendency to interact with the item.

It can capture long-term preferences that are not fully explained by the current dynamic latent representations.

**2. Latent Feature Compatibility**

$$
\mathbf{U}_{u}(t)^{\top}\mathbf{I}_{i}(t)
$$

This term measures the compatibility between the user's and item's current latent representations.

A larger inner product increases the interaction intensity, assuming the remaining terms are unchanged.

Because the representations evolve over time, this compatibility can change as new interactions occur.

**3. Temporal Influence**

$$
\alpha_{u,i}(t-t_{k}^{u})
$$

This component captures how the time elapsed since the user's latest interaction affects the current interaction intensity.

Depending on the learned value of $\alpha_{u,i}$, elapsed time may increase or decrease the predicted intensity.

**4. Exponential Transformation**

The exponential function ensures that:

$$
\lambda_{u,i}(t)>0
$$

This is necessary because an intensity function must be nonnegative.

### 6.2.6. Predicting Future Interactions and Their Timing

By combining evolving latent representations with temporal point processes, RCLFP can model both:

- **Which item a user is likely to interact with next.**
- **When the next interaction is likely to occur.**

These are related but distinct prediction tasks.

A conventional recommendation model may assign a relevance score to each candidate item.

A temporal point process model additionally characterizes the timing of future events through its intensity function.

The intensity can be used to derive probabilities of future interactions over specified time intervals.

For example, the probability of observing no interaction for a particular user–item pair during an interval $(a,b]$, conditional on the relevant history, is associated with the integrated intensity:

$$
P(N_{u,i}(b)-N_{u,i}(a)=0)=\exp(-\int_{a}^{b}\lambda_{u,i}(s)\,ds)
$$

Here, $N_{u,i}(t)$ denotes the counting process for interactions between user $u$ and item $i$.

This relationship provides a connection between instantaneous interaction intensity and event probabilities over time.

The ability to model both interaction preferences and event timing is valuable in applications such as:

- Personalized advertising.
- Customer return prediction.
- Recommendation timing.
- User engagement forecasting.
- Dynamic content recommendation.

### 6.2.7. Example: Input Data and Latent-State Updates

Consider a user interacting with several products over time.

| Time | User | Item | Interaction |
|---|---|---|---|
| $t_{1}$ | User A | Item X | View |
| $t_{2}$ | User A | Item Y | Click |
| $t_{3}$ | User B | Item X | Purchase |
| $t_{4}$ | User A | Item X | Purchase |

At $t_{1}$, the interaction between User A and Item X updates both their latent representations.

At $t_{2}$, User A's representation is updated again using the current representation of Item Y, the user's previous latent state, the elapsed time, and the interaction features.

At $t_{3}$, User B interacts with Item X.

This event updates Item X's representation, potentially changing its compatibility with other users.

Consequently, when User A interacts with Item X again at $t_{4}$, the item's representation may differ from its representation at $t_{1}$.

This illustrates the central concept of coevolution: user and item representations change through interactions, and those changes influence subsequent interactions.

## 6.3. A GRU-Based Recommendation Approach

Another application of recurrent neural networks in recommender systems involves using **Gated Recurrent Units (GRUs)** to learn item representations from textual information.

The approach introduced in *Ask the GRU: Multi-Task Learning for Deep Text Recommendations* combines neural text encoding with latent-factor recommendation models.

Its objective is to use textual descriptions and related content to learn meaningful representations of items, particularly when interaction data is limited.

### 6.3.1. Learning Item Representations from Text

Many recommendation platforms contain substantial textual information about their items.

Examples include:

- Product descriptions.
- User reviews.
- Book summaries.
- Movie descriptions.
- Item metadata.

Such information can reveal semantic characteristics that may not be evident from user–item interaction data alone.

The GRU-based approach processes each item's textual sequence and transforms it into a dense embedding vector.

The resulting embedding represents semantic information extracted from the text.

For example, a movie description may contain information about:

- Genre.
- Plot.
- Themes.
- Characters.
- Narrative structure.

A GRU can process the sequence of words and learn a representation reflecting these characteristics.

### 6.3.2. Integrating GRU Embeddings with Latent-Factor Models

After encoding an item's textual information, the resulting embedding is incorporated into a latent-factor recommendation framework.

This allows the recommendation model to combine:

1. Collaborative information from observed user–item interactions.
2. Semantic information extracted from item text.

The combination is useful because these information sources provide complementary signals.

Collaborative interactions reveal patterns in user behavior.

Textual representations describe item characteristics even when the item has received relatively few interactions.

The GRU encoder therefore acts as a mechanism for transforming unstructured text into numerical features suitable for recommendation.

### 6.3.3. Addressing Warm-Start and Cold-Start Recommendation

The GRU-based approach can benefit both warm-start and cold-start recommendation settings.

**Warm-Start Recommendation**

In a warm-start setting, an item already has a substantial interaction history.

The recommendation model can use both collaborative information and textual features to improve preference estimation.

For example, a popular book may have many ratings as well as a detailed description and numerous reviews.

The combination of these signals can produce a richer item representation.

**Cold-Start Recommendation**

In a cold-start setting, an item has few or no recorded interactions.

Traditional collaborative filtering methods may struggle because there is insufficient behavioral information to learn a reliable item embedding.

A GRU-based text encoder can generate a meaningful representation from the item's description or other available textual content.

This allows the recommendation system to estimate item relevance even when interaction data is scarce.

The approach therefore reduces dependence on dense user–item interaction histories.

### 6.3.4. Multi-Task Learning for Regularization

A major challenge in text-based recommendation is overfitting.

This can occur when the model has access to large amounts of textual information but relatively few labeled user–item interactions.

To address this problem, the proposed approach uses **Multi-Task Learning**.

Multi-task learning trains a model on multiple related objectives simultaneously.

In this case, the model combines:

1. A primary recommendation task.
2. An auxiliary item metadata prediction task.

**Primary Task: Rating Prediction**

The main objective is to predict user ratings or preferences for items.

The model learns item representations that are useful for recommendation.

**Auxiliary Task: Metadata Prediction**

The auxiliary objective predicts item metadata, such as:

- Categories.
- Tags.
- Genres.

This task encourages the text encoder to learn semantic features that reflect meaningful item characteristics.

### 6.3.5. Benefits of Joint Learning

Training the recommendation and metadata prediction tasks together provides additional supervision for the shared text representation.

The auxiliary task acts as a regularization mechanism.

Instead of learning representations that are useful only for fitting the observed rating data, the model is encouraged to capture broader semantic characteristics of items.

This can improve generalization when rating observations are sparse.

The approach offers several potential advantages:

- **Improved Representation Learning:** Item embeddings incorporate semantic information from text.
- **Reduced Overfitting:** Auxiliary metadata prediction provides an additional training signal.
- **Better Cold-Start Performance:** Textual information can support recommendations for new or rarely interacted-with items.
- **Improved Warm-Start Performance:** Semantic and collaborative information can complement one another.
- **Greater Robustness to Sparsity:** The model relies less exclusively on the observed rating matrix.

By combining GRU-based sequence encoding, latent-factor recommendation, and multi-task learning, the architecture provides a framework for incorporating textual information into collaborative recommendation.
