## Introduction to Graph Neural Networks

In the preceding sections, we explored the fundamental concepts of graphs, the importance of relationships in data, and graph embedding techniques such as **Node2Vec**, which generate low-dimensional representations of entities.

However, traditional graph embedding methods generally do not explicitly exploit the detailed local neighborhood structure of a graph when learning representations.

This limitation motivates the development of **Graph Neural Networks (GNNs)**, a family of machine learning models specifically designed to process graph-structured data.

## The Core Idea of GNNs: Message Passing

The fundamental mechanism underlying most modern GNN architectures is **Message Passing**, also known as **Neighborhood Aggregation**.

The central idea is straightforward but powerful:

- Each node updates its embedding, or hidden state, by combining its own representation from the previous GNN layer with information obtained from its neighboring nodes.
- This process is repeated across multiple layers, enabling each node to collect information from increasingly distant parts of the graph.

Consequently, as the number of layers increases, the receptive field of each node expands, allowing its representation to incorporate information from a larger portion of the graph.

### General Operations in a GNN Layer

The computation performed by a typical GNN layer for a node $v$ can be divided into two main stages.

### 1. Message Aggregation

Each node $v$ receives messages from its neighbors, denoted by $u \in N(v)$, where $N(v)$ represents the set of neighboring nodes.

These messages are generally constructed from the embeddings of neighboring nodes in the preceding layer.

The received messages are combined using an **aggregation function**, such as:

- **Mean aggregation:** Computes the average of neighboring node representations.
- **Sum aggregation:** Adds the representations of neighboring nodes.
- **Maximum aggregation:** Selects the maximum value independently for each embedding dimension.

An essential property of the aggregation function is **permutation invariance**. Because graph neighbors have no inherent ordering, changing the order in which their representations are processed must not change the aggregation result.

Mathematically, message aggregation at layer $l$ is expressed as:

$$
m_{N(v)}^{(l)} = AGGREGATE^{(l)}\left(\left\{h_{u}^{(l-1)} \mid u \in N(v)\right\}\right)
$$

### 2. Node Embedding Update

After aggregating information from its neighbors, node $v$ updates its representation by combining:

1. Its own embedding from the preceding layer.
2. The aggregated message received from its neighborhood.

This operation is performed using an **update function**, which may incorporate learnable linear transformations and nonlinear activation functions.

The general update rule is:

$$
h_{v}^{(l)} = UPDATE^{(l)}\left(h_{v}^{(l-1)},m_{N(v)}^{(l)}\right)
$$

### Mathematical Notation

| Symbol | Description |
|---|---|
| $h_{u}^{(l-1)}$ | Embedding of node $u$ at layer $l-1$. |
| $N(v)$ | Set of neighboring nodes of node $v$. |
| $m_{N(v)}^{(l)}$ | Aggregated neighborhood message for node $v$ at layer $l$. |
| $AGGREGATE^{(l)}$ | Aggregation function used at layer $l$, such as mean or sum. |
| $UPDATE^{(l)}$ | Node representation update function at layer $l$. |
| $h_{v}^{(l)}$ | Updated embedding of node $v$ at layer $l$. |

### Understanding Multi-Layer Message Passing

Consider a graph containing users and items, where edges represent observed interactions.

In the first GNN layer, a user receives information directly from the items with which they have interacted.

In the second layer, information from other users who interacted with those items can indirectly influence the original user's embedding.

With additional layers, the model can incorporate increasingly distant relationships.

This mechanism enables GNNs to capture **higher-order connectivity patterns**, which are difficult to represent using only direct user–item interactions.

For example, two users who have never interacted with the same item may still exhibit related preferences through multi-hop paths in the interaction graph.

## Importance of GNNs in Recommender Systems

Graph Neural Networks are particularly well suited to recommendation tasks because they naturally operate on the relational structures underlying user–item interactions.

### 1. Explicit Modeling of Relationships

GNNs can directly process the structure of a user–item interaction graph.

Unlike random-walk-based graph embedding methods such as Node2Vec, they do not require converting graph connectivity into sampled node sequences before representation learning.

Instead, neighborhood information is incorporated directly into the model's computational architecture.

### 2. Rich Information Propagation

Message passing enables information about users, items, and their interactions to propagate throughout the graph.

By repeatedly aggregating neighborhood information, GNNs automatically learn representations that encode both direct and indirect relationships.

This capability is particularly valuable when user preferences depend on complex patterns of interaction.

However, increasing the depth of a GNN also introduces potential limitations.

One important challenge is **oversmoothing**.

Oversmoothing occurs when repeated neighborhood aggregation causes the embeddings of different nodes to become increasingly similar.

As a result, the model may lose the ability to distinguish nodes with different characteristics or preferences.

Thus, adding more GNN layers does not necessarily improve recommendation quality.

### 3. Addressing Cold Start and Data Sparsity

Recommender systems frequently suffer from sparse interaction data, where many users and items have only a limited number of recorded interactions.

Through message passing, nodes with relatively few interactions can benefit from information associated with their neighbors.

For example, an item with only a small number of interactions may obtain a more informative representation by aggregating embeddings from users who have interacted with it.

Similarly, a user with limited interaction history may benefit from information propagated through related items and other users.

This mechanism can help alleviate **data sparsity** and certain **cold-start scenarios**.

However, graph-based propagation generally requires at least some connectivity or additional information. A completely isolated new user or item cannot benefit from interaction-based message passing alone.

## Neural Graph Collaborative Filtering (NGCF)

**Neural Graph Collaborative Filtering (NGCF)** was among the earliest influential approaches to explicitly incorporate graph neural network mechanisms into collaborative filtering.

Rather than treating user–item interactions merely as entries in a matrix, NGCF models them as a graph and learns user and item representations through repeated information propagation along observed interaction edges.

The central objective is to enrich user and item embeddings by incorporating the relational information contained in the interaction graph.

### Motivation Behind NGCF

Traditional recommendation approaches, including **Matrix Factorization**, typically learn latent representations from observed user–item interactions.

Although these methods can capture important collaborative patterns, they do not explicitly model the propagation of information along multi-hop paths in the interaction graph.

Consequently, higher-order relationships may not be fully exploited.

NGCF was developed to address this limitation.

Its main objective is to enhance user and item embeddings by propagating information across the interaction graph, thereby incorporating hidden and indirect relationships into the learned representations.

A defining feature of NGCF is its emphasis on designing an effective **embedding propagation rule** specifically for collaborative filtering.

### How NGCF Works

NGCF builds on the message-passing mechanism introduced earlier.

Information associated with users and items is transmitted through the edges of the interaction graph, where each edge represents an observed interaction.

The model operates through several stages.

### 1. Initial Embeddings

Each user $u$ and each item $i$ is assigned an initial embedding vector.

These embeddings act as learnable latent representations of users and items.

Unlike manually engineered features, the initial embeddings are optimized during model training.

They provide the starting point for subsequent graph propagation operations.

### 2. Information Propagation Through the Graph

NGCF employs multiple embedding propagation layers to progressively refine user and item representations.

At each layer, a node updates its embedding by combining information from:

- Its own representation at the preceding layer.
- The representations of its directly connected neighbors.

For example, the embedding of user $u$ at layer $l+1$ is computed using the user's embedding at layer $l$ and the embeddings of items with which the user has interacted.

Similarly, an item's embedding is updated using information from the users connected to that item.

A distinctive characteristic of NGCF is that it does more than simply aggregate neighboring embeddings.

It also explicitly models interactions between the central node's embedding and its neighbors' embeddings through **element-wise multiplication**.

This allows the propagated information to reflect interactions between the latent characteristics of connected nodes.

### NGCF Embedding Propagation Rule

For a user $u$, a representative NGCF propagation rule is:

$$
e_{u}^{(l+1)} = \sigma\left(W_{1}e_{u}^{(l)}+\sum_{i \in N_{u}}\frac{1}{\sqrt{|N_{u}||N_{i}|}}\left(W_{2}e_{i}^{(l)}+W_{3}\left(e_{u}^{(l)}\odot e_{i}^{(l)}\right)\right)\right)
$$

Here:

| Symbol | Description |
|---|---|
| $e_{u}^{(l)}$ | Embedding of user $u$ at layer $l$. |
| $e_{i}^{(l)}$ | Embedding of item $i$ at layer $l$. |
| $N_{u}$ | Set of items with which user $u$ has interacted. |
| $N_{i}$ | Set of users who have interacted with item $i$. |
| $W_{1},W_{2},W_{3}$ | Learnable weight matrices. |
| $\odot$ | Element-wise multiplication operator. |
| $\sigma$ | Nonlinear activation function, such as LeakyReLU. |

The normalization factor

$$
\frac{1}{\sqrt{|N_{u}||N_{i}|}}
$$

accounts for the degrees of the connected user and item nodes, preventing high-degree nodes from disproportionately dominating the aggregation process.

The element-wise interaction term

$$
e_{u}^{(l)}\odot e_{i}^{(l)}
$$

captures relationships between corresponding latent dimensions of the user and item embeddings.

This term allows NGCF to model more complex interactions than simple neighborhood averaging.

### 3. Multi-Layer Embedding Aggregation

After propagating information through multiple layers, NGCF combines the embeddings produced at different depths to construct the final representation of each node.

This operation is known as **Embedding Aggregation**.

Possible aggregation strategies include concatenating or summing embeddings from different layers.

In the standard NGCF architecture, embeddings from the initial layer and subsequent propagation layers are concatenated.

Combining multiple layers allows the final representation to preserve information from different neighborhood ranges.

For example:

- Initial embeddings contain the directly learned latent characteristics of users and items.
- Shallow propagation layers incorporate local neighborhood information.
- Deeper layers incorporate higher-order relationships involving more distant nodes.

Thus, multi-layer aggregation produces representations that capture information at multiple structural scales.

### 4. Interaction Prediction

Once the final user and item embeddings have been constructed, NGCF estimates a user's preference for an item using their inner product.

The prediction function is:

$$
\hat{r}_{ui}=e_{u}^{T}e_{i}
$$

where:

- $\hat{r}_{ui}$ is the predicted preference score of user $u$ for item $i$.
- $e_{u}$ is the final embedding of user $u$.
- $e_{i}$ is the final embedding of item $i$.
- $e_{u}^{T}e_{i}$ denotes the inner product between the two embeddings.

A larger predicted score generally indicates a stronger estimated preference or likelihood of interaction.

The resulting scores can be used to rank candidate items for recommendation.

### Higher-Order Connectivity in NGCF

Higher-order connectivity refers to relationships that emerge through paths containing multiple edges.

In a user–item bipartite graph, a direct interaction corresponds to a first-order connection between a user and an item.

A path involving a user, an item, and another user captures a second-order relationship.

Longer paths can reveal additional collaborative patterns.

By stacking propagation layers, NGCF allows these higher-order relationships to influence the learned embeddings.

This provides a mechanism for capturing collaborative signals beyond directly observed interactions.

### Advantages of NGCF

**1. Modeling Higher-Order Relationships**

One of NGCF's primary strengths is its ability to explicitly propagate information across the interaction graph.

This allows the model to discover complex collaborative patterns that extend beyond direct user–item interactions.

For example, preferences may be related through other users and items even when no direct interaction exists between the entities being compared.

**2. Improved Recommendation Accuracy**

By learning richer and more context-aware user and item representations, NGCF can achieve more accurate recommendations than traditional approaches in suitable experimental settings.

Its graph propagation mechanism incorporates additional structural information that conventional latent factor models may not explicitly capture.

**3. Effective Information Transfer**

Message passing enables useful information to reach users and items with relatively few recorded interactions.

This can improve representation quality in sparse datasets and help mitigate certain cold-start difficulties.

NGCF also established an important foundation for subsequent graph-based recommendation models by demonstrating how graph structure could be incorporated directly into collaborative filtering.

## Light Graph Convolutional Network (LightGCN)

**Light Graph Convolutional Network (LightGCN)** introduces a minimalist yet highly effective approach to graph-based collaborative filtering.

As discussed previously, the fundamental mechanism of graph neural networks is the propagation of information between connected nodes.

LightGCN builds on this principle but significantly simplifies the graph convolution process.

Its central idea is that, for collaborative filtering, Graph Convolutional Networks can be simplified substantially without sacrificing recommendation quality. In some cases, removing unnecessary architectural components can even improve performance.

### Motivation Behind LightGCN

Earlier GCN-based recommendation models, including NGCF, successfully exploited graph structure to learn user and item representations.

However, these architectures often included operations such as:

- **Feature Transformation:** Learnable linear transformations that modify node embeddings.
- **Nonlinear Activation Functions:** Functions applied after transformations to introduce nonlinearity into the learned representations.

Although these components are important in many graph learning applications, research has demonstrated that they are not necessarily beneficial for collaborative filtering.

In recommendation tasks, such operations may introduce unnecessary complexity and can sometimes degrade performance.

LightGCN addresses this issue by removing feature transformations and nonlinear activation functions from the graph propagation process.

The underlying hypothesis is that the primary benefit of graph convolution for collaborative filtering comes from **neighborhood aggregation**, rather than from complex nonlinear transformations.

Therefore, LightGCN concentrates on the most important source of information available in collaborative filtering: the interaction structure connecting users and items.

### How LightGCN Works

LightGCN learns user and item embeddings through three main stages.

### 1. Constructing the Interaction Graph

As in other graph-based recommendation approaches, LightGCN constructs a **bipartite user–item graph**.

The graph contains two distinct types of nodes:

- **User nodes:** Represent users of the recommendation system.
- **Item nodes:** Represent products, movies, books, or other recommendable entities.

Edges represent observed interactions, such as ratings, purchases, or other forms of user engagement.

Because the graph is bipartite, edges connect users to items rather than connecting two users or two items directly.

This graph serves as the structural foundation for embedding propagation.

### 2. Simplified Embedding Propagation

At each LightGCN layer, node embeddings are updated through a simple linear aggregation of neighboring embeddings.

Unlike more complex GNN architectures, LightGCN does not apply learnable feature transformation matrices or nonlinear activation functions during propagation.

Instead, information is transmitted through normalized neighborhood aggregation.

For a user $u$, the propagation rule can be written as:

$$
e_{u}^{(l+1)}=\sum_{i\in N_{u}}\frac{1}{\sqrt{|N_{u}||N_{i}|}}e_{i}^{(l)}
$$

$$

$$

- $e_{u}^{(l)}$ represents the embedding of user $u$ at layer $l$.
- $e_{i}^{(l)}$ represents the embedding of item $i$ at layer $l$.
- $N_{u}$ denotes the set of items connected to user $u$.
- $N_{i}$ denotes the set of users connected to item $i$.
