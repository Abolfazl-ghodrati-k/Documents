# Practical Implementation: From Preparation to Execution (Part Three)

In the previous section, we developed and evaluated a **Content-Based Filtering (CBF)** model using movie genre features and user-specific Lasso regression.

We now continue the project by implementing a **Collaborative Filtering (CF)** model, combining its predictions with those of the content-based model, and evaluating the resulting hybrid recommender system.

# Phase 4: Collaborative Filtering

In this phase, we implement a collaborative filtering model using the **K-Nearest Neighbors (KNN)** algorithm.

The objective is to complement the content-based model by identifying similarities between users and using those similarities to predict movie ratings.

We adopt **User-Based Collaborative Filtering**, which relies exclusively on historical user–movie ratings.

Unlike the content-based model, this approach does not directly use demographic attributes, such as age or gender, or movie attributes, such as genres.

Instead, it assumes that users with similar historical rating patterns are likely to assign similar ratings to other movies.

## How User-Based Collaborative Filtering Works

In user-based collaborative filtering, the predicted rating of user $u$ for movie $i$ is estimated from the ratings assigned to that movie by users whose preferences are similar to those of user $u$.

These similar users are called **nearest neighbors**.

The procedure consists of three main operations:

1. Measure similarities between users using their historical ratings.
2. Identify the $K$ most similar users who have rated the target movie.
3. Aggregate their ratings to estimate the target user's rating.

For this project, we use the **Pearson Correlation Coefficient** to measure similarity between users.

Pearson correlation captures relationships between users' rating patterns while reducing the influence of differences in their average rating tendencies.

For example, one user may consistently assign ratings between 4 and 5, while another may generally assign ratings between 3 and 4.

Although their absolute ratings differ, their relative preferences may be similar.

Pearson correlation can help identify such relationships.

### Converting Similarity into Distance

After calculating the Pearson correlation between two users, we convert it into a distance-like measure:

$$
d(u,v)=1-\rho(u,v)
$$

Where:

- $d(u,v)$ is the Pearson-based distance between users $u$ and $v$.
- $\rho(u,v)$ is their Pearson correlation coefficient.

Because Pearson correlation lies between $-1$ and $1$, the resulting distance values lie between 0 and 2.

A smaller distance indicates greater positive correlation.

A larger distance indicates weaker or negative correlation.

For example:

| Pearson Correlation | Pearson Distance | Interpretation |
|---:|---:|---|
| 1.0 | 0.0 | Perfect positive correlation |
| 0.8 | 0.2 | Strong positive correlation |
| 0.0 | 1.0 | No linear correlation |
| -0.5 | 1.5 | Negative correlation |
| -1.0 | 2.0 | Perfect negative correlation |

The model selects neighbors according to these distances.

### Weighted Neighbor Aggregation

Once the nearest neighbors have been selected, the model predicts the target rating using a weighted average of their observed ratings.

The weights are based on inverse distance, so users with smaller distances contribute more strongly.

For a target user $u$ and movie $i$, the prediction can be expressed as:

$$
\hat{R}_{u,i}=\frac{\sum_{v\in N_K(u,i)}w_{u,v}R_{v,i}}{\sum_{v\in N_K(u,i)}w_{u,v}}
$$

Where:

- $\hat{R}_{u,i}$ is the predicted rating of user $u$ for movie $i$.
- $N_K(u,i)$ is the set of up to $K$ selected neighbors who rated movie $i$.
- $R_{v,i}$ is the observed rating assigned by neighbor $v$ to movie $i$.
- $w_{u,v}$ is the weight assigned to neighbor $v$.

Using inverse-distance weighting:

$$
w_{u,v}=\frac{1}{d(u,v)+\epsilon}
$$

Where $\epsilon$ is a small positive constant introduced to avoid division by zero.

This weighting strategy gives greater influence to users with more similar rating patterns.

Although the implementation uses weighted raw ratings, another common user-based collaborative filtering approach predicts deviations from user mean ratings. Mean-centered prediction can further account for systematic differences in rating behavior.

> **KNN in Collaborative Filtering Versus General Machine Learning**
>
> KNN is also widely used for classification and regression.
>
> In conventional KNN classification, predictions are often generated using majority voting among neighboring observations.
>
> In KNN regression, predictions are typically generated using the mean or weighted mean of neighboring target values.
>
> User-based collaborative filtering follows the same nearest-neighbor principle, but neighbors represent users rather than ordinary training observations.
>
> Similarity is calculated from historical interaction patterns, and predictions are generated by aggregating the ratings assigned by similar users to the target item.
>
> Therefore, the underlying nearest-neighbor concept remains the same, although the representation, similarity measure, and prediction procedure are specialized for recommendation.

## Selecting the Number of Neighbors

The parameter $K$ determines how many similar users contribute to each prediction.

Choosing an appropriate value is important because it affects predictive accuracy, computational cost, and the stability of recommendations.

The MovieLens dataset used in this project contains approximately 6,000 users and 4,000 movies.

For a dataset of this size, relatively large neighborhood sizes, such as 30 to 100, may provide useful predictions by incorporating ratings from more users.

However, the optimal value depends on the interaction distribution and the quality of user similarities.

### Small Neighborhoods

When $K$ is small, predictions depend on a limited number of highly similar users.

This may improve personalization when those neighbors provide reliable evidence.

However, small neighborhoods can produce unstable predictions when very few similar users have rated the target movie.

### Large Neighborhoods

Increasing $K$ allows more users to contribute to each prediction.

This can reduce variance and improve prediction stability.

However, excessively large neighborhoods may include weakly related users, reducing personalization.

In extreme cases, predictions may approach general average ratings and become similar to those produced by a baseline model.

Larger neighborhoods may also increase computational requirements.

### Why Use Weighted Averages?

A simple arithmetic average treats all selected neighbors equally.

In contrast, inverse-distance weighting assigns greater importance to users with smaller distances.

This reduces the influence of weakly similar neighbors and can improve predictions when neighborhood sizes are relatively large.

Nevertheless, the relationship between neighborhood size and predictive accuracy must be established experimentally.

In this project, we use:

$$
K=40
$$

The resulting collaborative filtering model will provide an additional source of predictions for the hybrid system.

- `FilmID`: Movie identifier.
- `Tidstempel`: Rating timestamp.
- `Rangering`: Observed rating.

For collaborative filtering, the essential columns are the user identifier, movie identifier, and rating.

The timestamp is not directly used in this implementation.

### Constructing the User–Item Matrix

We transform the training data into a two-dimensional matrix using Pandas' `pivot()` method.

```python
user_matrix = train_df.pivot(index='BrukerID', columns='FilmID', values='Rangering')
```

The resulting matrix contains:

- Users as rows.
- Movies as columns.
- Observed ratings as matrix entries.

Mathematically:

$$
R\in\mathbb{R}^{m\times n}
$$

Where $m$ is the number of users and $n$ is the number of movies.

An observed entry $R_{u,i}$ represents the rating assigned by user $u$ to movie $i$.

Because users rate only a small fraction of available movies, most user–movie pairs have no observed rating.

Pandas represents these missing entries using `NaN`.

This is a direct consequence of the sparsity of the user–item interaction matrix.

### Mean-Centering User Ratings

Users may have different rating tendencies.

For example, one user may frequently assign high ratings, while another may use the lower end of the rating scale more often.

To reduce the influence of these systematic differences, we subtract each user's average rating from their observed ratings.

```python
user_matrix = user_matrix.sub(user_matrix.mean(axis=1), axis=0)
```

For user $u$, the mean observed rating is:

$$
\bar{R}_{u}=\frac{1}{|I_u|}\sum_{i\in I_u}R_{u,i}
$$

Where $I_u$ is the set of movies rated by user $u$.

The mean-centered rating is:

$$
R'_{u,i}=R_{u,i}-\bar{R}_{u}
$$

A positive centered value indicates that the user rated the movie above their personal average.

A negative centered value indicates that the user rated it below their personal average.

For example, suppose a user assigned the following ratings:

```text
[5, 4, 3]
```

The mean rating is:

$$
\bar{R}_{u}=\frac{5+4+3}{3}=4
$$

The centered ratings are:

```text
[1, 0, -1]
```

Mean-centering makes relative preferences more visible by reducing differences in users' overall rating levels.

### Handling Missing Values

After mean-centering, the matrix still contains missing values.

The implementation replaces these values with zero:

```python
user_matrix = user_matrix.fillna(0.0)
```

In the resulting matrix:

- Positive values represent ratings above the user's mean.
- Negative values represent ratings below the user's mean.
- Zero values may represent ratings equal to the user's mean or interactions that were originally missing.

This last distinction is important.

**A zero-filled missing entry does not represent an actual observed rating.**

It is a computational placeholder that allows subsequent matrix operations to proceed.

However, replacing missing interactions with zeros affects how similarities are calculated.

In particular, the implementation computes correlations over the complete zero-filled vectors rather than exclusively over movies rated by both users.

This differs from the conventional co-rated-item Pearson similarity formulation.

The distinction should be considered when interpreting the resulting distance matrix.

## Pearson Correlation Between Users

The Pearson correlation coefficient measures the strength and direction of the linear relationship between two sets of numerical observations.

In collaborative filtering, it can be used to compare users' rating patterns.

### Mathematical Definition

Suppose users $u$ and $v$ have both rated $n$ common movies.

Let their ratings for those movies be:

$$
u_1,u_2,\ldots,u_n
$$

and:

$$
v_1,v_2,\ldots,v_n
$$

The average rating for each user over the commonly rated movies is:

$$
\bar{u}=\frac{1}{n}\sum_{i=1}^{n}u_i
$$

$$
\bar{v}=\frac{1}{n}\sum_{i=1}^{n}v_i
$$

The Pearson correlation coefficient is:

$$
\rho(u,v)=\frac{\sum_{i=1}^{n}(u_i-\bar{u})(v_i-\bar{v})}{\sqrt{\sum_{i=1}^{n}(u_i-\bar{u})^{2}}\sqrt{\sum_{i=1}^{n}(v_i-\bar{v})^{2}}}
$$

The numerator measures how the deviations of the two users' ratings vary together.

The denominator normalizes this quantity using the magnitude of each user's rating deviations.

The resulting correlation lies within:

$$
-1\le\rho(u,v)\le1
$$

The interpretation is:

- Values close to 1 indicate strong positive correlation.
- Values close to 0 indicate weak or no linear correlation.
- Values close to -1 indicate strong negative correlation.

If either user's ratings have zero variance, the Pearson correlation is undefined without an additional handling rule.

### Constructing the Distance Matrix

The implementation calculates user correlations using Pandas and subtracts them from 1.

```python
# I calculate the Pearson Correlation between each user,
# and subtract this from 1 to get the Pearson Distance between users
user_dist_matrix = 1 - user_matrix.T.corr()
user_dist_matrix
```

The transpose operation:

```python
user_matrix.T
```

places users in columns and movies in rows.

The `.corr()` method then computes pairwise correlations between user columns.

Subtracting the correlations from 1 converts them into Pearson-based distances.

The resulting matrix is:

$$
D\in\mathbb{R}^{m\times m}
$$

Where:

$$
D_{u,v}=1-\rho(u,v)
$$

Each entry represents the distance between two users.

A portion of the resulting matrix is shown below.


For example, the distance between users 0 and 3 is approximately:

$$
D_{0,3}=0.870659
$$

The corresponding correlation is:

$$
\rho(0,3)=1-0.870659=0.129341
$$

This represents a weak positive correlation.

Similarly, the distance between users 0 and 1 is approximately:

$$
D_{0,1}=1.008851
$$

The corresponding correlation is:

$$
\rho(0,1)=1-1.008851=-0.008851
$$

This indicates a very weak negative correlation.

The diagonal entries are zero because each nonconstant user rating vector is perfectly correlated with itself.

### Interpretation and Limitations

The distance matrix provides the foundation for neighborhood selection.

For each target user, we can retrieve the distances to other users and select those with the smallest values.

However, several limitations should be recognized.

First, the zero-filled matrix contains missing interactions represented as zeros.

Consequently, the computed correlations may differ from correlations calculated exclusively over co-rated movies.

Second, the distance transformation $1-\rho$ is useful for ranking similarities, but it is not necessarily a mathematical metric satisfying all metric-space properties.

Third, correlations estimated from very few shared interactions may be unreliable.

A production implementation may therefore incorporate minimum overlap requirements, similarity shrinkage, or alternative similarity measures.

Nevertheless, the constructed distance matrix provides a practical foundation for the KNN-based collaborative filtering model developed next.

## 4.2 Designing the Collaborative Filtering Model

The next step is to use the user distance matrix to predict ratings in the validation set.

For each validation observation, the model identifies users who rated the target movie, selects the nearest neighbors, and calculates a weighted average of their ratings.

The prediction procedure is implemented using a loop over validation observations.

### 4.2.1 Preparing to Store Predictions

The original implementation follows the structure below, with the formatting and indexing corrected to ensure that the neighbor ratings and weights are aligned.

```python
# Part 1
CF_predictions = []

# Part 2
for index, row in X_val.iterrows():
    # Part 3
    if row["FilmID"] in X_train["FilmID"].unique():
        # Part 4
        users_rated_movie = X_train.loc[
            X_train['FilmID'] == row['FilmID'], 'BrukerID'
        ]

        # Part 5
        users_sorted = user_dist_matrix.loc[
            row['BrukerID'], users_rated_movie
        ].sort_values()

        # Part 6
        n_neighbours = users_sorted[:40]

        # Part 7
        nn_data = train_df.loc[
            (train_df['BrukerID'].isin(n_neighbours.index.to_list())) &
            (train_df['FilmID'] == row['FilmID'])
        ]

        weights = 1 / n_neighbours.loc[nn_data['BrukerID']].to_numpy()
        nearest_neighbours_avg_rating = np.average(
            nn_data['Rangering'],
            weights=weights
        )

        CF_predictions.append(nearest_neighbours_avg_rating)
    else:
        CF_predictions.append(train_df["Rangering"].mean())
```

The procedure can be understood through the following stages.

### Part 1: Initialize Prediction Storage

We create an empty list:

```python
CF_predictions = []
```

This list will store the predicted ratings for the validation observations.

Each prediction corresponds to a user–movie pair in `X_val`.

The order of predictions must match the order of validation observations so that the predictions can later be compared with `y_val`.

### Part 2: Iterate Through Validation Observations

The loop:

```python
for index, row in X_val.iterrows():
```

processes each validation observation individually.

Each row contains information identifying the target user and movie.

The objective is to estimate the rating that the specified user would assign to the specified movie.

### Part 3: Check Whether the Movie Exists in Training

The condition:

```python
if row["FilmID"] in X_train["FilmID"].unique():
```

checks whether the target movie appears in the training dataset.

If the movie has at least one training rating, collaborative filtering can potentially estimate the target rating using other users' observations.

If the movie is absent from training, no historical ratings are available for that item.

This represents an item cold-start situation for the collaborative component.

### Part 4: Identify Users Who Rated the Movie

For a movie that appears in training, we retrieve the identifiers of users who rated it.

```python
users_rated_movie = X_train.loc[
    X_train['FilmID'] == row['FilmID'], 'BrukerID'
]
```

These users form the candidate neighborhood.

Only users who rated the target movie can directly contribute an observed rating to the weighted prediction.

### Part 5: Sort Candidate Neighbors by Distance

We retrieve the distances between the target user and all users who rated the movie.

```python
users_sorted = user_dist_matrix.loc[
    row['BrukerID'], users_rated_movie
].sort_values()
```

The resulting Series contains user identifiers and their corresponding distances.

The distances are sorted in ascending order.

Because smaller distances indicate stronger positive correlations, the users at the beginning of the Series are considered the most similar.

### Part 6: Select the 40 Nearest Neighbors

We select the first 40 users from the sorted distance Series.

```python
n_neighbours = users_sorted[:40]
```

This implements the neighborhood size:

$$
K=40
$$

If fewer than 40 eligible users have rated the movie, the available users form a smaller neighborhood.

### Part 7: Calculate the Weighted Neighbor Rating

We retrieve the relevant training observations for the selected neighbors and target movie.

```python
nn_data = train_df.loc[
    (train_df['BrukerID'].isin(n_neighbours.index.to_list())) &
    (train_df['FilmID'] == row['FilmID'])
]
```

The Boolean conditions ensure that we select only:

1. Ratings provided by the chosen neighbors.
2. Ratings associated with the target movie.

Next, inverse-distance weights are calculated.

```python
weights = 1 / n_neighbours.loc[nn_data['BrukerID']].to_numpy()
```

The weights are aligned with the corresponding neighbors' observed ratings.

Finally, we calculate the weighted average:

```python
nearest_neighbours_avg_rating = np.average(
    nn_data['Rangering'],
    weights=weights
)
```

The result is appended to the prediction list.

```python
CF_predictions.append(nearest_neighbours_avg_rating)
```

This calculation estimates the target user's rating using the ratings assigned by similar users.

### Numerical Considerations

The educational implementation demonstrates the intended KNN procedure, but robust implementations should address several additional cases.

A zero distance would cause division by zero when calculating inverse-distance weights.

Undefined correlations can produce missing distance values.

A target user may also appear among the candidate neighbors if that user's training history contains a rating for the same movie.

To avoid these problems, a production implementation should explicitly exclude the target user, handle undefined correlations, and use a stable weighting rule.

For example:

$$
w_{u,v}=\frac{1}{d(u,v)+\epsilon}
$$

Where:

$$
\epsilon>0
$$

A fallback prediction should also be provided when no eligible neighbors remain.

These safeguards improve numerical reliability without changing the underlying user-based collaborative filtering approach.

### Handling Movies Without Training Ratings

If the target movie does not appear in the training dataset, the collaborative model cannot retrieve any ratings from similar users.

The implementation therefore uses the global average rating from the training set.

```python
CF_predictions.append(train_df["Rangering"].mean())
```

This provides a simple fallback for item cold start.

However, the prediction is not personalized because it does not use the target user's individual preferences.

A more advanced hybrid system may instead rely more heavily on content-based predictions when collaborative information is unavailable.

## 4.2.2 Evaluating the Collaborative Filtering Model

After generating predictions for all validation observations, we evaluate their accuracy using **Root Mean Squared Error (RMSE)**.

The RMSE formula is:

$$
RMSE=\sqrt{\frac{1}{N}\sum_{j=1}^{N}(y_j-\hat{y}_j)^{2}}
$$

Where:

- $N$ is the number of validation observations.
- $y_j$ is the actual rating.
- $\hat{y}_j$ is the predicted rating.

We calculate RMSE using:

```python
print("RMSE KNN_40:", sqrt(mean_squared_error(y_val, CF_predictions)))
```

The resulting value measures the prediction error of the collaborative filtering model with 40 nearest neighbors.

A lower RMSE indicates better rating prediction accuracy.

The calculated value can be compared with the baseline and content-based models developed in the previous sections.

# Phase 5: Building the Hybrid Recommender System

We now combine the predictions generated by the content-based and collaborative filtering models.

The objective is to determine whether combining these two recommendation approaches produces more accurate predictions than either model independently.

We use a **Weighted Hybrid** architecture.

In this approach, each model contributes to the final prediction according to an assigned weight.

## Collecting Content-Based Predictions

In Phase 3, we constructed a DataFrame named `CBF_y_pred_df`.

This DataFrame contains predicted ratings for every user–movie pair.

To combine the predictions with those of the collaborative filtering model, we first extract the content-based predictions corresponding to the validation observations.

```python
CBF_y_pred = [CBF_y_pred_df.loc[row["BrukerID"], row["FilmID"]] for index, row in X_val.iterrows()]
weighted_avgs = [(0.5, 0.5), (0.4, 0.6), (0.35, 0.65)]
```

The list comprehension retrieves the appropriate content-based prediction for each validation user–movie pair.

The resulting `CBF_y_pred` list is aligned with the validation observations.

The variable `weighted_avgs` contains three candidate weighting configurations.

| Configuration | Content-Based Weight | Collaborative Weight |
|---|---:|---:|
| 1 | 0.50 | 0.50 |
| 2 | 0.40 | 0.60 |
| 3 | 0.35 | 0.65 |

These configurations allow us to investigate how the relative contributions of the two models affect prediction accuracy.

## Combining Predictions Using Weighted Averaging

Let:

- $\hat{R}_{u,i}^{CBF}$ be the content-based prediction.
- $\hat{R}_{u,i}^{CF}$ be the collaborative filtering prediction.
- $w_{CBF}$ be the weight assigned to the content-based model.
- $w_{CF}$ be the weight assigned to the collaborative filtering model.

The hybrid prediction is:

$$
\hat{R}_{u,i}^{Hybrid}=w_{CBF}\hat{R}_{u,i}^{CBF}+w_{CF}\hat{R}_{u,i}^{CF}
$$

For a normalized weighted average:

$$
w_{CBF}+w_{CF}=1
$$

All three candidate configurations satisfy this condition.

For example, using equal weights:

$$
\hat{R}_{u,i}^{Hybrid}=0.5\hat{R}_{u,i}^{CBF}+0.5\hat{R}_{u,i}^{CF}
$$

Using weights of 0.35 and 0.65:

$$
\hat{R}_{u,i}^{Hybrid}=0.35\hat{R}_{u,i}^{CBF}+0.65\hat{R}_{u,i}^{CF}
$$

In the second configuration, collaborative filtering contributes more strongly to the final prediction.

## Evaluating Different Weight Configurations

We calculate hybrid predictions for each candidate weighting configuration.

The source implementation is:

```python
for weight in weighted_avgs:
    combined_predictions = (np.array(CBF_y_pred) * weight[0]) + (np.array(CF_predictions) * weight[1])
    print(f"RMSE for CBF {weight[0]}, CF {weight[1]}:", sqrt(mean_squared_error(y_val, combined_predictions)))
```

For each pair of weights:

1. The content-based predictions are multiplied by the content-based weight.
2. The collaborative filtering predictions are multiplied by the collaborative weight.
3. The weighted predictions are added together.
4. The resulting predictions are compared with the actual validation ratings.
5. RMSE is calculated and displayed.

The objective is to identify the weighting configuration that minimizes validation RMSE.

Mathematically:

$$
(w_{CBF}^{*},w_{CF}^{*})=\arg\min_{(w_{CBF},w_{CF})\in W}RMSE_{\text{validation}}
$$

Where $W$ is the set of candidate weight configurations.

The optimal weights are selected based on validation performance rather than test performance.

This distinction is important because the test set must remain independent of model selection.

# Phase 6: Final Evaluation

After selecting the best weighting configuration using the validation set, we evaluate the hybrid recommender on the test dataset.

The test set contains observations that were not used to train the component models or select the combination weights.

This provides an estimate of how well the model generalizes to previously unseen rating observations.

## Preparing Content-Based Test Predictions

We begin by extracting content-based predictions for the user–movie pairs in `X_test`.

As in the validation phase, the predictions are retrieved from `CBF_y_pred_df`.

```python
CBF_predictions_test = []
for index, row in X_test.iterrows():
    pred = CBF_y_pred_df.loc[row['BrukerID'], row['FilmID']]
    CBF_predictions_test.append(pred)
```

For each test observation, the code identifies the target user and movie.

It then retrieves the corresponding content-based prediction and appends it to `CBF_predictions_test`.

Because the content-based models were trained using the training set, these predictions do not require fitting the model on the test observations.

## Preparing Collaborative Filtering Test Predictions

Next, we generate collaborative filtering predictions for the test observations.

The procedure follows the same logic used during validation:

1. Check whether the movie appears in the training dataset.
2. Identify users who rated the movie.
3. Retrieve their distances to the target user.
4. Select the 40 nearest neighbors.
5. Calculate a weighted average of their ratings.
6. Use the training-set global mean if the movie has no training ratings.

The implementation is:

```python
CF_predictions_test = []
for index, row in X_test.iterrows():
    if row["FilmID"] in X_train["FilmID"].unique():
        users_rated_movie = X_train.loc[
            X_train['FilmID'] == row['FilmID'], 'BrukerID'
        ]

        users_sorted = user_dist_matrix.loc[
            row['BrukerID'], users_rated_movie
        ].sort_values()

        n_neighbours = users_sorted[:40]

        nn_data = train_df.loc[
            (train_df['BrukerID'].isin(n_neighbours.index.to_list())) &
            (train_df['FilmID'] == row['FilmID'])
        ]

        weights = 1 / n_neighbours.loc[nn_data['BrukerID']].to_numpy()
        nearest_neighbours_avg_rating = np.average(
            nn_data['Rangering'],
            weights=weights
        )

        CF_predictions_test.append(nearest_neighbours_avg_rating)
    else:
        CF_predictions_test.append(train_df["Rangering"].mean())
```

These predictions are calculated using the original training data and the user distance matrix constructed in Phase 4.

The test ratings themselves are not used to calculate user similarities or neighbor averages.

As with the validation implementation, numerical safeguards should be applied when deploying this procedure in a production environment.

## Combining the Final Predictions

Suppose the validation experiments indicate that the best weighting configuration is:

$$
w_{CBF}=0.35
$$

$$
w_{CF}=0.65
$$

These values assign 35% of the final prediction weight to the content-based model and 65% to the collaborative filtering model.

The final hybrid prediction is:

$$
\hat{R}_{u,i}^{Hybrid}=0.35\hat{R}_{u,i}^{CBF}+0.65\hat{R}_{u,i}^{CF}
$$

We apply these weights to the test predictions.

```python
hybrid_predictions_test = (np.array([y_pred * 0.35 for y_pred in CBF_predictions_test]) + np.array([y_pred * 0.65 for y_pred in CF_predictions_test]))
print(f"RMSE hybrid recommendations (test data): {sqrt(mean_squared_error(y_test, hybrid_predictions_test))}")
```

The first expression combines the predictions from the two models.

The second expression calculates RMSE by comparing the hybrid predictions with the actual test ratings.

The final test RMSE is:

$$
RMSE_{\text{test}}=\sqrt{\frac{1}{N_{\text{test}}}\sum_{j=1}^{N_{\text{test}}}(y_j-\hat{y}_j^{Hybrid})^{2}}
$$

Where:

- $N_{\text{test}}$ is the number of test observations.
- $y_j$ is the observed test rating.
- $\hat{y}_j^{Hybrid}$ is the corresponding hybrid prediction.

The resulting value provides the final evaluation of the weighted hybrid recommendation model on the held-out test set.
