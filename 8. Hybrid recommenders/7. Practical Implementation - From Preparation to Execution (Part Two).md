## 2.1 Splitting the Dataset into Training, Validation, and Test Sets

Our initial objective is to construct a simple model that predicts the numerical ratings users assign to movies.

Because the target variable is a numerical rating, this can be formulated as a **regression problem**.

Before training any model, we must divide the available observations into separate datasets for training, validation, and testing.

These subsets have distinct purposes:

- **Training Set:** Used to estimate model parameters.
- **Validation Set:** Used to evaluate alternative models, select hyperparameters, and guide model development.
- **Test Set:** Reserved for the final evaluation of the selected model on observations not used during training or model selection.

### An Important Consideration for Recommendation Evaluation

The splitting procedure used here randomly divides individual rating observations.

This is a common approach for evaluating explicit-rating prediction models.

However, random interaction splitting has several implications.

First, the same user may appear in the training, validation, and test sets, although the individual rating observations are separated.

Second, the timestamps are not used to preserve chronological ordering.

Consequently, the training set may contain interactions that occurred after interactions included in the validation or test sets.

This is acceptable for illustrating a conventional random-split rating prediction experiment, but it does not measure the model's ability to predict future interactions under a strictly chronological evaluation protocol.

For applications where temporal generalization is important, a time-based splitting strategy may be more appropriate.

Similarly, evaluating cold-start performance requires special splitting procedures that deliberately exclude selected users or items from training.

## 2.2 Constructing a Baseline Recommendation Model

Before developing more sophisticated recommendation algorithms, we need a simple model against which their performance can be compared.

Such a model is called a **baseline model**.

A baseline establishes a reference level of predictive performance.

If a complex recommendation algorithm cannot outperform a simple baseline, its additional computational and implementation complexity may not be justified.

### Movie Mean Rating as a Baseline

Our baseline model uses the average historical rating of each movie.

The central assumption is straightforward:

**Every user is predicted to assign a movie a rating equal to that movie's average rating in the training dataset.**

For example, suppose a movie has received the following ratings:

```text
[4, 5, 3, 4, 4]
```

Its average rating is:

$$
\bar{r}_{i}=\frac{4+5+3+4+4}{5}=4
$$

The baseline model therefore predicts a rating of 4 for that movie, regardless of which user requests the prediction.

This method is not personalized because it does not model individual user preferences.

Nevertheless, it provides a useful benchmark for determining whether more advanced models can exploit user-specific information to improve rating prediction.

Although average ratings are related to item popularity, the two concepts should be distinguished.

Popularity generally refers to how frequently an item is consumed or interacted with, whereas the average rating measures the mean numerical evaluation of the item.

The baseline implemented here is therefore more precisely described as an **item-mean rating baseline**.

### Mathematical Formulation

Let $\Omega_i$ denote the set of users who rated item $i$ in the training dataset.

The average rating for item $i$ is:

$$
\bar{r}_{i}=\frac{1}{|\Omega_i|}\sum_{u\in\Omega_i}R_{u,i}
$$

Where:

- $R_{u,i}$ is the observed rating assigned by user $u$ to item $i$.
- $\Omega_i$ is the set of users who rated item $i$.
- $|\Omega_i|$ is the number of observed training ratings for item $i$.

The baseline prediction is:

$$
\hat{R}_{u,i}=\bar{r}_{i}
$$

Because the prediction depends only on the item, different users receive the same predicted rating for the same movie.

### Calculating Average Movie Ratings

We calculate the average rating for each movie using the training dataset.

```python
# Creating a new dataframe with the average rating for each movie.

```


groups the training observations by movie identifier and calculates the average rating for each movie.

### Handling Movies Without Training Ratings

Some movies may not appear in the training dataset.

For example, a movie might occur in the validation or test set without having any ratings in the training set.

In such cases, the model cannot calculate a movie-specific average.

To prevent missing predictions, we use the overall average rating of the training dataset as a fallback value.

The global mean rating is:

$$
\mu=\frac{1}{|\Omega_{\text{train}}|}\sum_{(u,i)\in\Omega_{\text{train}}}R_{u,i}
$$

Where $\Omega_{\text{train}}$ is the set of observed training interactions.

The complete baseline prediction rule becomes:

$$
\hat{R}_{u,i}=\begin{cases}\bar{r}_{i} & \text{if item }i\text{ has training ratings}\\\mu & \text{otherwise}\end{cases}
$$

We implement this fallback mechanism as follows:

```python
# Calculating the average of the total points in the training set 
overall_mean_rating = train_df['Rangering'].mean()
# Find movies that are not in the training set but are in the validation or testing set
missing_movies = movies_df[~movies_df['FilmID'].isin(baseline_y_pred.index)]['FilmID']
# Add these movies to baseline_y_pred with the average total scores
for movie_id in missing_movies:
    baseline_y_pred.loc[movie_id, 'Rangering'] = overall_mean_rating
```

The first statement calculates the overall average rating.

Next, the code identifies movie identifiers that exist in `movies_df` but are absent from the baseline predictions.

Finally, each missing movie receives the global training mean.

This ensures that the baseline can generate predictions for every movie represented in the movie catalog.

Importantly, the fallback value is calculated exclusively from the training data.

Using validation or test ratings to calculate the global mean would introduce information leakage into the evaluation process.

## Evaluating the Baseline Model

We evaluate the baseline using **Root Mean Squared Error (RMSE)**.

RMSE measures the discrepancy between predicted ratings and actual ratings.

For $N$ evaluated observations, RMSE is defined as:

$$
RMSE=\sqrt{\frac{1}{N}\sum_{j=1}^{N}(y_{j}-\hat{y}_{j})^{2}}
$$

Where:

- $N$ is the number of evaluated rating observations.
- $y_j$ is the actual rating for observation $j$.
- $\hat{y}_j$ is the corresponding predicted rating.

The calculation involves four operations:

1. Calculate the prediction error for each observation.
2. Square each error.
3. Calculate the mean of the squared errors.
4. Take the square root of the result.

Because errors are squared, large prediction errors receive greater penalties than small errors.

A lower RMSE indicates that predictions are closer to the observed ratings under this metric.

An RMSE of zero indicates perfect predictions.

### Calculating RMSE in Python

```python
# calculating RMSE for the baseline model
print("RMSE baseline model: ", sqrt(mean_squared_error(baseline_y_pred_vs_y_true["Predicted rating"], 
                                                       baseline_y_pred_vs_y_true["Actual rating"])))
```

Output:

```text
RMSE baseline model:  0.9941652754192015
```

The baseline model achieves an RMSE of approximately:

$$
RMSE_{\text{baseline}}\approx0.994
$$

This result indicates the magnitude of the model's root-mean-square prediction error on the validation observations.

Because ratings range from 1 to 5, an RMSE close to 1 represents a substantial prediction error relative to the rating scale.

However, RMSE should not be interpreted as the arithmetic average of the absolute prediction errors.

That quantity is measured by Mean Absolute Error (MAE).

Instead, RMSE is the square root of the mean squared error and therefore places additional emphasis on larger prediction deviations.

The baseline result provides a reference point for evaluating the more sophisticated recommendation models developed in the following phases.

# Phase 3: Building a Content-Based Recommendation Model

In this phase, we construct a **Content-Based Filtering (CBF)** model that predicts user ratings using movie attributes.

Unlike the baseline model, which assigns the same predicted rating to every user for a given movie, the content-based model learns a separate preference function for each user.

The model uses the genres of previously rated movies to estimate how strongly an individual user prefers different types of content.

### Model Design

The content-based recommendation procedure follows three principal steps:

1. Extract movie content features, such as genres, and associate them with observed user ratings.
2. Train a separate **Lasso Regression** model for each user using the genres of movies they have rated.
3. Use the trained models to predict ratings for other movies and evaluate the predictions against the validation set.

This approach allows different users to have different relationships between content features and numerical ratings.

For example, one user may consistently assign high ratings to Action movies, while another may prefer Drama or Comedy.

A personalized regression model can learn these relationships from each user's historical ratings.

### Why Group Ratings by User?

For a user-specific content-based model, each user has an independent training problem.

Suppose user $u$ has rated $n_u$ movies.

The target vector for that user is:

$$
y_{u}=[r_{u,1},r_{u,2},\ldots,r_{u,n_u}]^{T}
$$

Where:

- $n_u$ is the number of training ratings associated with user $u$.
- $r_{u,j}$ is the rating assigned by user $u$ to the $j$-th movie in that user's training observations.

The corresponding genre features will form a separate feature matrix.

Together, the feature matrix and target vector provide the training data for that user's regression model.

By grouping the dataset in this way, we prepare the observations required for personalized content-based learning.

## 3.4 Training the Content-Based Model and Generating Predictions

We now train a personalized content-based recommendation model.

The selected algorithm is **Lasso Regression**, a linear regression method that incorporates L1 regularization.

Lasso is particularly useful when the input contains multiple potentially correlated or weakly informative features.

In this project, the features are binary genre indicators.

For each user, the model learns how different movie genres contribute to the predicted rating.

### The Lasso Regression Model

A linear regression model predicts a rating using a weighted combination of content features.

For user $u$ and movie $i$, the predicted rating can be written as:

$$
\hat{R}_{u,i}=b_u+\sum_{j=1}^{d}w_{u,j}x_{i,j}
$$

Where:

- $b_u$ is the intercept associated with user $u$.
- $w_{u,j}$ is the learned coefficient of content feature $j$ for user $u$.
- $x_{i,j}$ is the value of feature $j$ for movie $i$.
- $d$ is the total number of content features.

In this project, the model uses 18 genre indicators:

$$
d=18
$$

Because each user has a separate regression model, the coefficients can differ across users.

For example, one user may have a positive coefficient for Action and a negative coefficient for Horror.

Another user may exhibit the opposite preference pattern.

### L1 Regularization

Lasso extends ordinary linear regression by penalizing the absolute magnitudes of the model coefficients.

For user $u$, its objective can be written as:

$$
L_u(w_u,b_u)=\frac{1}{2n_u}\sum_{j=1}^{n_u}(y_{u,j}-b_u-w_u^{T}x_{u,j})^{2}+\alpha\sum_{f=1}^{d}|w_{u,f}|
$$

Where:

- $n_u$ is the number of training observations for user $u$.
- $y_{u,j}$ is the observed rating.
- $x_{u,j}$ is the movie feature vector.
- $w_u$ is the vector of learned regression coefficients.
- $b_u$ is the intercept.
- $\alpha$ controls the strength of L1 regularization.

The regularization term is:

$$
\alpha\sum_{f=1}^{d}|w_{u,f}|
$$

L1 regularization can shrink some coefficients exactly to zero.

Consequently, it can effectively eliminate genre features that provide little predictive value for a particular user.

This property can reduce model complexity and help prevent overfitting.

However, the choice of $\alpha$ is important.

If regularization is too strong, the model may suppress useful coefficients and produce predictions close to the user's average rating.

### Training One Model per User

The implementation initializes a Lasso regression model and then iterates through the user-specific training datasets.

```python
model = Lasso(alpha=1.0, max_iter=10000)

CBF_predictions = []
for i, x in enumerate(x_train_listed):
    model.fit(x_train_listed[i], y_train_listed[i])
    prediction = model.predict(all_movies)
    prediction = np.clip(prediction, 1, 5)
    CBF_predictions.append(prediction)
movie_ids = movies_df["FilmID"].values
```

The model is initialized using:

```python
model = Lasso(alpha=1.0, max_iter=10000)
```

The parameter `alpha=1.0` specifies the strength of the L1 regularization penalty.

The parameter `max_iter=10000` sets the maximum number of iterations allowed by the optimization procedure.

Next, the algorithm iterates through the user-specific feature matrices.

For each user, the model is fitted using:

```python
model.fit(x_train_listed[i], y_train_listed[i])
```

Here:

- `x_train_listed[i]` contains the genre features of movies rated by the current user.
- `y_train_listed[i]` contains the corresponding observed ratings.

After fitting the model, predictions are generated for all movies:

```python
prediction = model.predict(all_movies)
```

The result is a vector containing one predicted rating for each movie in the catalog.

### Restricting Predictions to the Rating Scale

Linear regression models can generate predictions outside the range of the target variable.

For example, a model trained on ratings between 1 and 5 might produce predictions below 1 or above 5.

Because the MovieLens rating scale is restricted to this interval, the implementation clips the predictions:

```python
prediction = np.clip(prediction, 1, 5)
```

Mathematically, clipping can be represented as:

$$
\hat{R}_{u,i}^{\text{clipped}}=\min(5,\max(1,\hat{R}_{u,i}))
$$

This ensures that every predicted rating satisfies:

$$
1\le\hat{R}_{u,i}^{\text{clipped}}\le5
$$

The predictions for each user are then appended to `CBF_predictions`.

After completing the loop, this list contains one prediction vector per user.

Because the same `Lasso` instance is refitted for each user, its coefficients are replaced during each iteration.

However, the predictions generated before the next fitting operation remain stored in `CBF_predictions`.

Thus, the code produces separate predictions for each user without storing all fitted model objects.

### Organizing the Prediction Matrix

The next step is to convert the prediction vectors into a DataFrame.

```python
CBF_y_pred_df = pd.DataFrame(CBF_predictions, index=user_ids, columns=movie_ids)
```

The resulting matrix has users as rows and movies as columns.

Each entry contains the content-based model's predicted rating for the corresponding user–movie pair.

Mathematically, the prediction matrix is:

$$
\hat{R}_{CBF}\in\mathbb{R}^{m\times n}
$$

Where:

- $m$ is the number of users.
- $n$ is the number of movies.
- $\hat{R}_{CBF}[u,i]$ is the predicted rating of user $u$ for movie $i$.

Unlike the validation matrix, the prediction matrix contains values for all user–movie combinations.

This allows us to estimate user preferences for movies that have not been rated.

However, the evaluation must compare predictions only with observed validation ratings.

## Evaluating the Content-Based Model Using RMSE

To evaluate the model, we compare its predictions with the actual ratings in the validation set.

Because the validation matrix is sparse, most of its entries are missing.

These missing values represent user–movie pairs without observed validation ratings.

They must not be treated as actual ratings of zero.

Therefore, we select only the positions where the validation matrix contains observed ratings.

### Extracting Observed Ratings and Corresponding Predictions

```python
CBF_y_pred_df = pd.DataFrame(CBF_predictions, index=user_ids, columns=movie_ids)
num_actual = validation_matrix.to_numpy().flatten()[validation_matrix.notna().to_numpy().flatten()]
num_predict = CBF_y_pred_df.to_numpy().flatten()[validation_matrix.notna().to_numpy().flatten()]

print("RMSE Lasso:", sqrt(mean_squared_error(num_predict, num_actual)))
```

The expression:

```python
validation_matrix.notna()
```

creates a Boolean mask identifying entries that contain actual validation ratings.

For each observed entry, the mask contains `True`.

For missing entries, it contains `False`.

The expression:

```python
validation_matrix.to_numpy().flatten()
```

converts the validation matrix into a NumPy array and flattens it into a one-dimensional vector.

The Boolean mask is also flattened:

```python
validation_matrix.notna().to_numpy().flatten()
```

Applying this mask selects only the observed validation ratings:

```python
num_actual = validation_matrix.to_numpy().flatten()[validation_matrix.notna().to_numpy().flatten()]
```

The same mask is then applied to the prediction matrix:

```python
num_predict = CBF_y_pred_df.to_numpy().flatten()[validation_matrix.notna().to_numpy().flatten()]
```

This ensures that each predicted rating is paired with the corresponding actual validation rating.

The evaluation therefore excludes user–movie pairs for which no ground-truth rating is available.

### Calculating RMSE

The final evaluation uses:

```python
print("RMSE Lasso:", sqrt(mean_squared_error(num_predict, num_actual)))
```

The metric is calculated as:

$$
RMSE_{CBF}=\sqrt{\frac{1}{N_{\text{val}}}\sum_{(u,i)\in\Omega_{\text{val}}}(R_{u,i}-\hat{R}_{u,i})^{2}}
$$

Where:

- $\Omega_{\text{val}}$ is the set of observed validation interactions.
- $N_{\text{val}}$ is the number of evaluated validation observations.
- $R_{u,i}$ is the actual rating.
- $\hat{R}_{u,i}$ is the rating predicted by the content-based model.

A lower RMSE indicates better predictive performance under this evaluation metric.

### What Has the Content-Based Model Learned?

The content-based model represents each movie using 18 binary genre indicators.

For each user, it estimates a separate set of regression coefficients describing how those genre attributes relate to the user's ratings.

This allows the model to generate personalized predictions rather than assigning every user the same item-average rating.

The resulting prediction matrix can be used to estimate ratings for movies that a user has not previously evaluated.

Because predictions depend on item attributes, this approach can also estimate preferences for movies with limited interaction histories, provided that their content features are available and the user's model has sufficient training data.

However, the model's predictive capabilities remain limited by the information contained in the selected features.

In this implementation, the model uses only genre indicators.

It does not directly account for factors such as directors, actors, plot descriptions, item popularity, or collaborative interaction patterns.

Furthermore, users with very few observed ratings may not provide sufficient training data for reliable user-specific regression models.

These considerations motivate the later integration of content-based predictions with collaborative filtering, allowing the hybrid recommender to exploit both item characteristics and patterns in user–item interactions.
