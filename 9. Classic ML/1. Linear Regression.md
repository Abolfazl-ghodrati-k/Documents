
In this chapter, we adopt a more flexible and powerful approach to building recommender systems through **Machine Learning (ML)**. Machine learning enables us to incorporate a broader range of information, including user attributes, item characteristics, and contextual features, and formulate recommendation tasks as standard prediction problems.

The first algorithm we will examine is **Linear Regression**, one of the simplest and most fundamental supervised learning algorithms.

Linear regression is designed for **regression problems**, in which the objective is to predict a continuous numerical value. In recommender systems, one of its most common applications is predicting the numerical rating that a user would assign to a particular item.

## Why Linear Regression?

Although linear regression is not necessarily the most powerful algorithm for building recommender systems, it provides an excellent starting point for understanding machine learning-based recommendation.

Its importance can be explained through three main characteristics.

### 1. Simplicity and Interpretability

Linear regression is based on a straightforward mathematical relationship between input features and a target variable.

Unlike many complex machine learning algorithms, its predictions can be expressed as a weighted sum of the input features.

This makes the model relatively easy to understand, implement, and interpret.

### 2. Establishing a Baseline Model

Linear regression can serve as a **baseline model** against which more sophisticated recommendation algorithms are evaluated.

A baseline is a relatively simple model that provides a reference level of performance.

For example, suppose a development team spends hundreds of hours designing and training a computationally expensive recommendation model.

Without an appropriate baseline, it may be difficult to determine whether the additional complexity and computational cost have produced meaningful improvements.

A practical evaluation strategy is to:

1. Train a simple baseline model, such as linear regression.
2. Train the more sophisticated model using the same training data.
3. Evaluate both models on the same held-out test set using identical metrics.
4. Compare their predictive performance, computational requirements, and operational costs.

If the complex model performs only marginally better than the baseline, its additional cost may not be justified.

Conversely, a substantial improvement over the baseline provides evidence that the more sophisticated approach offers practical value.

Therefore, baseline models help determine whether increasing model complexity is worthwhile.

### 3. Incorporating Additional Features

Linear regression can use a wide variety of numerical input features.

In recommendation applications, these may include:

- User demographic attributes.
- Item content characteristics.
- Statistical summaries of historical interactions.
- Contextual information.
- Predictions generated by other recommendation algorithms.

This flexibility also allows linear regression to function as a component within a **Hybrid Recommender System**.

For example, the predictions of collaborative filtering and content-based filtering models can be used as input features to a linear regression model.

The regression model then learns how to combine these signals to generate a final prediction.

This approach provides a simple introduction to learning-based model combination.

## The Linear Regression Model

Linear regression assumes that the target variable can be approximated by a linear combination of the input features.

The general mathematical formulation is:

$$
\hat{y}=\beta_{0}+\beta_{1}x_{1}+\beta_{2}x_{2}+\cdots+\beta_{p}x_{p}
$$

Equivalently, using vector notation:

$$
\hat{y}=\beta_{0}+\mathbf{x}\cdot\boldsymbol{\beta}
$$

Where:

- $\hat{y}$ is the value predicted by the model. In a recommendation task, this may represent the predicted rating for a particular user–item pair.
- $x_{1},x_{2},\ldots,x_{p}$ are the input features associated with an observation.
- $\mathbf{x}=[x_{1},x_{2},\ldots,x_{p}]$ is the input feature vector.
- $\beta_{0}$ is the **intercept**, representing the predicted value when all input features are zero.
- $\beta_{1},\beta_{2},\ldots,\beta_{p}$ are the model's **coefficients**, also called weights.
- $\boldsymbol{\beta}=[\beta_{1},\beta_{2},\ldots,\beta_{p}]$ is the coefficient vector.

Each coefficient determines how a corresponding feature contributes to the predicted value when the other features remain constant.

For example, if $\beta_{1}$ is positive, increasing $x_{1}$ while keeping the remaining features unchanged increases the predicted value.

If $\beta_{1}$ is negative, increasing $x_{1}$ decreases the prediction.

The coefficients are estimated automatically from training data.

### Geometric Interpretation

Linear regression attempts to find a mathematical function that best approximates the relationship between the input features and the target variable.

When the model contains one input feature, the prediction function describes a straight line:

$$
\hat{y}=\beta_{0}+\beta_{1}x_{1}
$$

When the model contains two input features, the prediction function describes a plane in three-dimensional space:

$$
\hat{y}=\beta_{0}+\beta_{1}x_{1}+\beta_{2}x_{2}
$$

With more than two features, the model defines a **hyperplane** in a higher-dimensional space.

The objective is to select coefficients that minimize the differences between the observed target values and the predictions produced by this hyperplane.

These differences are known as **residuals** or prediction errors.

For an observation $k$, the residual is:

$$
e_{k}=y_{k}-\hat{y}_{k}
$$

The smaller the residuals, according to the selected optimization criterion, the better the fitted model represents the training observations.

## Linear Regression in Recommender Systems

Linear regression can be applied to recommendation tasks in which the objective is to predict numerical ratings.

For example, consider a movie recommendation system in which users rate movies on a scale from 1 to 5.

The model attempts to estimate the rating that a particular user would assign to a particular movie.

Unlike traditional matrix factorization, which primarily learns from user–item interactions, linear regression can directly incorporate engineered features describing users, items, and their interactions.

### Representing User–Item Interactions as Training Samples

Suppose we have an interaction dataset containing the following columns:

- `user_id`
- `item_id`
- `rating`

Each observed interaction becomes a separate training sample.

For a user $u$ and an item $i$, let the observed rating be:

$$
R_{u,i}
$$

We construct a feature vector associated with this user–item pair:

$$
\mathbf{x}_{u,i}=[x_{u,i,1},x_{u,i,2},\ldots,x_{u,i,p}]
$$

These features may describe the user, the item, or the relationship between them.

For example, in a movie recommendation system, a feature may represent the user's average rating for movies belonging to a particular genre.

The regression model then predicts the rating as:

$$
\hat{R}_{u,i}=\beta_{0}+\beta_{1}x_{u,i,1}+\beta_{2}x_{u,i,2}+\cdots+\beta_{p}x_{u,i,p}
$$

Here:

- $\hat{R}_{u,i}$ is the predicted rating of user $u$ for item $i$.
- $x_{u,i,j}$ is the value of feature $j$ for the user–item pair.
- $\beta_{j}$ is the learned coefficient associated with feature $j$.

The model learns the coefficients that best explain the observed ratings in the training dataset.

### Visualizing Rating Prediction

A simple illustration of linear regression may show a set of observed user ratings and one or more fitted regression lines.

Each line represents a learned relationship between an input feature and the predicted rating.

In practice, recommendation models typically use several features simultaneously, making direct visualization difficult.

For educational purposes, such diagrams may represent a single feature or a simplified aggregate of several user characteristics.

## Feature Selection for Linear Regression

The predictive performance of linear regression depends heavily on the quality and relevance of its input features.

This makes **Feature Engineering** an essential part of building regression-based recommender systems.

Feature engineering involves selecting, transforming, and constructing variables that provide useful information for the prediction task.

We will examine this topic in greater detail in the section *Feature Engineering and Data Preprocessing*.

For now, consider several categories of features that can be constructed for each user–item pair.

### 1. Statistical Features Derived from Interactions

Historical interaction data can be summarized into numerical features.

Examples include:

- **User Average Rating:** The average rating assigned by user $u$ to other items.
- **User Rating Count:** The number of items rated by user $u$.
- **Item Average Rating:** The average rating received by item $i$ from other users.
- **Item Rating Count:** The number of users who have rated item $i$.

These features capture useful information about user behavior and item popularity.

For example, users who consistently assign high ratings may have different rating tendencies from users who generally assign lower ratings.

Similarly, an item with a high average rating may be more likely to receive a favorable rating from another user.

When constructing these features, it is essential to prevent **data leakage**. Statistical features must be calculated using information available at the time of prediction, rather than using ratings from the held-out test set or future interactions.

### 2. User Side Features

User attributes can provide additional information beyond historical ratings.

Examples include:

- **Age:** The age of user $u$.
- **Gender:** A categorical attribute that may require numerical encoding.
- **Geographic Location:** A location attribute that must be transformed into a suitable representation.

Categorical attributes cannot generally be passed directly to standard linear regression implementations as arbitrary strings.

They must first be encoded numerically using appropriate techniques, such as **One-Hot Encoding**.

The inclusion of demographic or location information should also account for relevance, data quality, fairness, and privacy considerations.

### 3. Item Side Features

Item metadata can be used to represent characteristics of the recommended content or product.

Examples include:

- **Primary Genre:** The main genre of item $i$, encoded numerically.
- **Release Year:** The year in which item $i$ was released.
- **Price:** The price of item $i$.

These features may help the model distinguish between different categories of items.

For example, a movie's release year may capture certain historical or temporal patterns in user preferences.

Likewise, price may be an important predictive feature in an e-commerce recommendation system.

### 4. Simple Interaction Features

Additional features can be constructed by combining existing variables.

Examples include:

**Product of User and Item Average Ratings**

A feature can be created by multiplying the user's average rating by the item's average rating.

This allows the model to represent an interaction between two statistical characteristics.

**Difference Between User Age and Population Average Age**

Another feature can represent the difference between a user's age and the average age of the user population.

This measures the user's relative position within the observed age distribution.

These engineered variables may provide information that is not directly represented by the original features.

Importantly, even though linear regression is linear in its coefficients, engineered interaction terms can allow it to represent certain nonlinear relationships between the original variables.

### Choosing Appropriate Features

Not every recommendation dataset contains all the features described above.

Some applications may provide only interaction statistics, while others include extensive user profiles, item metadata, and contextual information.

Depending on the application, a regression model may use:

- Only interaction-derived statistical features.
- Only user or item side features.
- A combination of several feature categories.

The appropriate selection depends on data availability, the recommendation objective, and the predictive usefulness of each feature.

Determining which features to include is a central responsibility of feature engineering.

## Constructing the Training Data

To train a linear regression model, we need two fundamental data structures.

### Feature Matrix

The **feature matrix**, denoted by $X$, contains the input features for all observed training interactions.

Each row corresponds to one user–item interaction.

If there are $N$ training observations and $p$ features, the feature matrix has dimensions:

$$
X\in\mathbb{R}^{N\times p}
$$

Each row represents a feature vector:

$$
\mathbf{x}_{u,i}
$$

associated with a particular user–item pair.

### Target Vector

The **target vector**, denoted by $\mathbf{y}$, contains the actual ratings associated with the training observations.

Its dimensions are:

$$
\mathbf{y}\in\mathbb{R}^{N}
$$

For each row of $X$, the corresponding element of $\mathbf{y}$ contains the observed rating.

The training objective is to learn a mapping from the feature matrix to the target ratings.

## Learning the Model: Estimating the Regression Coefficients

Training a linear regression model involves finding the coefficients:

$$
\beta_{0},\beta_{1},\ldots,\beta_{p}
$$

that produce predictions as close as possible to the observed ratings.

To measure prediction errors, we define a **loss function**.

A standard choice for ordinary least squares regression is the **Sum of Squared Errors (SSE)**.

### Sum of Squared Errors

The SSE objective is:

$$
SSE=\sum_{k=1}^{N}(y_{k}-\hat{y}_{k})^{2}
$$

Substituting the linear regression prediction function gives:

$$
SSE=\sum_{k=1}^{N}\left(y_{k}-\left(\beta_{0}+\sum_{j=1}^{p}\beta_{j}x_{k,j}\right)\right)^{2}
$$

The training objective is:

$$
\min_{\beta_{0},\beta_{1},\ldots,\beta_{p}}\sum_{k=1}^{N}\left(y_{k}-\left(\beta_{0}+\sum_{j=1}^{p}\beta_{j}x_{k,j}\right)\right)^{2}
$$

Where:

- $N$ is the number of training observations.
- $y_{k}$ is the actual rating for observation $k$.
- $\hat{y}_{k}$ is the predicted rating for observation $k$.
- $x_{k,j}$ is the value of feature $j$ for observation $k$.
- $\beta_{j}$ is the coefficient associated with feature $j$.

Squaring the residuals has two important consequences.

First, positive and negative errors cannot cancel one another.

Second, larger prediction errors receive greater penalties than smaller errors.

The optimization algorithm therefore attempts to identify coefficients that minimize the total squared prediction error.

### Ordinary Least Squares

Minimizing the SSE objective is known as an **Ordinary Least Squares (OLS)** problem.

As discussed previously in the context of matrix factorization, least-squares optimization is a fundamental technique for estimating model parameters.

For linear regression, the objective is quadratic in the coefficients and can be solved using linear algebra.

### The Normal Equation

To express the solution in matrix form, we augment the feature matrix with a column of ones representing the intercept.

The resulting matrix has dimensions:

$$
X\in\mathbb{R}^{N\times(p+1)}
$$

The coefficient vector becomes:

$$
\boldsymbol{\beta}=[\beta_{0},\beta_{1},\ldots,\beta_{p}]^{T}
$$

The target vector has dimensions:

$$
\mathbf{y}\in\mathbb{R}^{N\times1}
$$

The least-squares objective can then be written as:

$$
\min_{\boldsymbol{\beta}}\lVert X\boldsymbol{\beta}-\mathbf{y}\rVert^{2}_{2}
$$

When $X^{T}X$ is invertible, the optimal coefficient vector can be obtained using the **Normal Equation**:

$$
\hat{\boldsymbol{\beta}}=(X^{T}X)^{-1}X^{T}\mathbf{y}
$$

Where:

- $X^{T}$ is the transpose of the feature matrix.
- $(X^{T}X)^{-1}$ is the inverse of the matrix $X^{T}X$.
- $\hat{\boldsymbol{\beta}}$ is the estimated coefficient vector.

This expression provides a direct analytical solution to the least-squares problem.

### Computational Considerations

One advantage of ordinary least squares regression is that it does not necessarily require iterative optimization methods such as gradient descent.

When the feature matrix has suitable properties, the coefficients can be computed directly.

However, explicitly calculating the inverse of $X^{T}X$ may be computationally expensive or numerically unstable, particularly when the feature matrix contains many columns or highly correlated features.

If $X^{T}X$ is singular, the inverse does not exist.

Practical implementations therefore often use more numerically stable techniques, such as QR decomposition, Singular Value Decomposition (SVD), or least-squares solvers based on the pseudoinverse.

These methods make linear regression applicable even when the direct inverse-based formulation is unsuitable.
