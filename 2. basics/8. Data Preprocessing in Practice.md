### Why Does Data Distribution Matter?

The distribution of a feature is particularly important when it will be used as an input variable in a machine learning model. If a categorical feature is highly imbalanced, the model may become biased toward the majority class during training.

For example, if the **gender** feature were incorporated into a recommendation model without considering its imbalance, the model might implicitly learn that most movie users are male simply because male records dominate the training data. Such a conclusion would reflect the characteristics of this particular dataset rather than the actual population of movie viewers.

This phenomenon is known as **class imbalance**, and it can negatively affect both the fairness and generalization ability of machine learning models. Depending on the application, various balancing techniques—such as oversampling, undersampling, or synthetic data generation—may be employed to mitigate this issue.

# Splitting the Dataset into Training and Test Sets

One of the most important preprocessing steps in any machine learning workflow is dividing the dataset into separate **training** and **testing** sets.

The objective of this separation is straightforward: we train the recommender system using one portion of the data and evaluate its performance using another portion that the model has never seen before. This provides a realistic estimate of how well the model will perform when making recommendations for new users or unseen interactions.

Without this separation, it becomes difficult to determine whether a model has truly learned meaningful patterns or has simply memorized the training data—a phenomenon known as **overfitting**.

The most common strategy is to partition the original dataset into:

- **Training Set**, used for learning the model parameters.
    
- **Test Set**, reserved exclusively for evaluating the trained model.
    

This can be accomplished easily using the `train_test_split` function provided by **Scikit-learn**.

```python
from sklearn.model_selection import train_test_split

test_set_size = 0.2

train_df, test_df = train_test_split(
    ratings_df,
    test_size=test_set_size,
    random_state=42
)
```

In this example, **20%** of the data are allocated to the test set, while the remaining **80%** are used for training. The parameter `random_state=42` ensures that the split is reproducible, meaning that every execution of the code produces the same partition.

For recommender systems, random interaction splitting is useful as a simple baseline, but it is often not the most realistic evaluation protocol. It can place a user's later interaction in training while an earlier interaction appears in test data, which leaks future behavior into the model. Prefer a **time-based split** when timestamps are available, and use a **per-user holdout** when every evaluated user should retain at least one interaction in the training set. Also decide explicitly how to handle users and items that occur only in the test set; they are cold-start cases, not ordinary ranking cases.

After performing the split, we can verify the size of each subset.


Creating the evaluation set should ideally be **the very first preprocessing step** performed after loading the raw dataset. Doing so prevents **data leakage**, a critical issue in machine learning where information from the test set inadvertently influences the training process.

To preserve the integrity of the evaluation, **all subsequent preprocessing operations—such as feature scaling, missing value imputation, and categorical encoding—should be fitted exclusively on the training data**. The same transformations are then applied to the test set without recalculating their parameters. This procedure closely simulates real-world deployment, where future data are unavailable during model training and ensures that performance metrics accurately reflect the model's ability to generalize to unseen data.

# Encoding Categorical Features

The dataset contains two categorical attributes:

- **gender**
    
- **occupation**
    

These features are represented as text labels. While they are easily understood by humans, most machine learning algorithms require numerical input and therefore cannot process textual categories directly.

One of the most widely used techniques for converting categorical variables into numerical representations is **One-Hot Encoding**.

## One-Hot Encoding

One-Hot Encoding transforms each category into a separate binary feature. Each newly created feature represents the presence or absence of a particular category.

For example, consider the **gender** feature.

|Original Gender|gender_M|
|---|---|
|M|1|
|F|0|

Similarly, the **occupation** column is expanded into multiple binary columns, each representing one occupation.

| Occupation | occupation_student | occupation_engineer | occupation_writer |
| ---------- | -----------------: | ------------------: | ----------------: |
| student    |                  1 |                   0 |                 0 |
| engineer   |                  0 |                   1 |                 0 |
| writer     |                  0 |                   0 |                 1 |

This representation allows machine learning algorithms to treat each category independently without introducing artificial ordinal relationships between them.

Pandas provides the **`get_dummies()`** function to perform One-Hot Encoding with minimal effort.

```python
categorical_cols = ['gender', 'occupation']

train_df_encoded = pd.get_dummies(
    train_df,
    columns=categorical_cols,
    drop_first=True
)

test_df_encoded = pd.get_dummies(
    test_df,
    columns=categorical_cols,
    drop_first=True
)
```

The parameter **`drop_first=True`** removes one category from each encoded feature group. This avoids perfect multicollinearity—commonly referred to as the **dummy variable trap**—which can cause problems for linear models. Since the omitted category can always be inferred from the remaining binary columns, no information is lost.

# Ensuring Consistent Feature Spaces

When the original dataset is divided into training and testing subsets, it is possible that certain categorical values appear in only one subset.

For example, imagine that no user with the occupation **doctor** happens to appear in the test set after random splitting. In that case, `get_dummies()` would create an `occupation_doctor` column in the training set but not in the testing set.

This inconsistency creates a serious problem because machine learning models expect the training and testing datasets to contain **exactly the same feature columns**.

To ensure both datasets have identical structures, we first retrieve the list of columns from each encoded DataFrame.

```python
train_cols = train_df_encoded.columns
test_cols = test_df_encoded.columns
```

Next, we identify columns that exist in the training set but are missing from the test set, and add them with default values of zero.

```python
missing_in_test = set(train_cols) - set(test_cols)

for c in missing_in_test:
    test_df_encoded[c] = 0
```

The reverse comparison is also performed to detect any columns that appear only in the testing set.

```python
missing_in_train = set(test_cols) - set(train_cols)

for c in missing_in_train:
    train_df_encoded[c] = 0
```

Finally, we reorder the columns of the test set so that they match the training set exactly.

```python
test_df_encoded = test_df_encoded[train_df_encoded.columns]

print("Encoded training set shape:", train_df_encoded.shape)
print("Encoded test set shape:", test_df_encoded.shape)
```

**Output**

```text
Encoded training set shape: (80000, 27)
Encoded test set shape: (20000, 27)
```

At this stage, both datasets contain the same **27 features** arranged in the same order. Maintaining this consistency is critical because a trained model associates each input feature with a specific learned parameter. If the feature order or feature set differs during inference, the model may produce incorrect predictions or fail entirely.

With missing values handled and categorical features successfully encoded, the dataset is now properly structured and ready for the next preprocessing stage: **scaling numerical features**.

# Scaling Numerical Features

After handling missing values and encoding categorical variables, the dataset is structurally ready for model training. However, one important preprocessing step remains: **scaling numerical features**.

Our dataset contains numerical attributes such as **age** and **rating**, each measured on a different scale. While movie ratings range from **1 to 5**, user ages range approximately from **7 to 73**. These differences in magnitude can significantly influence the behavior of many machine learning algorithms.

Algorithms that rely on **distance calculations**, such as **K-Nearest Neighbors (KNN)** and **K-Means clustering**, or those that employ **gradient-based optimization**, such as **Artificial Neural Networks**, are particularly sensitive to feature scales. If one feature has substantially larger numerical values than another, it may dominate the learning process, causing the model to assign disproportionate importance to that feature.

**Feature scaling** addresses this issue by transforming numerical features into comparable ranges, ensuring that each feature contributes more equally during model training. Proper scaling often improves convergence speed, numerical stability, and overall predictive performance.

Two of the most widely used scaling techniques are:

- **Standardization (Z-Score Scaling)**
    
- **Min-Max Normalization**
    

---

# Z-Score Scaling (Standardization)

Standardization transforms each feature so that it has:

- A **mean of zero**
    
- A **standard deviation of one**
    

For every observation, the standardized value is computed by subtracting the feature's mean and dividing by its standard deviation:

$$
z = \frac{x - \mu}{\sigma}  
$$

where:

- (x) is the original value,
    
- $(\mu)$ is the mean of the training data,
    
- $(\sigma)$ is the standard deviation of the training data.
    

This transformation preserves the overall shape of the distribution while placing all numerical features on a comparable scale.

Standardization is commonly used with algorithms that assume approximately normally distributed data or rely on distance computations, including Logistic Regression, Support Vector Machines (SVMs), Principal Component Analysis (PCA), and many neural network architectures.

To standardize the **age** feature, we use the **StandardScaler** class provided by Scikit-learn.

```python
from sklearn.preprocessing import StandardScaler

scaler_z = StandardScaler()

train_df_encoded['age_scaled_z'] = scaler_z.fit_transform(
    train_df_encoded[['age']]
)

test_df_encoded['age_scaled_z'] = scaler_z.transform(
    test_df_encoded[['age']]
)

train_df_encoded[['age', 'age_scaled_z']].head()
```

**Output**

```text
       age  age_scaled_z
75220   41      0.692357
48955   51      1.557895
44966   48      1.298234
13568   20     -1.125273
92727   17     -1.384935
```

Notice that the transformed values are no longer restricted to the original age range. Instead, they are expressed in terms of their distance from the mean, measured in standard deviations.

Positive values indicate observations above the mean, while negative values correspond to observations below the mean.

---

# Understanding `fit_transform()` and `transform()`

A common source of confusion for beginners is the distinction between the methods **`fit_transform()`** and **`transform()`**. Although their names are similar, they serve different purposes and must be used carefully to avoid introducing data leakage.

The **`fit_transform()`** method performs two operations:

1. It **learns** the required statistics from the dataset.
    
2. It immediately **applies** the transformation using those statistics.
    

For **StandardScaler**, the learned statistics are simply the **mean** and **standard deviation** of the feature.

In contrast, the **`transform()`** method does **not** compute any new statistics. Instead, it uses the parameters that were previously learned during the fitting stage.

Consequently, the correct workflow is:

```python
scaler.fit_transform(training_data)
scaler.transform(test_data)
```

and **never**

```python
scaler.fit_transform(training_data)
scaler.fit_transform(test_data)
```

Why is this distinction so important?

If the scaler is fitted separately on the test set, it gains access to information that would not be available during real-world deployment. This introduces **data leakage**, producing overly optimistic evaluation results because the preprocessing stage has inadvertently incorporated knowledge from the unseen data.

Therefore, **all preprocessing parameters must always be learned exclusively from the training set**. The same learned parameters are then reused when transforming validation or test data. This principle applies not only to scaling but also to many other preprocessing techniques, including normalization, missing value imputation, and dimensionality reduction.

# Min-Max Scaling (Normalization)

Another widely used scaling technique is **Min-Max Scaling**, often referred to simply as **Normalization**.

Instead of centering the data around zero, Min-Max Scaling maps every value into a predefined interval—most commonly **[0, 1]**.

The transformation is defined as

$$ 
x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}}  
$$

where:

- $(x_{\min})$ is the minimum value observed in the training data,
    
- $(x_{\max})$ is the maximum value observed in the training data.
    

Unlike standardization, normalization preserves the relative ordering of the data while compressing all values into the same bounded range.

This technique is particularly useful when:

- the algorithm expects inputs within a fixed range,
    
- different features have vastly different scales,
    
- the underlying data distribution is unknown.
    

However, because the transformation depends directly on the minimum and maximum values, Min-Max Scaling is generally **more sensitive to outliers** than Z-Score Scaling. A single extreme value can significantly compress the remaining observations into a narrow interval.

Using Scikit-learn, the normalization process is straightforward.

```python
from sklearn.preprocessing import MinMaxScaler

scaler_minmax = MinMaxScaler(feature_range=(0, 1))

train_df_encoded['age_scaled_minmax'] = scaler_minmax.fit_transform(
    train_df_encoded[['age']]
)

test_df_encoded['age_scaled_minmax'] = scaler_minmax.transform(
    test_df_encoded[['age']]
)

train_df_encoded[['age', 'age_scaled_minmax']].head()
```

**Output**

```text
       age  age_scaled_minmax
75220   41           0.515152
48955   51           0.666667
44966   48           0.621212
13568   20           0.196970
92727   17           0.151515
```

Notice that every transformed value now lies between **0** and **1**, making the feature compatible with algorithms that require bounded inputs or benefit from normalized feature ranges.

# Comparing Z-Score Scaling and Min-Max Scaling

To better understand the differences between these two scaling techniques, let us compare the transformed values produced by each method.

```
train_df_encoded[['age', 'age_scaled_z', 'age_scaled_minmax']].head()
```

**Output**

```
       age  age_scaled_z  age_scaled_minmax
75220   41      0.692357           0.515152
48955   51      1.557895           0.666667
44966   48      1.298234           0.621212
13568   20     -1.125273           0.196970
92727   17     -1.384935           0.151515
```

Although both techniques rescale the original feature, they produce values with very different interpretations.

With **Z-Score Scaling**, each value represents the number of standard deviations it lies above or below the mean. Consequently, standardized values are not restricted to a specific interval and may be either positive or negative.

In contrast, **Min-Max Scaling** maps every value to a predefined range—typically **0 to 1**. The smallest value in the training data becomes **0**, the largest becomes **1**, and all remaining values are proportionally scaled between these two extremes.

The following code illustrates the numerical ranges produced by each method.

```
print(f"Original age max: {train_df_encoded.age.max()}, Original age min: {train_df_encoded.age.min()}")
print(f"Scaled age with Z-Score max: {train_df_encoded.age_scaled_z.max():.2f}, Scaled age with Z-Score min: {train_df_encoded.age_scaled_z.min():.2f}")
print(f"Scaled age with MinMax max: {train_df_encoded.age_scaled_minmax.max():.2f}, Scaled age with MinMax min: {train_df_encoded.age_scaled_minmax.min():.2f}")
```

**Output**

```
Original age max: 73, Original age min: 7
Scaled age with Z-Score max: 3.46, Scaled age with Z-Score min: -2.25
Scaled age with MinMax max: 1.00, Scaled age with MinMax min: 0.00
```

The comparison highlights the fundamental difference between the two approaches:

- **Z-Score Scaling (Standardization)** centers the data around zero and scales it according to its standard deviation. It is generally preferred for algorithms that assume standardized inputs or rely on statistical properties of the data, such as Support Vector Machines, Logistic Regression, Principal Component Analysis, and many neural networks.
- **Min-Max Scaling (Normalization)** rescales data into a fixed interval, typically **[0, 1]**. It is particularly useful for algorithms that require bounded input values or operate on distance measures where preserving the relative magnitude of observations is important. However, because it depends on the minimum and maximum values, it is more sensitive to outliers than standardization.

Neither technique is universally superior; the appropriate choice depends on both the characteristics of the dataset and the requirements of the learning algorithm.
