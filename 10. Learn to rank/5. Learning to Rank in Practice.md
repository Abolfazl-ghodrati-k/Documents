In the preceding sections, we introduced Learning to Rank (LTR), examined its applications in recommender systems, studied the Pointwise, Pairwise, and Listwise learning approaches, and discussed ranking evaluation metrics such as NDCG.

We now turn to the algorithms used to implement these approaches in practical recommendation systems.

Just as LTR problems can be formulated using different learning approaches, each approach can be implemented using several machine learning algorithms. One useful way to classify LTR algorithms is according to their training objectives and the structure of the data they process.

## 5.1. Classification of Learning-to-Rank Algorithms

LTR algorithms can be broadly categorized into three groups:

1. Pointwise algorithms.
2. Pairwise algorithms.
3. Listwise algorithms.

These categories describe how the learning problem is formulated rather than specifying a particular model architecture. Consequently, related model families may appear in more than one category, depending on their training objectives.

### 5.1.1. Pointwise Algorithms

In the Pointwise approach, each user–item pair is treated as an independent training example.

The objective is to predict a relevance score for that pair.

This score may represent:

- An explicit user rating.
- The probability of a click.
- A relevance grade.
- Another numerical measure of user interest.

#### Data Representation

Each training example contains a feature vector and a target relevance label.

The general structure is:

`(User–Item Features) → Relevance Score`

For example:

`(user_id, item_id, item_category, user_age, ...) → 3.5`

This formulation corresponds to a regression problem because the target is numerical.

Alternatively:

`(user_id, item_id, ...) → Clicked`

This corresponds to a classification problem because the target is categorical.

#### Common Pointwise Algorithms

Because Pointwise ranking reduces the problem to conventional supervised learning, many standard machine learning algorithms can be used.

Examples include:

- **Linear Regression:** Predicts a continuous relevance score using a linear combination of input features.
- **Logistic Regression:** Estimates the probability of a binary outcome, such as whether a user will click an item.
- **Support Vector Machines (SVM):** Can be used for classification or regression, depending on the formulation.
- **Decision Trees:** Learn decision rules that map features to relevance predictions.
- **AdaBoost:** Combines multiple weak learners to improve predictive performance.
- **Gradient Boosting Machines (GBM):** Construct an ensemble of models that progressively reduces prediction errors.

After training, these models assign scores to candidate items, which are then sorted to produce the recommendation list.

### 5.1.2. Pairwise Algorithms

The Pairwise approach learns a function that predicts the relative preference between two items for a particular user or query.

Instead of asking:

> How relevant is this item?

The model asks:

> Is Item A more relevant than Item B for this user?

#### Data Representation

Suppose item $i$ is known to be more relevant than item $j$ for a particular user.

A Pairwise training example can be constructed by subtracting their feature vectors:

$$
\mathbf{v}_{ij}=\mathbf{x}_{i}-\mathbf{x}_{j}
$$

The resulting difference vector receives a preference label:

$$
y_{ij}=+1
$$

This label indicates that item $i$ is preferred over item $j$.

If the preference is reversed, the label becomes:

$$
y_{ij}=-1
$$

The model learns to distinguish between positive and negative preference relationships.

#### Common Pairwise Algorithms

Several important LTR algorithms use Pairwise learning principles.

**RankSVM**

RankSVM adapts the principles of Support Vector Machines to learn ranking preferences from item pairs.

**RankNet**

RankNet uses a neural network scoring function and a probabilistic Pairwise loss to learn relative preferences.

**LambdaRank**

LambdaRank extends Pairwise neural ranking by modifying the learning gradients according to the effects of item swaps on ranking metrics such as NDCG.

**LambdaMART**

LambdaMART combines LambdaRank-style gradient signals with Multiple Additive Regression Trees (MART), a form of gradient-boosted decision trees.

Although LambdaMART uses Pairwise comparisons to construct its gradient signals, its objective is closely associated with optimizing list-level ranking quality.

### 5.1.3. Listwise Algorithms

The Listwise approach considers an entire group of candidate items associated with a particular user or query.

Its objective is to learn an ordering that optimizes the quality of the ranked list.

Unlike Pointwise methods, which optimize individual predictions, and Pairwise methods, which optimize relative preferences, Listwise methods construct training objectives that depend on the ranking group as a whole.

#### Data Representation

Each training example consists of a query or user together with a collection of candidate items and their relevance labels.

For example:

`User u → [(Item A, 4), (Item B, 1), (Item C, 3), ...]`

The model uses the relevance labels to learn the appropriate ordering of the candidates.

#### Common Listwise Algorithms

**ListNet**

ListNet uses probability distributions derived from item scores to construct a Listwise learning objective.

**LambdaRank**

LambdaRank uses ranking-metric-aware gradient adjustments and is often discussed in connection with Listwise optimization, although its underlying comparisons are Pairwise.

**LambdaMART**

LambdaMART is one of the most widely used tree-based LTR algorithms.

It combines gradient-boosted decision trees with LambdaRank-inspired gradient signals to improve ranking metrics such as NDCG.

Rather than directly differentiating NDCG, which is not differentiable with respect to predicted scores, LambdaMART uses surrogate gradients designed to reflect changes in ranking quality.

This makes it particularly suitable for practical ranking applications.

## 5.2. RankSVM: Learning to Rank with Support Vector Machines

**RankSVM** is one of the foundational algorithms in Learning to Rank.

It extends the principles of Support Vector Machines to solve ranking problems through Pairwise preference comparisons.

Although standard SVM models can be used in Pointwise classification or regression pipelines, RankSVM itself is primarily a Pairwise ranking method.

Its objective is to learn a function capable of answering:

> For a particular user, should Item A be ranked above Item B?

RankSVM transforms ranking preferences into a supervised learning problem involving differences between feature vectors.

The algorithm can be understood through three main stages:

1. Constructing training pairs.
2. Training the ranking model.
3. Ranking previously unseen items.

### 5.2.1. Stage One: Constructing Training Pairs

Before training RankSVM, historical user interactions must be transformed into Pairwise preference examples.

Suppose a user has interacted with two movies:

- **Movie A:** The user watched the movie to completion.
- **Movie B:** The user stopped watching after a few minutes.

From these observations, we may infer that Movie A is more relevant to this user than Movie B.

This provides the preference relationship:

$$
A\succ B
$$

Here, the relation indicates that Movie A is preferred over Movie B.

The corresponding training pair is:

`(Movie A, Movie B)`

#### Constructing Difference Vectors

RankSVM does not simply concatenate the features of both items.

In its standard linear formulation, it constructs a difference vector:

$$
\mathbf{v}_{AB}=\mathbf{x}_{A}-\mathbf{x}_{B}
$$

Where:

- $\mathbf{x}_{A}$ is the feature vector of Movie A.
- $\mathbf{x}_{B}$ is the feature vector of Movie B.
- $\mathbf{v}_{AB}$ is the difference between the two feature vectors.

The resulting vector receives the label:

$$
y_{AB}=+1
$$

This indicates that Movie A is preferred over Movie B.

If the preference were reversed, the corresponding difference vector could receive the label $-1$.

This procedure is repeated for many observed preference relationships.

The resulting training dataset contains difference vectors and their associated preference labels.

### 5.2.2. Stage Two: Training the SVM Model

After constructing the training pairs, the ranking problem can be formulated as a binary classification problem.

The training examples are difference vectors labeled according to their preference direction.

A linear Support Vector Machine attempts to learn a separating hyperplane that distinguishes the two preference classes.

#### The SVM Decision Boundary

A Support Vector Machine learns a decision boundary that separates observations belonging to different classes.

In two dimensions, this boundary is a line.

In three dimensions, it is a plane.

In higher-dimensional spaces, it is called a **hyperplane**.

The SVM attempts to find a separating hyperplane with a large margin between the classes.

For RankSVM, the decision function can be expressed as:

$$
f(\mathbf{v})=\mathbf{w}^{T}\mathbf{v}
$$

Where:

- $\mathbf{v}$ is the difference vector between two items.
- $\mathbf{w}$ is the learned weight vector.

For a pair of items $A$ and $B$:

$$
f(\mathbf{v}_{AB})=\mathbf{w}^{T}(\mathbf{x}_{A}-\mathbf{x}_{B})
$$

The sign of this value determines the predicted preference.

If:

$$
f(\mathbf{v}_{AB})>0
$$

The model predicts that Movie A should be ranked above Movie B.

If:

$$
f(\mathbf{v}_{AB})<0
$$

The model predicts that Movie B should be ranked above Movie A.

Thus, the learned hyperplane provides a mechanism for predicting relative preferences.

#### The RankSVM Optimization Objective

A common linear RankSVM formulation learns a weight vector by minimizing:

$$
\frac{1}{2}\lVert\mathbf{w}\rVert^{2}+C\sum_{(i,j)\in P}\xi_{ij}
$$

Subject to:

$$
\mathbf{w}^{T}(\mathbf{x}_{i}-\mathbf{x}_{j})\ge 1-\xi_{ij}
$$

And:

$$
\xi_{ij}\ge 0
$$

Where:

- $P$ is the set of training pairs in which item $i$ is preferred over item $j$.
- $\mathbf{w}$ is the learned ranking weight vector.
- $\xi_{ij}$ is a slack variable allowing violations of the desired margin.
- $C$ controls the trade-off between margin maximization and training errors.

The objective encourages the model to assign higher scores to preferred items while controlling model complexity.

### 5.2.3. Stage Three: Ranking New Items

After training, RankSVM produces a weight vector that can be used to assign a score to each candidate item.

For a linear RankSVM model, the score is calculated as:

$$
Score(i)=\mathbf{w}^{T}\mathbf{x}_{i}
$$

Where:

- $\mathbf{w}$ is the learned weight vector.
- $\mathbf{x}_{i}$ is the feature vector of candidate item $i$.

To rank a collection of new items:

1. Extract the feature vector for each candidate.
2. Calculate the score of each candidate using the learned weight vector.
3. Sort the candidates in descending order of their scores.

The item receiving the highest score is placed at the beginning of the recommendation list.

Although RankSVM is trained using Pairwise comparisons, its linear scoring function allows individual items to be ranked efficiently at prediction time.

## 5.3. Practical Example: Movie Recommendation with RankSVM

Consider a movie recommendation system designed to generate personalized recommendations for a user named Sarah.

Sarah is particularly interested in science-fiction and action movies.

We want to use RankSVM to rank three previously unseen movies according to her preferences.

### 5.3.1. Defining the Features

For simplicity, assume that each movie is represented by three numerical features.

**Feature 1: Genre Match**

A value between 0 and 10 indicating how closely the movie's genre matches Sarah's preferences.

**Feature 2: Critics' Rating**

A numerical rating between 1 and 10 representing the movie's critical reception.

**Feature 3: Global Popularity**

A value between 0 and 1 representing the movie's overall popularity.

The feature vector for each movie is:

$$
\mathbf{x}=(x_{1},x_{2},x_{3})
$$

Where:

- $x_{1}$ is genre match.
- $x_{2}$ is critics' rating.
- $x_{3}$ is global popularity.

### 5.3.2. Historical Training Data

Suppose Sarah has previously interacted with three movies:

| Movie | Genre Match | Critics' Rating | Popularity | Sarah's Preference |
|---|---:|---:|---:|---|
| Inception | 9 | 9.0 | 0.90 | High |
| The Dark Knight | 8 | 9.5 | 0.95 | Medium |
| La La Land | 2 | 8.0 | 0.80 | Low |

For convenience, denote these movies as:

- $A$: Inception.
- $B$: The Dark Knight.
- $C$: La La Land.

Based on Sarah's historical preferences, we infer:

$$
A\succ B
$$

$$
A\succ C
$$

$$
B\succ C
$$

These relationships provide three positive preference pairs.

### 5.3.3. Constructing Pairwise Difference Vectors

We now calculate the feature differences for each preference pair.

#### Pair 1: Inception Versus The Dark Knight

The feature vectors are:

$$
\mathbf{x}_{A}=(9,9,0.9)
$$

$$
\mathbf{x}_{B}=(8,9.5,0.95)
$$

Their difference is:

$$
\mathbf{v}_{AB}=\mathbf{x}_{A}-\mathbf{x}_{B}=(1,-0.5,-0.05)
$$

Because Sarah prefers Inception, the training label is $+1$.

#### Pair 2: Inception Versus La La Land

The feature vector for La La Land is:

$$
\mathbf{x}_{C}=(2,8,0.8)
$$

The difference vector is:

$$
\mathbf{v}_{AC}=\mathbf{x}_{A}-\mathbf{x}_{C}=(7,1,0.1)
$$

The training label is $+1$.

#### Pair 3: The Dark Knight Versus La La Land

The difference vector is:

$$
\mathbf{v}_{BC}=\mathbf{x}_{B}-\mathbf{x}_{C}=(6,1.5,0.15)
$$

The training label is $+1$.

The resulting training examples are:

| Preference Pair | Difference Vector | Label |
|---|---|---:|
| A preferred over B | (1, -0.5, -0.05) | +1 |
| A preferred over C | (7, 1, 0.1) | +1 |
| B preferred over C | (6, 1.5, 0.15) | +1 |

These difference vectors express Sarah's relative preferences through numerical feature comparisons.

In a practical implementation, reverse pairs may also be included to provide examples of both preference directions.

### 5.3.4. Learning the Ranking Weights

RankSVM uses the training pairs to learn a weight vector:

$$
\mathbf{w}=(w_{1},w_{2},w_{3})
$$

The model attempts to find weights that satisfy the observed preference relationships.

For example:

$$
\mathbf{w}^{T}\mathbf{v}_{AB}>0
$$

$$
\mathbf{w}^{T}\mathbf{v}_{AC}>0
$$

$$
\mathbf{w}^{T}\mathbf{v}_{BC}>0
$$

The weights are learned during model training rather than manually specified.

For illustration, suppose the trained model produces:

$$
\mathbf{w}=(0.7,0.2,0.1)
$$

These weights indicate that, under the chosen feature scales, genre match contributes more strongly to the predicted ranking score than critics' rating or global popularity.

Specifically:

- Genre match has a weight of 0.7.
- Critics' rating has a weight of 0.2.
- Global popularity has a weight of 0.1.

Because feature scales differ, raw coefficient magnitudes should be interpreted cautiously. Feature normalization may be necessary before comparing their relative importance.

### 5.3.5. Ranking New Movies

Suppose we now want to recommend three new movies to Sarah.

Their features are:

| Movie | Genre Match | Critics' Rating | Popularity |
|---|---:|---:|---:|
| Dune | 10 | 8.5 | 0.85 |
| Oppenheimer | 5 | 9.0 | 0.90 |
| Tenet | 9 | 7.5 | 0.80 |

The ranking score is calculated using:

$$
Score(i)=\mathbf{w}^{T}\mathbf{x}_{i}
$$

Substituting the illustrative weight vector:

$$
Score(i)=0.7x_{1}+0.2x_{2}+0.1x_{3}
$$

#### Calculating the Score for Dune

Dune has the feature vector:

$$
\mathbf{x}_{Dune}=(10,8.5,0.85)
$$

Therefore:

$$
Score(Dune)=0.7(10)+0.2(8.5)+0.1(0.85)
$$

$$
Score(Dune)=7+1.7+0.085=8.785
$$

#### Calculating the Score for Oppenheimer

Oppenheimer has the feature vector:

$$
\mathbf{x}_{Oppenheimer}=(5,9,0.9)
$$

Therefore:

$$
Score(Oppenheimer)=0.7(5)+0.2(9)+0.1(0.9)
$$

$$
Score(Oppenheimer)=3.5+1.8+0.09=5.39
$$

#### Calculating the Score for Tenet

Tenet has the feature vector:

$$
\mathbf{x}_{Tenet}=(9,7.5,0.8)
$$

Therefore:

$$
Score(Tenet)=0.7(9)+0.2(7.5)+0.1(0.8)
$$

$$
Score(Tenet)=6.3+1.5+0.08=7.88
$$

### 5.3.6. Final Recommendation Ranking

The calculated scores are:

| Movie | Calculation | Final Score |
|---|---|---:|
| Dune | 7 + 1.7 + 0.085 | 8.785 |
| Oppenheimer | 3.5 + 1.8 + 0.09 | 5.390 |
| Tenet | 6.3 + 1.5 + 0.08 | 7.880 |

Sorting the movies by their predicted scores produces the following recommendation list:

| Rank | Movie | Ranking Score |
|---:|---|---:|
| 1 | Dune | 8.785 |
| 2 | Tenet | 7.880 |
| 3 | Oppenheimer | 5.390 |

The final ordering is:

**Dune > Tenet > Oppenheimer**

Although Oppenheimer has higher critics' ratings and global popularity than Tenet, Tenet receives a higher personalized ranking score.

The reason is that Tenet has a substantially stronger genre match with Sarah's preferences.

Because the illustrative model assigns a relatively large weight to genre match, this feature has a strong influence on the final ranking.

This example demonstrates an important characteristic of personalized ranking: **the most appropriate recommendation is not necessarily the item with the highest global rating or popularity, but the item whose features best match the preferences of the target user.**

RankSVM provides a practical non-neural approach to Pairwise Learning to Rank, particularly when a linear ranking function is appropriate and meaningful preference pairs can be constructed from historical interactions.
