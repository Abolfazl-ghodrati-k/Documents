In the previous section, we examined how to prepare training data and construct meaningful feature vectors for Learning to Rank (LTR). We learned how raw user interactions can be transformed into representations containing user, item, and contextual features.

The next question is how an LTR model uses these features to learn an effective ranking.

There is no single solution to this problem. Instead, Learning to Rank encompasses three principal approaches, each of which formulates the ranking task differently:

1. **Pointwise Approach:** Predicting the relevance of individual items.
2. **Pairwise Approach:** Learning relative preferences between pairs of items.
3. **Listwise Approach:** Optimizing the quality of an entire ranked list.

These approaches differ in their training examples, objective functions, computational requirements, and relationship to the final ranking objective.

## 3.1. Pointwise Approach: Focusing on Individual Predictions

The **Pointwise Approach** is the simplest and most intuitive formulation of Learning to Rank.

Its central principle is to treat each item independently, without explicitly considering its position relative to other items in the same recommendation list.

The model attempts to answer the following question:

> What is the relevance score or relevance label of this particular item?

In this approach, the ranking problem is reduced to a conventional supervised learning problem, typically regression or classification.

### 3.1.1. How Pointwise Learning Works

During training, the model processes individual query–item examples.

Each example contains a feature vector and a corresponding relevance label.

The objective is to predict the relevance label as accurately as possible.

If the labels are numerical ratings, the task can be formulated as regression.

If the labels represent discrete relevance categories, such as relevant and irrelevant, the task can be formulated as classification.

For example, suppose a user assigns a movie a rating of 5. The model receives features describing the user, the movie, and their relationship, and attempts to predict a value close to 5.

The prediction error is calculated by comparing the predicted value with the observed relevance label.

For regression, a common objective is Mean Squared Error (MSE):

$$
L_{\text{pointwise}}=\frac{1}{N}\sum_{i=1}^{N}(y_{i}-\hat{y}_{i})^{2}
$$

Where:

- $N$ is the number of training examples.
- $y_{i}$ is the observed relevance label.
- $\hat{y}_{i}$ is the model's predicted relevance score.

For binary relevance labels, a classification loss such as binary cross-entropy may be used instead.

After training, the model predicts a score for every candidate item. The items are then sorted in descending order of their predicted scores.

### 3.1.2. Training Data Structure

In the Pointwise Approach, each user–item interaction is represented as an independent training example.

Each example contains two principal components:

**Feature Vector**

A numerical representation containing user features, item features, and interaction features.

**Target Label**

A value representing the relevance of the item.

The target may be:

- An explicit rating, such as 3 out of 5.
- A binary label, such as 1 for a click and 0 for no click.
- A numerical relevance value or probability estimate.

Consider the following movie recommendation dataset:

| user_id | item_id | user_age | item_is_action | similarity_score | relevance_score |
|---|---|---:|---:|---:|---:|
| u-101 | m-55 | 25 | 1 | 0.91 | 5 |
| u-101 | m-82 | 25 | 0 | 0.65 | 3 |
| u-240 | m-55 | 52 | 1 | 0.30 | 1 |

The columns have the following meanings:

- `user_id`: Identifies the user.
- `item_id`: Identifies the movie.
- `user_age`: Represents the user's age.
- `item_is_action`: Indicates whether the movie belongs to the action genre.
- `similarity_score`: Measures the similarity between the user and the movie.
- `relevance_score`: Contains the target relevance label.

The relevance score may originate from an explicit rating or from a relevance value derived from implicit feedback, such as completing a movie.

For the first row, the model receives the feature vector:

`[25, 1, 0.91]`

Its objective is to predict a relevance score close to 5.

Each row is treated as an independent regression or classification example.

### 3.1.3. Pointwise Learning in Recommender Systems

Suppose we want to develop a movie recommendation model for Netflix and have access to explicit user ratings ranging from 1 to 5 stars.

The objective is to predict the rating that a particular user would assign to a movie they have not yet watched.

The training procedure is as follows:

1. Construct a feature vector for every observed user–movie interaction.
2. Use the user's actual rating as the target label.
3. Train a regression model, such as `RandomForestRegressor`, on these examples.
4. During recommendation, predict the rating for each candidate movie.
5. Sort the candidate movies according to their predicted ratings.

The resulting ordered list becomes the recommendation output.

Matrix Factorization, as studied in earlier chapters, is also commonly trained using a Pointwise objective.

For example, when matrix factorization minimizes the squared error between observed and predicted user–item ratings, it learns to predict individual interaction values rather than directly optimizing the relative ordering of items.

However, matrix factorization is not inherently restricted to Pointwise learning. The same latent-factor model can also be trained using Pairwise ranking objectives.

### 3.1.4. Advantages of the Pointwise Approach

**Simplicity**

Pointwise learning is straightforward to implement because it can use standard regression and classification algorithms.

There is no need to construct item pairs or explicitly process complete ranking lists during training.

**Computational Efficiency**

Training can be relatively efficient because individual examples can be processed independently.

The approach is often practical when computational resources or training data are limited.

**Compatibility with Existing Models**

Many conventional machine learning algorithms can be adapted to Pointwise ranking with minimal modifications.

### 3.1.5. Limitations of the Pointwise Approach

The principal limitation is that **Pointwise learning does not explicitly optimize ranking quality**.

Its objective is to predict relevance labels accurately, not necessarily to produce the best ordering.

As demonstrated in the previous section, a model with a lower rating prediction error may still generate an inferior ranking.

Another limitation is that conventional Pointwise loss functions generally do not distinguish between errors occurring at different ranking positions.

For example, incorrectly exchanging the first and second items may be substantially more important than exchanging the tenth and eleventh items.

However, a standard Pointwise loss function does not directly account for this positional difference.

The model is therefore largely unaware of the structure and quality of the final ranked list.

## 3.2. Pairwise Approach: Learning Relative Preferences

The **Pairwise Approach** addresses a central weakness of Pointwise learning by explicitly modeling the relative ordering of items.

Its fundamental principle is that ranking is a relative task.

Instead of predicting the exact relevance score of an item, the model learns whether one item should be ranked above another.

The central question becomes:

> For a particular query or user, is Item A more relevant than Item B?

### 3.2.1. How Pairwise Learning Works

During training, the model considers pairs of items associated with the same query or user.

Each pair contains two items with a known or inferred preference relationship.

For example, if a user prefers Item A over Item B, the model should learn to assign Item A a higher score.

Let $f(u,i)$ represent the predicted relevance score of item $i$ for user $u$.

If item $i$ is preferred over item $j$, the desired relationship is:

$$
f(u,i)>f(u,j)
$$

Equivalently, the score difference should be positive:

$$
f(u,i)-f(u,j)>0
$$

A ranking error occurs when the model assigns a higher score to the less-preferred item.

The learning objective penalizes such violations and encourages the correct relative ordering.

Pairwise learning can therefore be formulated as a collection of binary preference comparisons.

An intuitive analogy is a tennis tournament.

Instead of estimating an absolute skill score for every player, we observe the outcomes of matches between pairs of players.

The objective is to infer a ranking from these relative comparisons.

Similarly, Pairwise LTR learns item preferences through comparisons rather than relying exclusively on absolute relevance predictions.

### 3.2.2. Training Data Structure

The fundamental training unit in Pairwise learning is a pair of items associated with the same user or query.

A training example typically contains:

- A user or query identifier.
- A preferred item.
- A less-preferred item.
- Features describing both items in the corresponding context.

A preference label may also be included.

For example:

- `+1`: The first item is preferred over the second.
- `-1`: The second item is preferred over the first.

Consider the following e-commerce dataset:

| user_id | positive_item_id | negative_item_id |
|---|---|---|
| u-101 | p-123 (iPhone 15) | p-456 (Samsung S23) |
| u-101 | p-789 (Dell Laptop) | p-780 (Acer Laptop) |
| u-202 | p-333 (Coffee Maker) | p-999 (Electric Kettle) |

Here:

- `user_id` identifies the user.
- `positive_item_id` identifies the item that the user preferred.
- `negative_item_id` identifies the less-preferred item.

A positive item may be a product the user purchased or added to their shopping cart.

A negative item may be a product the user viewed but did not purchase, or an item they ignored.

However, non-interaction does not necessarily indicate dislike. Negative examples derived from implicit feedback should therefore be interpreted as weaker preference signals rather than definitive negative judgments.

### 3.2.3. Learning the Scoring Function

Unlike Pointwise learning, the target is not necessarily an explicit numerical relevance score.

Instead, the model learns a scoring function that satisfies preference constraints.

For the first row of the dataset, the desired relationship is:

$$
f(u\text{-}101,\text{iPhone 15})>f(u\text{-}101,\text{Samsung S23})
$$

The model is trained to increase the score of the preferred item relative to the less-preferred item.

A loss function penalizes the model when the desired ordering is violated or insufficiently supported.

After training, the scoring function can be applied to individual candidate items, and the resulting scores can be used to construct the final ranking.

### 3.2.4. Pairwise Learning in Recommender Systems

Suppose an e-commerce platform wants to rank products according to their likelihood of being purchased.

The objective is to place products that users are more likely to purchase above products that attract weaker interest.

A possible training procedure is:

1. Extract user interaction histories.
2. Construct triplets containing a user, a purchased product, and a viewed but unpurchased product.
3. Convert each triplet into a Pairwise training example.
4. Train the model to assign higher scores to purchased products.
5. Use the learned scoring function to rank candidate products.

One of the best-known algorithms based on this principle is **Bayesian Personalized Ranking (BPR)**.

## 3.3. Bayesian Personalized Ranking (BPR)

**Bayesian Personalized Ranking** is a Pairwise learning framework designed primarily for personalized recommendation using implicit feedback.

Rather than predicting exact ratings, BPR learns preference relationships between items.

Its central question is:

> If a user has shown greater interest in Item A than Item B, how can the model learn to predict this preference for future recommendations?

### 3.3.1. The Preference-Based Interpretation

Consider a music recommendation system.

Suppose a user has:

- Liked Song A.
- Explicitly skipped or rejected Song B.
- Listened to Song A but never interacted with Song C.

The first observation provides relatively direct evidence that Song A is preferred over Song B.

The second may also be used to construct a preference relationship between Song A and Song C, although the absence of an interaction with Song C does not necessarily indicate dislike.

BPR commonly assumes that observed positive interactions should receive higher predicted scores than sampled unobserved interactions.

This allows the model to learn from implicit-feedback datasets where explicit negative labels are often unavailable.

### 3.3.2. User and Item Latent Vectors

BPR requires an underlying model capable of assigning a score to each user–item pair.

One common implementation uses Matrix Factorization.

Let:

- $\mathbf{p}_{u}$ be the latent vector representing user $u$.
- $\mathbf{q}_{i}$ be the latent vector representing item $i$.

A simple scoring function is the dot product:

$$
Score(u,i)=\mathbf{p}_{u}^{T}\mathbf{q}_{i}
$$

The dot product measures the alignment between the user's latent preferences and the item's latent characteristics.

A larger score indicates a stronger predicted preference according to the learned model.

Unlike cosine similarity, the dot product also depends on vector magnitudes.

The objective of BPR is to learn user and item representations that produce the desired relative ordering.

### 3.3.3. Pairwise Preference Constraints

For each user $u$, consider:

- A positive item $i$.
- A sampled negative or unobserved item $j$.

The desired relationship is:

$$
Score(u,i)>Score(u,j)
$$

Therefore:

$$
Score(u,i)-Score(u,j)>0
$$

Define the score difference as:

$$
\Delta_{uij}=Score(u,i)-Score(u,j)
$$

The model should learn parameters that make this difference positive for observed preference triplets.

### 3.3.4. The Sigmoid Function

BPR uses the sigmoid function to transform the score difference into a value between 0 and 1.

The sigmoid function is defined as:

$$
\sigma(x)=\frac{1}{1+e^{-x}}
$$

Applying it to the score difference gives:

$$
\sigma(\Delta_{uij})=\frac{1}{1+e^{-\Delta_{uij}}}
$$

This value can be interpreted within the BPR model as the probability that user $u$ prefers item $i$ over item $j$.

If the score of the positive item is much greater than the score of the negative item, the sigmoid output approaches 1.

If both items receive similar scores, the output approaches 0.5.

If the negative item receives a substantially higher score, the output approaches 0.

### 3.3.5. BPR Loss Function

BPR optimizes a loss function designed to encourage correct Pairwise preferences.

For a collection of training triplets $D$, the regularized BPR loss can be written as:

$$
L_{\text{BPR}}=-\sum_{(u,i,j)\in D}\ln\left(\sigma(Score(u,i)-Score(u,j))\right)+\lambda\lVert\Theta\rVert^{2}
$$

Where:

- $D$ is the set of training triplets.
- $u$ represents a user.
- $i$ represents a positive item.
- $j$ represents a negative or unobserved item.
- $\sigma$ is the sigmoid function.
- $\Theta$ represents the model parameters.
- $\lambda$ controls the strength of regularization.

The first term penalizes preference violations.

If the positive item receives a much higher score than the negative item, the corresponding loss becomes small.

If the model assigns similar scores to both items, or ranks the negative item higher, the loss increases.

The regularization term discourages excessively large parameter values and can help reduce overfitting.

The model parameters can be optimized using gradient-based methods, such as Stochastic Gradient Descent.

### 3.3.6. Advantages of the Pairwise Approach

**Direct Modeling of Relative Preferences**

Pairwise learning is more closely aligned with the ranking task than conventional Pointwise regression because it explicitly models which items should appear ahead of others.

**Suitability for Implicit Feedback**

Pairwise methods can learn from observed and unobserved interactions without requiring precise numerical ratings.

**Flexibility**

Pairwise ranking objectives can be combined with different scoring models, including latent-factor models and neural networks.

### 3.3.7. Limitations of the Pairwise Approach

**Limited Awareness of Ranking Positions**

A conventional Pairwise objective focuses on whether one item is ranked above another.

It does not necessarily distinguish between errors occurring near the top and bottom of the recommendation list.

For example, exchanging the first and second items may be treated similarly to exchanging the twentieth and twenty-first items.

However, errors near the top of a ranking are often more consequential because users pay greater attention to those positions.

Some advanced Pairwise methods address this limitation by weighting comparisons according to their expected effect on ranking metrics.

**Computational Complexity**

For a candidate list containing $N$ items, the number of distinct unordered item pairs is:

$$
\frac{N(N-1)}{2}
$$

Consequently, the number of possible comparisons grows quadratically with the number of candidates.

Generating and processing all possible pairs can therefore become computationally expensive.

In practice, Pairwise methods often use sampling strategies to reduce training costs.

## 3.4. Listwise Approach: Optimizing the Entire Ranked List

The **Listwise Approach** treats ranking as a problem involving an entire collection of candidate items.

Its central principle is that ranking quality depends on the ordering of the complete list rather than only on individual predictions or isolated item pairs.

The fundamental question becomes:

> What is the best possible ordering of all candidate items for this query or user?

Unlike Pointwise learning, which processes individual examples, and Pairwise learning, which compares pairs of items, Listwise learning considers groups of candidates when constructing its training objective.

### 3.4.1. How Listwise Learning Works

During training, the model considers the candidate items associated with a particular query.

The objective is to learn an ordering that reflects the relevance relationships among those items.

Listwise methods use loss functions that depend on the ranked list as a whole.

Some methods model probability distributions over rankings, while others use differentiable approximations or surrogate objectives related to ranking metrics.

Examples of ranking metrics include:

- Normalized Discounted Cumulative Gain (NDCG).
- Mean Average Precision (MAP).

These metrics evaluate ranking quality while accounting for the placement of relevant items.

In particular, NDCG assigns greater importance to highly relevant items appearing near the beginning of the list.

Because ranking operations and many ranking metrics are not directly differentiable, practical Listwise algorithms often optimize surrogate losses rather than the exact evaluation metric.

### 3.4.2. An Intuitive Analogy

Consider a gymnastics competition.

A Pointwise approach would attempt to predict an absolute score for each gymnast independently.

A Pairwise approach would compare gymnasts two at a time to determine which one should rank higher.

A Listwise approach would evaluate the complete group of competitors and learn an ordering that best reflects their relative performance.

The distinction is not whether the model produces numerical scores.

All three approaches may use scoring functions.

The important difference is **how the model is trained and which objective its loss function attempts to optimize**.

In Pointwise learning, the model focuses on the accuracy of individual predictions.

In Listwise learning, the model considers how predicted scores collectively determine the ordering of an entire group.

Another analogy involves student rankings.

A Pointwise objective might encourage a model to predict each student's examination score as accurately as possible.

A Listwise objective would instead focus on identifying the correct ordering of students.

A student may rank first with a score of 85 if every other student scores lower.

Conversely, a score of 95 may be insufficient for first place if another student scores 100.

Thus, absolute scores and relative rankings are related but distinct objectives.

### 3.4.3. Training Data Structure

In Listwise learning, the fundamental training unit is a collection of candidate items associated with the same query.

The dataset must therefore preserve information identifying which items belong to each ranking group.

Consider the following dataset containing three recommendation lists for three users.

| query_id | item_id | user_age | item_is_action | similarity_score | relevance_score |
|---|---|---:|---:|---:|---:|
| q-1 | m-55 | 25 | 1 | 0.91 | 5 |
| q-1 | m-82 | 25 | 0 | 0.65 | 3 |
| q-1 | m-99 | 25 | 0 | 0.20 | 1 |
| q-2 | m-10 | 41 | 0 | 0.85 | 4 |
| q-2 | m-15 | 41 | 1 | 0.40 | 2 |
| q-3 | m-55 | 30 | 1 | 0.45 | 2 |
| q-3 | m-82 | 30 | 0 | 0.15 | 1 |
| q-3 | m-77 | 30 | 1 | 0.95 | 5 |

The columns have the following meanings:

**`query_id`**

Identifies the ranking request.

All rows sharing the same query identifier belong to the same ranking group.

The dataset contains three ranking groups:

- `q-1`
- `q-2`
- `q-3`

**`item_id`**

Identifies each candidate movie.

**Feature Columns**

The columns `user_age`, `item_is_action`, and `similarity_score` provide information about the user, item, and their relationship.

**`relevance_score`**

Contains the observed relevance label for each item.

These labels define the desired ordering within each ranking group.

### 3.4.4. Learning from Complete Ranking Groups

Unlike Pointwise learning, Listwise learning does not treat every row as an independent training objective.

Instead, the loss function considers the items belonging to the same ranking group.

For query `q-1`, the relevance labels are:

| Item | Relevance |
|---|---:|
| m-55 | 5 |
| m-82 | 3 |
| m-99 | 1 |

The ideal ordering is:

`m-55 > m-82 > m-99`

For query `q-3`, the relevance labels are:

| Item | Relevance |
|---|---:|
| m-55 | 2 |
| m-82 | 1 |
| m-77 | 5 |

The ideal ordering is:

`m-77 > m-55 > m-82`

The model learns to produce rankings that approach these ideal orderings.

The loss function evaluates predictions using relationships among multiple items within the same group.

This enables Listwise methods to account for properties of the complete ranking that cannot be represented by independent prediction errors alone.

### 3.4.5. Optimizing Ranking Metrics

One of the principal motivations for Listwise learning is to align the training objective more closely with the final evaluation criterion.

For example, a recommender system may be evaluated using NDCG.

NDCG rewards rankings that place highly relevant items near the top.

A Listwise training objective can be designed to approximate the optimization of this metric.

This is important because conventional losses such as MSE do not explicitly account for ranking positions.

However, not every Listwise algorithm directly optimizes NDCG or MAP.

Different Listwise methods use different objective functions, and the degree of alignment between the training loss and the evaluation metric varies across algorithms.

### 3.4.6. Listwise Learning in Recommender Systems

Suppose we want to optimize the **Recommended for You** section on an e-commerce home page.

The system has already retrieved 20 candidate products for a user.

The objective is to arrange these products so that the most relevant ones receive prominent positions.

A Listwise training procedure may involve:

1. Constructing ranking groups containing the candidate products and their features.
2. Providing relevance labels derived from historical user interactions.
3. Training a Listwise model using an objective that evaluates the ordering of candidates within each group.
4. Learning a scoring function that produces high-quality rankings.
5. Applying the trained model to new candidate lists.

For example, a Listwise model trained with an NDCG-oriented objective may learn to place highly relevant products near the beginning of the recommendation list.

It is also possible to incorporate diversity and other list-level considerations into recommendation optimization.

However, standard NDCG does not explicitly reward category diversity. To optimize diversity, the system must introduce an appropriate diversity-aware objective, constraint, or re-ranking mechanism.

### 3.4.7. Advantages of the Listwise Approach

**Closer Alignment with Ranking Objectives**

Listwise methods can incorporate properties of the complete ranked list into their training objectives.

This makes them particularly suitable when final evaluation depends on ranking metrics.

**Awareness of Relative Positions**

Listwise objectives can account for the greater importance of placing highly relevant items near the top of a recommendation list.

**Potentially Higher Ranking Quality**

When sufficient training data and suitable objectives are available, Listwise methods can achieve strong ranking performance.

However, their superiority over Pointwise and Pairwise methods is not guaranteed for every dataset or application.

### 3.4.8. Limitations of the Listwise Approach

**Greater Implementation Complexity**

Listwise objectives are generally more complex than conventional regression or classification losses.

**Computational Requirements**

Processing ranking groups and optimizing list-dependent objectives may require additional computation and memory.

**Training Data Requirements**

Listwise learning requires appropriately organized ranking groups and informative relevance labels.

The quality and completeness of these labels strongly influence model performance.

## 3.5. Comparison of Learning-to-Rank Approaches

The three approaches can be compared according to their training units, objectives, applications, advantages, and limitations.

| Characteristic | Pointwise | Pairwise | Listwise |
|---|---|---|---|
| **Training unit** | Individual item | Pair of items | Group or list of items |
| **Central question** | What is this item's relevance score? | Which item is more relevant? | What is the best ordering of the list? |
| **Learning objective** | Predict relevance labels | Learn relative preferences | Optimize a list-dependent ranking objective |
| **Recommendation example** | Rating prediction using Matrix Factorization | Comparing observed and unobserved interactions using BPR | Optimizing recommendation lists using NDCG-oriented objectives |
| **Main advantage** | Simplicity and efficiency | Direct modeling of relative preferences | Closer alignment with list-level ranking quality |
| **Main limitation** | Does not explicitly optimize ordering | Conventional objectives may ignore ranking positions | Greater complexity and computational cost |

### 3.5.1. Choosing an Appropriate Approach

The choice between Pointwise, Pairwise, and Listwise learning depends on the available data, computational resources, and desired ranking objective.

**When to Use Pointwise Learning**

Pointwise learning is a practical choice when:

- Explicit relevance labels or ratings are available.
- A straightforward regression or classification formulation is sufficient.
- Simplicity and computational efficiency are important.
- Individual relevance estimates are useful beyond the ranking task itself.

For example, a movie recommendation system with explicit star ratings may use Pointwise regression to predict ratings and sort candidate movies accordingly.

**When to Use Pairwise Learning**

Pairwise learning is particularly useful when:

- Relative preferences are more reliable than absolute relevance scores.
- Implicit feedback is the primary source of training information.
- The objective is to rank observed positive interactions above sampled negative examples.
- Preference comparisons can be constructed from historical behavior.

For example, BPR can learn to rank songs a user has listened to above songs with which the user has not interacted.

**When to Use Listwise Learning**

Listwise learning is appropriate when:

- The final objective is explicitly related to ranking quality.
- Candidate items can be organized into meaningful ranking groups.
- Relevance labels are available for evaluating the ordering of multiple candidates.
- The system aims to optimize metrics such as NDCG.

For example, an e-commerce platform may use a Listwise ranking model to improve the ordering of products displayed on its home page.

### 3.5.2. Combining Ranking Approaches

In practice, modern recommendation systems do not necessarily rely on a single learning approach throughout the entire pipeline.

Different stages may use different objectives.

For example, an e-commerce recommendation system might:

1. Use a Pointwise model to estimate the relevance or purchase probability of individual items.
2. Use Pairwise learning to improve relative preference predictions.
3. Use a Listwise objective or re-ranking stage to improve the final ordering of recommendations.

These approaches can therefore complement one another.

The appropriate strategy depends on the trade-off between model simplicity, computational efficiency, data availability, and alignment with the final ranking objective.
