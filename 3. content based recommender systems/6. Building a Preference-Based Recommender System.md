For this purpose, we define a preprocessing function:

```python
stop_words = set(stopwords.words('english'))
stemmer = PorterStemmer()

def preprocess(text):
    text = text.lower()  # Convert all characters to lowercase
    text = re.sub(r'[^a-z\s]', ' ', text)  # Remove non-letter characters

    tokens = [stemmer.stem(t) for t in tokens]  # Apply stemming
    
    return ' '.join(tokens)  # Reconstruct cleaned text
```

# Phase 3: Feature Vectorization

So far, we have cleaned and normalized the textual content of the news headlines. However, computers cannot directly understand textual information. Therefore, we need to transform the processed text into a numerical representation that machine learning algorithms can analyze.

In this phase, we perform **feature vectorization**, which converts textual data into numerical vectors.

For this implementation, we use the **TF-IDF (Term Frequency–Inverse Document Frequency)** technique, which was discussed in previous lessons.

TF-IDF assigns a numerical weight to each word based on:

- How frequently the word appears in a specific document.
    
- How rare or common the word is across all documents.
    

The intuition behind TF-IDF is that words appearing frequently in a specific document but rarely in the entire dataset are more informative.

---

## Understanding the `min_df` and `max_df` Parameters

When creating the `TfidfVectorizer`, two important parameters were defined:

- `min_df`
    
- `max_df`
    

These parameters control which words are included in the final vocabulary.

---

## `min_df` Parameter

The `min_df` parameter defines the minimum number of documents in which a word must appear to be included in the vocabulary.

Its purpose is to remove extremely rare words that provide little generalizable information.

For example:

```python
min_df = 2
```

means that a word must appear in at least **2 documents** to be considered.

A word that appears in only one document will be ignored.

The parameter can also be specified as a ratio:

```python
min_df = 0.01
```

This means that only words appearing in at least **1% of all documents** will be included.

Mathematically, if:

- $N$ represents the total number of documents.
    
- $df(t)$ represents the number of documents containing term (t).
    

Then a term is selected only if:

$$  
df(t) \geq min_df  
$$

---

## `max_df` Parameter

The `max_df` parameter works in the opposite direction.

It removes words that appear too frequently across documents because such words usually contain little discriminative information.

For example:

```python
max_df = 8
```

means that words appearing in more than 8 documents will be ignored.

Alternatively:

```python
max_df = 0.65
```

means that words appearing in more than 65% of documents will be removed.

Mathematically:

$$  
df(t) \leq max_df  
$$

This filtering process prevents very common words from dominating the feature space.

# Phase 4: Building the User Profile

In this phase, we use the user's interaction history to understand their preferences.

Assume we have a user who has previously interacted with several news articles. In this system, these interactions are stored as the user's history.

---

## What Is a User Profile?

In a **content-based recommender system**, the **user profile** is the core component responsible for representing user preferences.

A user profile is a numerical representation of a user's interests in the same feature space used for item representations.

Instead of looking at individual items separately, the user profile provides a summarized representation of the user's overall interests.

For example:

- Each news article is represented as a point in TF-IDF vector space.
    
- When a user reads several articles, those articles represent the user's areas of interest.
    
- Combining these vectors creates a single representation of the user's preferences.
    

This combined representation is called the **user profile vector**.

---

## Creating the User Profile

To construct the user profile, we calculate the average of the TF-IDF vectors of all items previously interacted with by the user.

The formula is:

 $$  
\text{User Profile} =

\frac{1}{|H|}  
\sum_{i \in H}  
\bar{v_i}  
$$

Where:

- $H$ represents the user's interaction history, which contains previously viewed or rated items.
    
- $\bar{v_i}$ represents the TF-IDF vector of item (i).
    
- $|H|$ represents the number of items in the user's history.
    

---

## Why Do We Use Averaging?

Averaging provides a simple but effective method for combining multiple user interests.

It helps by:

- Reducing the influence of individual items.
    
- Creating a more stable representation of preferences.
    
- Capturing the general direction of user interests.
    

For example, if a user has read 10 articles, averaging their vectors produces one vector that summarizes the common characteristics of those articles.

This vector represents the user's position in the TF-IDF feature space.

# Phase 4: Building the User Profile (Implementation)

## Why Is the User Profile Important?

The user profile allows the recommender system to compare the user's interests with all available items.

The process works as follows:

1. The user profile represents the user's preferences.
    
2. Each item has its own TF-IDF vector representation.
    
3. The similarity between the user profile and each item vector is calculated.
    
4. Items with the highest similarity scores are selected as recommendations.
    

This approach converts the recommendation problem into a **vector similarity problem**.

The system is no longer directly comparing text. Instead, it compares numerical representations in a shared feature space.

# Phase 5: Measuring Item Similarity

In this phase, we calculate how similar each item is to the user's profile.

Since both:

- The user profile vector
    
- The item TF-IDF vectors
    

exist in the same vector space, we can use **cosine similarity** as a suitable similarity measure.

Cosine similarity measures the angle between two vectors rather than their absolute distance.

The formula is:

 $$  
\text{Cosine Similarity}(A,B) =

\frac{A \cdot B}  
{|A||B|}  
$$

where:

- $A \cdot B$ is the dot product of the two vectors.
    
- $|A|$ and $|B|$ are the magnitudes (Euclidean norms) of the vectors.
    

The resulting value ranges between:

$$  
0 \leq \text{similarity} \leq 1  
$$

where:

- A value close to **1** indicates high similarity.
    
- A value close to **0** indicates little similarity.
    

---

## Calculating Similarity Scores

We calculate the similarity between the user profile and every item:

```python
sim_scores = cosine_similarity(
    user_profile,
    tfidf_matrix
).flatten()
```

The result is an array containing one similarity score for each item.

Since our dataset contains 20 items, the output array contains 20 values.

---

## Removing Previously Viewed Items

A recommender system should not recommend items that the user has already consumed.

Therefore, we remove the user's previous interactions from the candidate list:

```python
for idx in history_indices:
    sim_scores[idx] = -1
```

We assign a value of `-1` because cosine similarity values are normally between 0 and 1. This guarantees that these items will never appear among the highest-ranked recommendations.

# Phase 6: Recommending the K Nearest Items

After computing the similarity scores between the user's profile and every available item, the final step is to identify the most relevant recommendations.

Rather than recommending every candidate item, recommender systems typically return only the **Top-K** items with the highest similarity scores.

The value of **K** is application-dependent. For example:

- A news website may display the top 5 recommended articles.
    
- An e-commerce platform may recommend the top 10 products.
    
- A streaming service may present the top 20 movies or songs.
    

In this example, we choose:

$$  
K = 3  
$$

meaning that only the three most similar unseen items will be recommended.

---

## Selecting the Top-K Items

We first sort the similarity scores in descending order and then select the first **K** items.

```python
# Top-3 recommendations
top_k = sim_scores.argsort()[::-1][:3]

recommended_ids = df.loc[top_k, "item_id"].tolist()

print("Recommended:", recommended_ids)
```

Output:

```text
Recommended: [20, 2, 17]
```

---

## How Does `argsort()` Work?

The function

```python
sim_scores.argsort()
```

does **not** sort the similarity values themselves.

Instead, it returns the **indices** that would sort the array in ascending order.

Suppose the similarity scores are

```python
sim_scores = [0.20, 0.75, 0.10, 0.50]
```

Then

```python
sim_scores.argsort()
```

returns

```text
[2, 0, 3, 1]
```

because the similarities in ascending order are

$$  
0.10 < 0.20 < 0.50 < 0.75  
$$

Notice that the returned values are the **positions** of these elements, not the values themselves.

---

## Why Do We Use `[::-1]`?

The output of `argsort()` is sorted in **ascending** order.

However, recommendation systems require the **largest** similarity scores.

Therefore, we reverse the order using

```python
[::-1]
```

For example,

```text
[2, 0, 3, 1]
```

becomes

```text
[1, 3, 0, 2]
```

which corresponds to the similarity scores

$$  
0.75 > 0.50 > 0.20 > 0.10  
$$

---

## Selecting Only the First K Items

Finally,

```python
[:3]
```

selects only the first three indices.

Therefore,

```python
top_k = sim_scores.argsort()[::-1][:3]
```

can be interpreted as:

1. Sort all items according to their similarity scores.
    
2. Reverse the order so the most similar items appear first.
    
3. Keep only the first **K** items.
    

---

## Mapping Indices Back to Item IDs

The variable `top_k` contains **row indices** of the DataFrame rather than actual item identifiers.

To retrieve the original item IDs, we use

```python
recommended_ids = df.loc[top_k, "item_id"].tolist()
```

This returns

```text
[20, 2, 17]
```

These are the identifiers of the recommended news articles.

---

## Interpreting the Recommendation Results

The output

```text
Recommended: [20, 2, 17]
```

indicates that the recommender system predicts these three articles to be the most relevant to the user's interests.

These recommendations satisfy two important conditions:

- They have the highest cosine similarity with the user's profile.
    
- They are items that the user has **not** previously viewed.
    

Conceptually, the recommendation process can be summarized as

#$$  
\text{Recommendations} =

$$

# Phase 7: Evaluating the Recommender System

Building a recommender system is only part of the process. We also need to evaluate whether the generated recommendations are actually useful.

In content-based recommender systems, evaluation measures how well the recommended items match the user's true interests.

Several evaluation metrics have been proposed in the literature. Among the most widely used are:

- **Precision@K**
    
- **Recall@K**
    
- **Normalized Discounted Cumulative Gain (NDCG@K)**
    

These metrics assess different aspects of recommendation quality.

- **Precision@K** evaluates the accuracy of the recommendations.
    
- **Recall@K** measures how completely the system retrieves relevant items.
    
- **NDCG@K** evaluates both the relevance of recommendations and their ranking positions.
    

Together, these metrics provide a comprehensive assessment of recommender system performance.

---

## Preparing Test Data

To evaluate the recommender system, we first define a small test dataset.

For each user, we specify:

- the items previously viewed by the user (interaction history),
    
- and the items considered relevant during evaluation (ground-truth items).
    

```python
# Defining test data for users
user_test_data = [
    ([1, 5, 12], [2, 17, 20]),   # User 1
    ([3, 7, 15], [19, 11, 14]),  # User 2
    ([4, 8, 16], [9, 13, 18])    # User 3
]
```

Each tuple consists of:

- the user's interaction history, and
    
- the set of relevant items that should ideally be recommended.
    

The recommender system will generate recommendations based solely on the interaction history, while the relevant items will be used only during evaluation to measure the quality of those recommendations.

## Implementing the Recommendation Function

To evaluate the recommender system for multiple users, it is convenient to encapsulate the recommendation process into a reusable function.

The following function generates recommendations for a user based on their interaction history.

```python
def recommend_for_user(user_history_ids, k=5):
    history_indices = [
        df.index[df['item_id'] == uid][0]
        for uid in user_history_ids
    ]

    user_profile = (
        np.asarray(tfidf_matrix[history_indices].mean(axis=0))
        .ravel()
        .reshape(1, -1)
    )

    sim_scores = cosine_similarity(
        user_profile,
        tfidf_matrix
    ).flatten()

    # Remove previously viewed items
    for idx in history_indices:
        sim_scores[idx] = -1

    top_k = sim_scores.argsort()[::-1][:k]

    return df.loc[top_k, "item_id"].tolist()
```

This function performs the entire recommendation pipeline for a single user:

1. It retrieves the indices of the user's previously viewed items.
    
2. It constructs the user profile by averaging the corresponding TF-IDF vectors.
    
3. It computes the cosine similarity between the user profile and every item in the dataset.
    
4. It removes items already viewed by the user.
    
5. It returns the **Top-K** recommended item identifiers.
    

By encapsulating these operations into a function, we can easily generate recommendations for any user by supplying only their interaction history.

For example,

```python
recommend_for_user([1, 5, 12], k=5)
```

returns the five items that best match the preferences inferred from the user's viewing history.

---

# Computing the Evaluation Metrics

Now that we have a recommendation function, we can evaluate its performance using three commonly adopted metrics:

- **Precision@K**
    
- **Recall@K**
    
- **NDCG@K**
    

First, we import the required function from Scikit-learn:

```python
from sklearn.metrics import ndcg_score
```

Next, we initialize the evaluation parameters.

```python
K = 5

precisions = []
recalls = []
ndcgs = []
```

The lists above will store the evaluation results for each user.

---

## Evaluating Each User

We evaluate the recommender system separately for every user in the test dataset.

```python
for user_history, actual_items in user_test_data:

    recommended = recommend_for_user(user_history, k=K)

    recommended_set = set(recommended)
    actual_set = set(actual_items)

    # Calculate Precision and Recall
    true_positives = len(recommended_set & actual_set)

    precision = true_positives / K
    recall = true_positives / len(actual_set)

    # Calculate NDCG
    y_true = [
        1 if item in actual_set else 0
        for item in recommended
    ]

    y_score = [
        1 / (rank + 1)
        for rank in range(len(recommended))
    ]

    ndcg = ndcg_score([y_true], [y_score])

    precisions.append(precision)
    recalls.append(recall)
    ndcgs.append(ndcg)
```

The evaluation process is repeated for every user in the test dataset.

For each user, the algorithm performs the following steps:

1. Generate the Top-K recommendations.
    
2. Compare the recommended items with the ground-truth relevant items.
    
3. Compute Precision@K.
    
4. Compute Recall@K.
    
5. Compute NDCG@K.
    
6. Store the resulting values.
    

After all users have been evaluated, the overall performance is obtained by averaging the individual metric values.

---

## Displaying the Final Results

Finally, we compute and display the average value of each evaluation metric.

```python
print(f"Average Precision@{K}: {np.mean(precisions):.2f}")
print(f"Average Recall@{K}: {np.mean(recalls):.2f}")
print(f"Average NDCG@{K}: {np.mean(ndcgs):.2f}")
```

## NDCG@5

The average normalized discounted cumulative gain is

$$  
\mathrm{NDCG@5}=0.54  
$$

Unlike Precision and Recall, NDCG also considers the **ranking order** of recommendations.

Relevant items appearing near the beginning of the recommendation list contribute more to the score than relevant items appearing near the end.

Consequently, NDCG provides a better approximation of the actual user experience, since users are much more likely to examine the first few recommendations.

The value of NDCG ranges between

$$  
0 \leq \mathrm{NDCG} \leq 1  
$$

where:

- **1** represents the ideal ranking, in which all relevant items appear at the top of the recommendation list.
    
- **0** indicates extremely poor ranking quality.
    

An NDCG value of **0.54** suggests that the recommender places relevant items in reasonably good positions, although there is still room for improvement.

# Summary

In this tutorial, we implemented a complete **content-based recommender system** using textual features represented by TF-IDF vectors.

The implementation followed a standard recommendation pipeline:

1. Construct a dataset of news articles.
    
2. Preprocess the textual descriptions.
    
3. Convert the processed text into TF-IDF vectors.
    
4. Build a user profile by averaging the vectors of previously viewed items.
    
5. Measure similarity between the user profile and candidate items using cosine similarity.
    
6. Recommend the Top-K most similar unseen items.
    
7. Evaluate the recommendations using **Precision@K**, **Recall@K**, and **NDCG@K**.
    

Although the dataset used in this tutorial is intentionally small and synthetic, the overall workflow closely resembles that employed in practical content-based recommender systems. In real-world applications, the same methodology can be extended to substantially larger datasets, richer feature representations, and more sophisticated user modeling techniques to deliver more accurate and personalized recommendations.
