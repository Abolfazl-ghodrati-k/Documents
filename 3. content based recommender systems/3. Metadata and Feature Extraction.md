## Introduction

In the previous section, we explored preprocessing techniques for **textual data**. However, textual information is only one source of information available to content-based recommendation systems. Another equally important source is **metadata**, which serves as the focus of this section.

Metadata often provides highly structured and informative descriptions of items, enabling recommendation systems to model item characteristics more effectively and generate more accurate recommendations.

---

# What Is Metadata?

One of the first questions that naturally arises is:

**What exactly is metadata?**

Metadata can be broadly defined as **data that describes other data**.

In recommender systems, metadata consists of attributes that provide additional information about items rather than representing the items themselves.

Examples include:

- a movie's genre,
- a product category,
- the author of a book,
- publication date,
- language,
- manufacturer,
- brand,
- tags,
- keywords,
- and many other descriptive properties.

Instead of describing user interactions, metadata describes the intrinsic characteristics of items. These descriptive attributes allow recommendation algorithms to compare items based on their content and semantic properties.

---

# Categories of Metadata

Metadata can be classified into several categories according to its purpose.

The most common categories are described below.

---

## 1. Descriptive Metadata

**Descriptive metadata** characterizes the content of an item.

Typical examples include:

- title,
- author,
- publication date,
- keywords,
- abstract,
- genre,
- language,
- publisher,
- tags.

For instance, for a book these attributes may include:

- Title
- Author
- Publication year
- ISBN
- Subject
- Keywords

Descriptive metadata is particularly valuable for recommendation systems because it provides the features used to compare items and determine their similarity.

---

## 2. Structural Metadata

**Structural metadata** describes the relationships among different components of a collection or dataset.

Rather than describing the content itself, it explains how information is organized.

Examples include:

- hierarchical category structures,
- document organization,
- parent-child relationships,
- navigation paths,
- product taxonomies.

Consider an online marketplace where a user wants to purchase a gaming keyboard.

The hierarchical category structure might be:

```
Digital Products
    └── Computer Accessories
            └── Keyboards
                    └── Gaming Keyboards
```

This hierarchical organization enables recommendation systems to understand relationships between categories and recommend items that belong to nearby branches of the taxonomy.

Structural metadata therefore helps algorithms exploit semantic relationships beyond individual item attributes.

---

## 3. Administrative Metadata

**Administrative metadata** contains information required for managing and maintaining digital resources.

Examples include:

- creation date,
- last modification date,
- file format,
- file size,
- ownership,
- copyright,
- access permissions,
- licensing information.

For example, academic digital libraries often store metadata such as:

- PDF or HTML format,
- open-access versus subscription-based availability,
- publication timestamp,
- copyright status.

Although this information may not directly influence recommendation quality, it plays an important role in resource management and access control.

---

## 4. Interaction Metadata

**Interaction metadata** records how users interact with items.

Examples include:

- clicks,
- purchases,
- ratings,
- likes,
- shares,
- comments,
- bookmarks,
- watch history,
- browsing behavior.

These interactions constitute one of the richest sources of information for modeling user preferences.

Even in content-based recommendation systems, interaction metadata is used to determine which items should contribute to constructing the user's profile.

Unlike descriptive metadata, which characterizes items themselves, interaction metadata characterizes the relationship between users and items.

---

# Metadata Storage Formats

Metadata can also be categorized according to how it is stored.

The storage format significantly affects preprocessing strategies and the complexity of subsequent feature extraction.

---

## Structured Metadata

Before discussing structured metadata, it is useful to define **structured data**.

Structured data follows a predefined schema consisting of rows and columns, making it straightforward to store, query, and process.

Characteristics of structured data include:

- tabular organization,
- fixed schema,
- compatibility with relational databases,
- efficient querying using SQL,
- simple integration with analytical tools.

CSV files, spreadsheets, and relational database tables are common examples.

Consider the following metadata for a digital library.

|Book Title|Author|Publication Year|Genres|
|---|---|---|---|
|Animal Farm|George Orwell|1945|Novel, Social, Political|
|The Little Prince|Antoine de Saint-Exupéry|1943|Novel, Social, Fantasy, Children|

This is an example of structured metadata because every record follows the same schema.

---

## Semi-Structured Metadata

Semi-structured data does not follow the rigid row-column organization of relational databases, yet it still contains explicit organizational information through tags, keys, or attributes.

Common examples include:

- JSON
- XML
- YAML

For example, the previous table can be represented as JSON:

```
[
  {
    "Book Title": "Animal Farm",
    "Author": "George Orwell",
    "Publication Year": "1945",
    "Genres": ["Novel", "Social", "Political"]
  },
  {
    "Book Title": "The Little Prince",
    "Author": "Antoine de Saint-Exupéry",
    "Publication Year": "1943",
    "Genres": ["Novel", "Social", "Fantasy", "Children"]
  }
]
```

Although JSON is not tabular, each field is explicitly labeled, making it relatively easy to parse and transform into structured formats.

Semi-structured metadata is extremely common in modern web applications and APIs because it provides flexibility while preserving machine-readable organization.

## Unstructured Metadata

Unlike structured and semi-structured metadata, **unstructured metadata** does not follow a predefined schema and lacks explicit fields or attributes that can be directly analyzed.

Examples include:

- free-form customer reviews,
- product descriptions,
- news articles,
- social media posts,
- emails,
- images,
- audio,
- video.

Since these data sources contain little or no explicit structure, they require specialized processing techniques before they can be used by recommendation systems.

For textual data, this preprocessing typically involves **Natural Language Processing (NLP)** techniques such as those introduced in the previous section:

- tokenization,
- normalization,
- stop-word removal,
- stemming,
- lemmatization,
- vectorization.

Other types of unstructured data, such as images or audio, require computer vision or signal processing techniques to extract meaningful features.

---

# Metadata Processing

Having developed an understanding of the different types of metadata, we can now examine how metadata is processed before it is used by a recommendation system.

Although implementations vary across applications, the overall metadata processing pipeline generally consists of the following stages.

---

# 1. Metadata Collection

The first step is to gather metadata from all available sources.

For example, in a movie recommendation system, metadata may include:

- genres,
- directors,
- actors,
- production companies,
- keywords,
- plot summaries,
- release years.

These data may originate from multiple databases, APIs, or files and are usually consolidated into a common representation using data-processing libraries such as **pandas**.

The objective of this stage is to create a unified dataset containing all available descriptive information about each item.

---

# 2. Metadata Preprocessing

The preprocessing strategy depends largely on the structure of the available metadata.

Different preprocessing techniques are appropriate for:

- structured data,
- semi-structured data,
- unstructured data.

In this section, we assume that the metadata is **semi-structured**, such as JSON documents retrieved from an API.

The preprocessing pipeline consists of several stages.

---

## 2.1 Converting Metadata into Structured Data

The first task is to transform semi-structured metadata into a structured, tabular representation.

Consider the following JSON document:

```
[
  {
    "Book Title": "Animal Farm",
    "Author": "George Orwell",
    "Publication Year": "1945",
    "Genres": ["Novel", "Social", "Political"]
  },
  {
    "Book Title": "The Little Prince",
    "Author": "Antoine de Saint-Exupéry",
    "Publication Year": "1943",
    "Genres": ["Novel", "Social", "Fantasy", "Children"]
  }
]
```

After transformation, the data becomes a structured table.

|Book Title|Author|Publication Year|Genres|
|---|---|---|---|
|Animal Farm|George Orwell|1945|Novel, Social, Political|
|The Little Prince|Antoine de Saint-Exupéry|1943|Novel, Social, Fantasy, Children|

Representing metadata in tabular form simplifies subsequent preprocessing and feature engineering.

---

## 2.2 Handling Missing Values

Real-world datasets are rarely complete.

Some records may contain missing values for one or more attributes.

Examples include:

- missing publication dates,
- unknown authors,
- incomplete product categories,
- absent keywords.

Several strategies can be used to address missing values, depending on the application:

- removing incomplete records,
- replacing missing values with the mean,
- replacing them with the median,
- replacing them with the mode,
- assigning a default placeholder value such as **Unknown**,
- removing entire attributes if they contain excessive missing data.

Selecting an appropriate strategy requires understanding both the dataset and the downstream recommendation algorithm.

---

## 2.3 Cleaning and Normalizing Textual Metadata

Many metadata fields contain textual information that must be preprocessed before feature extraction.

Typical operations include:

- removing unnecessary punctuation,
- converting all text to lowercase,
- removing stop words,
- stemming,
- lemmatization,
- standardizing formatting.

These preprocessing steps are identical to those introduced in the previous chapter on textual data preprocessing.

Applying consistent normalization across all textual metadata ensures that semantically identical information is represented uniformly throughout the dataset.

---

## 2.4 Combining Features into a Unified Item Representation

Once every attribute has been cleaned and standardized, the various metadata fields are combined to create a single representation for each item.

For example, suppose a book has the following metadata:

- Title: _Animal Farm_
- Author: _George Orwell_
- Genres: _Novel, Political, Social_

These attributes can be concatenated into a single textual representation:

```
Animal Farm George Orwell Novel Political Social
```

This unified representation summarizes the most important characteristics of the item.

Later, this combined text can be passed to vectorization algorithms such as:

- Bag-of-Words,
- TF-IDF,
- Word2Vec,
- Sentence Transformers,

to generate numerical feature vectors suitable for recommendation.

At this point, the preprocessing stage is complete, and the data is ready for feature vector generation.

```
[

    "publication_year": "1945",

    "publication_year": "1943",
    "genres": ["Novel", "Social", "Fantasy", "Children"]
  },
  {
    "book_name": "1984",
    "author": "George Orwell",
    "publication_year": "1949",
    "genres": ["Novel", "Dystopian", "Political"]
  },
  {
    "book_name": "Pride and Prejudice",
    "author": "Jane Austen",
    "publication_year": "1813",
    "genres": ["Novel", "Romance", "Social"]
  }

```

The following implementation demonstrates the complete preprocessing pipeline described above.

## Complete Metadata Preprocessing Example

The following Python program demonstrates a complete metadata preprocessing pipeline. It illustrates how to:

1. Load metadata from a JSON file.
2. Convert the data into a tabular structure.
3. Clean and normalize textual attributes.
4. Combine multiple metadata fields into a unified item representation suitable for feature extraction.

```
import json
import pandas as pd
import re

# 1. Load data from a JSON file
with open('books.json', 'r', encoding='utf-8') as f:
    books = json.load(f)

# 2. Assign a unique ID to each book
for idx, book in enumerate(books, start=1):
    book['id'] = idx

# 3. Create a DataFrame
df = pd.DataFrame(books)

# 4. Define stop words and preprocessing functions
stopwords = {'and', 'or', 'the', 'a', 'an', 'in', 'on', 'of', 'for', 'to', 'with'}

def clean_text(text: str) -> str:
    text = text.lower()
    text = re.sub(r'[^a-z0-9\s]', '', text)   # Remove punctuation
    return text

def remove_stopwords(text: str) -> str:
    tokens = text.split()
    return ' '.join([t for t in tokens if t not in stopwords])

def preprocess(text: str) -> str:
    text = clean_text(text)
    text = remove_stopwords(text)
    return text

# 5. Preprocess textual columns
df['clean_book_name'] = df['book_name'].apply(preprocess)
df['clean_author'] = df['author'].apply(preprocess)

# Convert the genre list into a single string before preprocessing
df['clean_genres'] = df['genres'].apply(
    lambda genres: preprocess(' '.join(genres))
)

# 6. Combine all features into a single representation
df['combined_features'] = (
      df['clean_book_name']
    + ' '
    + df['clean_author']
    + ' '
    + df['clean_genres']
)

# 7. Display the final result
print(
    df[
        [
            'id',
            'book_name',
            'author',
            'publication_year',
            'genres',
            'combined_features'
        ]
    ]
)
```

---

## Understanding the Implementation

Although the implementation is relatively short, each step performs an important task in preparing metadata for a recommendation system.

### Step 1 — Loading the Metadata

The metadata is read from a JSON file and stored as a list of Python dictionaries.

At this stage, the data still follows the original semi-structured JSON format.

---

### Step 2 — Assigning Unique Identifiers

Each book is assigned a unique identifier.

```
book['id'] = idx
```

Unique identifiers simplify later operations such as:

- indexing,
- joining datasets,
- retrieving recommendations,
- mapping vectors back to original items.

In production systems, these IDs usually already exist within the database.

---

### Step 3 — Creating a DataFrame

The JSON data is converted into a **Pandas DataFrame**.

This transformation converts semi-structured metadata into a structured tabular format that is much easier to manipulate.

The resulting table contains columns such as:

- `book_name`
- `author`
- `publication_year`
- `genres`

From this point onward, preprocessing operations can be applied independently to each column.

---

### Step 4 — Defining Preprocessing Functions

Three preprocessing functions are defined.

#### `clean_text()`

This function performs basic normalization by:

- converting text to lowercase,
- removing punctuation,
- removing special characters.

#### `remove_stopwords()`

This function removes frequently occurring words that contribute little semantic information.

For example:

```
The Lord of the Rings
```

becomes

```
lord rings
```

after stop-word removal.

#### `preprocess()`

This function combines the previous preprocessing steps into a single reusable pipeline.

Instead of repeatedly calling multiple functions, preprocessing can now be performed simply by calling:

```
preprocess(text)
```

This modular design improves readability and makes the code easier to maintain.

---

### Step 5 — Cleaning Individual Metadata Fields

Each textual attribute is cleaned separately.

```
df['clean_book_name']
```

contains normalized book titles.

```
df['clean_author']
```

contains normalized author names.

The list of genres is first converted into a single string before preprocessing.

For example,

```
["Novel", "Political", "Social"]
```

becomes

```
Novel Political Social
```

and is then normalized using the same preprocessing pipeline.

Applying identical preprocessing across all textual fields ensures consistency in the resulting feature representation.

---

### Step 6 — Building a Unified Item Representation

This is one of the most important stages in metadata preprocessing.

Rather than processing each metadata field independently during recommendation, all informative attributes are merged into a single textual representation.

For example,

```
Animal Farm
George Orwell
Novel Political Social
```

becomes

```
animal farm george orwell novel political social
```

This combined representation now contains the essential descriptive information about the book.

The recommendation system can subsequently convert this unified text into a numerical feature vector using a vectorization algorithm.

Combining multiple metadata attributes in this way often improves recommendation quality because it enables the model to learn from all available descriptive information simultaneously rather than treating each attribute in isolation.

---

## Summary

Metadata provides valuable descriptive information about items and plays a central role in content-based recommendation systems.

Unlike free-form textual content, metadata is often already organized into meaningful attributes, making it easier to preprocess and transform into machine-readable representations.

A typical metadata preprocessing pipeline consists of:

1. collecting metadata from available sources,
2. converting semi-structured data into structured formats,
3. handling missing values,
4. cleaning and normalizing textual attributes,
5. combining multiple metadata fields into a unified item representation.

The resulting representation serves as the input to **feature vectorization**, where textual metadata is transformed into numerical vectors that recommendation algorithms can compare using similarity measures.
